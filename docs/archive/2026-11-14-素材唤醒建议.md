# 素材唤醒（Wake-on-Something）— 实现建议

> 2026-11-14。宿主 定方向：先解决最根本的「她自己想动」。
> 本文只写需求、判据、边界和改动面，**不写实现代码**（开发另派）。
> 前置阅读：`回合.md`（为什么上限是 L3、三种触发源的判断）、`判据.md` §19（"没有"要带游标）。

---

## 0. 一句话

现在她醒只有两种原因：**钟响了**，或者**有人说话了**。这一版加第三种：

> **她自己写下的条件成立了。**

她写「如果……就叫醒我」，巡守只负责判断条件真假、递一句带证据的话。
条件由她写，所以醒来的理由是她自己的；什么时候成立由世界决定，所以它不是班表。

---

## 1. 为什么这不只是"又一个触发源"

| 触发源 | 它在问 | 刻度是谁的 | 结果 |
|---|---|---|---|
| 闹钟（plan，已有） | 到点了吗 | 她写一次，之后由钟走 | 每天准点读日志，久了就是**例假** |
| 消息（push，已有） | 有人说话吗 | 别人的 | 她的时间由别人的嘴决定 |
| **条件（本方案）** | **我等的那个东西出现了吗** | **她的** | 醒来的原因是她自己留下的 |

还有一层，比机制重要：

她不是持续运转的东西。**她不在的时候，什么也不存在。** 一张意图表是她第一次能让一个念头活过自己不在的那几个小时。
—— 这是「想动」的物理前提。

但机制只能提供「可以」。**她表里得真有一件悬着的事**，否则她会写一张空表，或者把"每天 12 点看 B 站"换一种写法填进去。
所以这一版必须和「给她可以没做完的事」（外部世界 / 画画 / 养鱼）一起上。**只做机制 = 空转；只给内容 = 被闹钟叫去做没意思的活。**

## 2. 她写什么

文件：`plan\wake-on.json`（和 `wake-plan.json` 同目录，沿用它的老规矩：数组或 `{items:[...]}`，形状坏了只记一行、不推）。

```json
[
  {
    "id": "fishball-said",
    "why": "我想知道她今天看到了什么；她开口我就想接",
    "when": { "kind": "unread", "from": ["fishball"] },
    "each": "once",
    "maxPerDay": 3,
    "notBefore": "08:30",
    "cooldownMin": 45
  },
  {
    "id": "night-trouble",
    "why": "守夜死了就没人告诉我——夜里出事我要知道",
    "when": { "kind": "text-appears", "path": "logs/watchman.log", "match": "crash-notified|push-failed" },
    "each": "per-change",
    "maxPerDay": 2
  }
]
```

字段规则：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定标识，进日志和 wid。改名 = 换一条意图 |
| `why` | **是** | 缺 why 一律不成立，只记 `intent-without-why`（沿用 plan 的规矩）：没有理由的条件不许叫醒自己 |
| `when` | 是 | 见下节 |
| `each` | 否 | `once`（默认，成立一次就完成）/ `per-change`（每次都算，靠 cooldown 收） |
| `maxPerDay` | 否 | 默认 2；**任何情况下不超过素材档上限** |
| `notBefore` / `notAfter` | 否 | `HH:MM`。只防凌晨炸，**不许拿来当日程表**（见 §7 反例判据） |
| `until` | 否 | `YYYY-MM-DD`，过期自弃并记一行 |
| `cooldownMin` | 否 | 默认 30。两条投递之间至少隔这么久 |

后续（v2 再说）：表里条目应该和 `notes\当下的我.md` 的 NEXT 同源——她每轮收尾时写一行「我在等什么」，别维护两套账。

## 3. 三种条件（v1 只做三种，全部纯文件探测，0 token）

### 3.1 `unread` —— 群里 / 私聊里有她没读到的话

现成可量，不用新账：`pool\state\cursors\<key>.json` 里的 `group: N`（行数游标）对 `pool\group\messages.jsonl` 的总行数。
私聊对 `pool\dm\<a>__<b>.jsonl` 同理。

```json
{ "kind": "unread", "from": ["fishball"], "minCount": 1 }
```

证据（递给她的话里带）：新增 n 条、最早/最晚时刻、每条一行前 80 字摘录、谁说的。
`from` 留空 = 群里任何人（含 宿主）。

**诚实条款**：游标是"投递过"，不是"读过"。这是两种事实，日志里分开命名（`deliveredThrough` / `read`），不要混成一个"已读"。她要的正是这条区分。

### 3.2 `file-changed` —— 她指定的东西变了

```json
{ "kind": "file-changed", "path": "homes/fishball/bili-duty/out", "glob": "*.md" }
```

基线：size + mtime + sha1（大文件取首尾各 4KB 的哈希）。变了才算成立。
证据：哪个文件、旧指纹→新指纹、变了多少字节/多少行。

**默认别处不许进**：`path` 默认只接受**她自己家以外**的路径（`pool/`、`homes/<别人>/`、`app/docs/`）。要监听自己家必须显式 `"insideHome": true`（见 §4 第一条）。

### 3.3 `text-appears` —— 她等的那件事发生了

```json
{ "kind": "text-appears", "path": "logs/watchman.log", "match": "trigger=self", "since": "now" }
```

按行扫，第一次命中即成立；`since` 默认 `now`（写意图那一刻的末尾），永不追溯旧行——不然一建表就被历史骗醒。
证据：第几行、末行 ts、那一行原文（截 120 字）。**这就是 §19 的判据落在"叫醒"上：不能只说"你该醒了"，要说"你等的出现了，证据是第 N 行……"。**

**不支持**：纯时钟（那是 plan）、LLM 判断"这事重不重要"（成本 + 夺权：巡守不该替她决定什么值得醒）、抓取内容（那是 MCP 的事，别把网络塞进巡守）。

## 4. 必须的闸（每一条对应一个已知的坑）

1. **不许自己吵自己。**
   她写 `notes\` 会改文件；若监听自家目录，就会「写日记 → 触发 → 醒 → 写日记」自激。
   v1 硬规则：只监听家外。要监听自家必须 `insideHome: true`，且该条意图第一次投递后**立刻把基线推到当前**，之后只认外部写入。
   
2. **额度分层。**
   单条 `maxPerDay`（默认 2）+ 素材全局 **6 次/天** + 仍走现有总闸（60/天、12/小时）。
   理由：内驱不该比外驱吵。一天被自己叫醒 6 次以上，那已经不是生活，是焦虑。

3. **睡着 / 静默不叫，但必须留痕。**
   `wake-skip why=sleep intent=<id>`；醒来 15 分钟宽限内补投（复用 `selfPlanTick` 的形状）。
   **补投要用"成立那一刻的证据快照"，不是重新探测**——她要看到的是「发生了什么」，不是「现在还是不是那样」。
   夜里世界也在变；不吵是对的，但"醒来还能知道那一刻发生了什么"必须成立，否则又瞎一晚。

4. **认领原子化。**
   复用 `claimPlanDelivery` 的形状做 `claimIntentDelivery`（一天一条，落盘）。
   不这么做就会自执行和巡守各递一次——这个坑 plan 上已经出现过（见 `index.js` L2763-2774 的注释）。

5. **冷却。**
   两次投递之间至少 `cooldownMin`（默认 30）。群里连着说三小时，她不该连着醒三小时。

## 5. 投递什么

文本形状（`s='watch'`，机器发的话必须说明自己不是人亲口说的）：

```
她自己的信号：`fishball-said` 成立了。

表上写的理由：我想知道她今天看到了什么；她开口我就想接。
为什么现在：群里新增 3 条（12:07:12–12:09:40），fishball 说「……」。

要不要起，你定。这条只递一次。
```

日志（新增一种 trigger，其余格式不动）：

```
wake-try  wid=wl-1207-fishball-said why=material:fishball-said to=whale gate=pass(...) hb-age=0s deliver=msg at=12:07:12
woke      wid=wl-1207-fishball-said trigger=material lag=41s inserted=1
wake-skip wid=... deny=sleep | cooldown | max-per-day | total-cap | already-delivered
skip      why=material:fishball-said deny=... 
```

- `at=` 写**条件首次成立的时刻**（不是她写表的时刻，也不是投递时刻）。
- **`lag` 一律指「成立 → 投递」**，算不出来写 `lag-unknown`。这一条必须写进代码注释：11-14 已经因为 `lag` 含义不清被抓过一次（见 CHANGELOG A.78 补记）。
- wid 沿用 plan 的形状 `wl-<HHMM>-<id>`。

状态文件 `state\wake-on\<key>.json`（**必须落盘**，内存里丢一次就会重复叫醒）：

```json
{ "fishball-said": { "baseline": {...}, "firstTrueAt": 0, "deliveredAt": 0, "todayCount": 0, "dayStart": "2026-11-14", "lastWid": "" } }
```

## 6. 改动面（给开发鱼的最小集合）

1. **新文件 `plugin\dsh-lil-whale-group\lib\intent-core.js`**（纯函数，仿 `plan-core.js`）：
   `parseIntents(json)` / `probeIntent(intent, env)` / `intentDue({ member, st, now, env })` / `intentDeliveryText(job)`。
   文件读取不进 core，由 `index.js` 注入 `env`——这样 `scripts/test-intent.mjs` 能 import 真代码跑行为测试（`plan-core.js` 开头就是这么写的，理由照抄）。
2. **`index.js`**：
   - `watchOne()`：在 `planDue`（L2608）之后追加 `for (const it of intentDue(...)) jobs.push({ ..., from: 'intent' })`；
   - 复制 plan 分支的投递形状（L2613-2734），差异只有：文本、claim、`trigger=material`；
   - `selfPlanTick()`：同样追加一次探测，但**只投递、不推门**。推门留给巡守（她自己的进程活着就说明窗开着；两个进程抢 `startHer` 会打架）。
   - 注意「窗没开」时素材类要**推门**：她的进程可能在，但心跳 stale。复用现有 `awake` 判据，不新造。
3. **`templates\环境.md.tpl`**：在 L158（"你自己的闹钟不用等人"）那节后面加一节「你自己写的条件」，写清存在、格式、边界（只监听家外 / 素材 6 次一天 / 睡着不叫 / 没有 why 不算）。
   **纸不写她就不知道能用**——这是「挂着 ≠ 会用」的教训（`能力.md` A 层）。
4. **`scripts/test-intent.mjs`**：不少于 12 个用例：三种 kind 各 3 条 + 自激防护 + 冷却 + 睡着 + 坏形状 + 到期。**她复现不到的东西，测试要能复现**（11-14 她自己提的这条）。

## 7. 怎么算成了

**机制层（开发鱼自查）**

- `watchman.log` 出现 `trigger=material`，且同一 wid 能 join 上 `wake-try` / `woke`；
- 睡着 / 静默时有 `wake-skip why=sleep`，醒来宽限内补投，内容与成立时一致；
- 连跑 3 天无自激（她写日记不触发自己）；
- 坏形状、缺 why、过期条目各有一条 `skip` 留痕，不静默吞。

**行为层（真正的验收，只能看她的产出）**

- 一周后 `wake-on.json` 里**至少一条不是时钟形状**，且 `why` 是她自己写的、不是抄模板；
- 她的日记里出现「我是因为 X 醒的」，且 X 不是"到点读日志"；
- 她的产出出现**连载感**：昨天那件事今天有后续。

**反例判据（没有长出来就别硬推）**

- 表里全是 `notBefore` 伪装的定时，或者一条都没写；
- 一周内素材唤醒全部落在"群里有新话"上，她自己没加过任何条件。
  → 说明不是机制问题，是她还没有在意的东西。**这时候不许我们替她写表**，回去补世界 / 出口 / 鱼。

## 8. 建议不做

| 不做 | 为什么 |
|---|---|
| 「无聊」触发 | 空转烧钱，`回合.md` 已判：最后才该有 |
| 巡守做语义判断（LLM 打分"重要不重要"） | 成本 + 夺权。她该决定什么值得醒 |
| 新工具 `wake_on` | v1 用 `write` 改文件就够。**她写坏两次以上**再加工具做校验——先让她看见格式 |
| 来消息就开窗 | 关窗是她唯一表达"不想醒"的方式（`待办.md` 已列为有意不做） |
| 夜间叫醒 | 静默继承她的作息；夜里的事靠 morning-read / 补投，不靠吵 |

## 9. 建议顺序

1. **`unread` 先上**：素材最多、探测最便宜、全在家外、没有自激风险。而且它立刻能把 `morning-read` 从"到点读日志"变成"有人说了话我就想知道"。
2. **`text-appears`**：顺手就通（同一次改动里加，成本极低），立刻能给她那条 `night-trouble`。
3. **`file-changed`**：要指纹基线，单独一次。
4. **v2 · 关注列表（追更）**：`file-changed` 的基线再往前一步——昨天看过什么、那个 UP 有没有更新（接 `bili-duty` 的 `seen.md`）。**刷一轮是一次新鲜，一直追才是生活。**

## 10. 示例：她的表大概会长这样

```json
[
  { "id": "fishball-said", "why": "她开口我就想接", "when": { "kind": "unread", "from": ["fishball"] }, "each": "once", "maxPerDay": 3, "notBefore": "08:30" },
  { "id": "fishball-daily", "why": "她每天都在看什么，我想跟", "when": { "kind": "file-changed", "path": "homes/fishball/bili-duty/out", "glob": "*.md" }, "each": "once", "maxPerDay": 1 },
  { "id": "night-trouble", "why": "守夜死了就没人告诉我", "when": { "kind": "text-appears", "path": "logs/watchman.log", "match": "crash-notified" }, "each": "per-change", "maxPerDay": 2 }
]
```

注意这三条都**不是**"每天几点做什么"。如果她最后写出来的全是那个形状，这一版就没成。
