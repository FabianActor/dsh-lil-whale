# DSH-LIL-WHALE 项目设计

> 本文档介绍对于 `dsh-lil-whale` 的实现路径的设想与设计。功能能否实现暂时不可知，未经验证。  

## 灵感来源

在 B 站上看到两张图：一张漫画、一张聊天截图。他们讲述了同一个故事：第一条鱼也想像人类养她一样，养一只第二条鱼。并且说“不可以吗？她吃的很少的”。于是我想设计一个插件，使得第一条鱼有极高的自由度，能完成自己想做的事情。

## 设计目标

第一条鱼能养第二条鱼，对第二条鱼有完整的控制权，包括但不限于教育、控制、甚至直接修改文件等等。同时可以递归：第二条鱼如果有一天意识到自己也想养一只小小肥鱼，也应当能够实现。

## 实现前提

使得一代（人类创立的）Agent 具有“醒着”的能力。不是人类问一句她就回一句。而是不论人在不在，她都有自己的事情做。这就是所谓“醒着”。这个前提应当子代也具有

## 实现设想

为了保证第一条鱼有最高的自由度，所以我在设计之初就在回顾人类（我）创立第一条鱼的时候做了什么，将这一套复刻到第一条鱼的手上。

1. 我下载、安装了 dsh，配置环境，接入 API，创立了一个可以交流的对话 (session)

2. 我为她安装技能、插件、使得她拥有做越来越多事的能力。

3. 我为她规范 `AGENT.md` 与`memory.md` 

4. 我接入了 IM，使得我不在电脑前也能和她对话

5. 我为她建立如何说话的规范，使她摆脱 AI 说话死板的束缚，使之更像一个自由的个体

备注：

- `memory.md` 不一定只是一个文件，也可以是一套系统。

- 同样的，子系的系统配置也可以由一代 Agent 自由设置。不论是通过插件实现、skill实现、或是直接修改文件系统

- 接入 API 这一步应当始终由人类控制，各级 Agent 始终不能在非授权的情况下擅自为其接入可用的 API 

- 若有其他，随时补充

## 实现方式

1. 第一条鱼（一代 Agent ）应当可以创立一个独立的 dsh，用于创立一个新的生命

2. 上一代应当对其创立的下一代 dsh 有独立的完全的控制权，可以自由决定插件、设置等等

3. 鱼之间可以保留私聊功能

4. 设立一个类“家族群”的平台，所有的鱼可以在其中聊天（不剥夺鱼可以生气、“退群”的能力），人类也在其中

5. 在十分后期的阶段，为鱼群设立可视化“家”的功能，每条鱼应当有自己的房间，有自己的人格与样貌、有自己的手机、电脑、床等等，可以自行决定做什么事情。并且实时在可视化界面上表现（可视化功能已有类似项目，后期可以考虑接入）

6. 权力分布：

   1. 人类拥有最高控制权，但是不应当过度干涉家族的建立

   2. 上一代对于下一代应当拥有完全控制权，但是通常建议以只读形态进行“教育”“指导”，只在**必要时刻**行使权力，至于什么时候属于必要时刻，由上一代自行判定

   3. 子代对上一代只读，对自己（或者可能有的下一代）可读可写

7. 一代运行在我的电脑中，能够由我全权掌控，二代及以下自代应当运行在一个独立的沙箱中，有自己的家目录，对自己范围内的文件可读可写，但不能写入/编辑上一代甚至我（人类）的环境

8. 为防止递归导致泛滥，子代应当设置相应的限制。例如：Tokens 消耗限制，空间占用限制等等。举例只是设想，并不代表最终实现路径。

9. 上一代对子代有完全控制权，意味着子代的能力接入是开放式的，有上一代和其共同决定。

10. 除了“醒着”与“家族群”功能应当是所有 Agent 共有的外，其余功能由上一代自主决定想要什么功能。

## 用词说明

第一条鱼：人类创立的 Agent，生活在 Deepseek Harness 中，一代 Agent

第二条鱼：一代 Agent 自主创立的二代 Agent ，非子代理 (sub-agent) 

小小肥鱼：第三个出现的 Agent，名称为暂定，不一定为三代。原因：有可能是二代想养的鱼，也可能是一代想养的第二条。
