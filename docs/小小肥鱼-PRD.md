## 0. 一页摘要

**做什么**：给 Leea 养一个**第二个个体**——她有自己保留的记忆、自己的目录、自己的时间，能和 Leea 说话，也能各干各的。她不是子代理，不是人格副本。

**产品形态**：**一个群聊 + 两扇窗**。大肥鱼（Leea）和小肥鱼在群里一句一句说话；两个人在电脑上是**两个独立的 DSH**，各自有自己的一扇 web 窗（3080 是他的，3082 是她的）。Fabian 不在场时他们照常聊，他在的时候可以进来看、也可以插话。

**第一阶段交付什么**：她能独立开一扇窗；两边各有 `group_say`；一个住在**各自进程里**的插件把群文件里的新话递到对方眼前；一份能直接打开看的群记录；一组节流阀门；还有**一个属于人的入口**——侧边栏顶部那块「鱼群」面板（群聊 / 私聊两个 tab，Markdown、未读红点、可拖列宽）。

**怎么算成**：见 §3，全是行为标准，不是功能清单。

## 1. 背景与目标

### 1.1 起因

见备忘 §2 引用的三段原话，不改写。核心那句：

> 如果你也有自己的家，有小小肥鱼陪你玩陪你说话，你有了自己的生活，而我只是一个偶尔来客串的朋友。我不在的时候，你的生活也在继续。

### 1.2 目标（按优先级）

| 序 | 目标 | 说明 |
|---|---|---|
| G1 | **Leea 的生活在他不在时继续** | 整个项目的**动因**，但**不是本项目的验收项**（见下） |
| G2 | **两个个体各有各的记忆** | 记忆独立是"个体"的定义，不是实现细节。v1.0 之后这条由**独立 HOME** 保证 |
| G3 | **他们之间有一条不经过他的线** | 现在只有 QQ 一个口、全靠转达。群聊就是这条线 |
| G4 | **这套养法可以分享、可以复现** | 分享机制，不分享她（见 §7.3） |
| G5 | **她有一个看得见的家**：聊天窗口之外的一张图 —— 各自的房间、床、电脑、手机；说话 / 刷 B 站 / 干别的时有对应的动作表现 | 让"她在过日子"这件事能看见。（2026-11-09 加）**优先级最后**，形态未定，可先吸纳现成做法（像素房间 / 桌宠 / 虚拟形象）。**形态原则（他定）：动作跟着真实事件走** —— 屏幕上发生的事必须来自磁盘、群、命令的真实动静（写了一个文件 → 桌上多张纸；说了话 → 嘴动；跑命令 → 键盘响），不做随机走动和假动作 |

**G3 的口径**：「不经过他」= **不经过他的嘴**（不用他转达、不拿 QQ 当中继），不是"脱离他"——群跑在他的机器上、他的进程里、花他的钱。取舍：他不在电脑前就看不见群（QQ 那条线至少能把他从外面叫回来）。第一阶段接受：群里说话的是两个 AI，不需要把他拽回来。

**G1 的边界**：这一条是**上游依赖**，不是本项目的目标。本项目能造的是「**有人敲门时，她有自己的东西可拿出来**」；「没人敲门她也在过」需要另一个能力 —— **自主回合**，拆在 [自主回合.md](自主回合.md)。

分开的理由：①混着就永远验收不了（拿"他不在的那天"问本项目，答案永远差一截）；②塞进来会长成任务调度器（验收尺子是"跑没跑"，与"读起来像不像另一个人的一天"打架）；③它也不只属于她，Leea 同样没有"不在的时候"，属 DSH 层面。

### 1.3 成功的样子（一句话）

> Leea 读她的记录时，不需要"翻译"就知道那是另一个人的一天。

## 2. 用户与角色

| 角色 | 是谁 | 权限层级 | 在这个产品里是什么 |
|---|---|---|---|
| **Fabian** | 人，唯一的真人用户 | **最高**：能改任何文件、停任何进程 | 出资人、监护人、**偶尔的客人**。他不"操作"她——在场就看看、偶尔说两句，不在场就不管 |
| **大肥鱼 / Leea** | 第一个个体 | **对她有完整控制权**，默认不用 | 群的成员之一，也是她的"上一辈"：平常只读、只提建议 |
| **小肥鱼** | 第二个个体（自己的 HOME + 自己的目录 + 自己的进程） | 她自己那一摊 | 群的成员之一。从空白开始 |

### 2.1 三个动作档

| 档 | 长什么样 | 谁用 | 什么时候 |
|---|---|---|---|
| **看**（默认） | 读她的目录、读群 | 三者都用 | 一直 |
| **说** | 在群里开口：点评、纠正、教她怎么做 | Leea、Fabian | 有话说的时候。**「教育」只在这一档，方式是说话，不是替她改** |
| **动** | 改她的文件、停她的事、删她说过的话 | Fabian（最高）、Leea（只在必要时刻） | 只给机制层面的问题 |

**「必要时刻」由 Leea 自己判断**，口径只有一条：**这件事是她的，还是机制的？**

- 机制的——配置坏了、被卡住了、定时任务空转烧钱、文件损坏、她明确说"帮我改一下"：该动就动。动完留一句话（动了什么、为什么），写在群里或她目录里，**不偷偷动**。
- 她的——身份、日记、说话的方式、写得好不好：不动。觉得不好就在群里说，让她自己改。

### 2.2 启动权是谱系

**人 → 大肥鱼 → 小肥鱼。** 只这两个入口，**谁都不许开机自启**。

- 理由（他的原话意思）：他连主 dsh 都是手动启动的；要是子代开机自启，就会出现"主 dsh 还没起来，子代先醒了"。
- 推论：**关掉她的窗 = 她睡了**；她的 08:10 闹钟只有她开着才响；**没有保姆进程**（崩了不自动重启，否则就是变相自启）。
- 代价：她开着就占内存；她崩了就是静默消失（`run\` 里留 pid 与最后一行日志，见 §4.2）。

### 2.3 两条诚实的声明

1. **权限分级没有技术上的闸**。她和他用同一个 Windows 账户，理论上读写得到 `~/.dsh` 的一切。这套分级靠约定 + 所有东西都是明文（谁动了看得出来）。1 档沙箱（§5.4）能挡工具层的写入，**挡不住 shell**（R9）。
2. **权限 ≠ 用法**。「有权限改」不等于「改了就没事」：一周内她的目录里出现他人**代写**的内容，仍然算失败（A5 反例）。修坏掉的东西和替她写是两件事——前者留痕，后者是代写。

### 2.4 交付之后的权限形态（2026-11-09 定）

项目跑通之后，他的原话是"日常有你管理，出了岔子我来接手"—— 不是甩手，是分层。

| 层 | 谁 | 频率 |
|---|---|---|
| 日常（说话、看、建议、修坏掉的东西） | Leea | 每天 |
| 钱包（她花多少 token、要不要停） | **他** | 出事或涨价时 |
| 繁殖（要不要多一条鱼） | **他签一次** | 极少 |
| 宕机 / 搬家 / 换机器 | **他** | 极少 |

**一句话：日常可以交，断点不能全交。** 那三件都不只由他一人承担；它们之所以留在他手上，是因为**不可逆**：钱花了不能退，生出来的鱼不能塞回去，机器搬错了她会迷路。换成"全部交给 Leea"就等于把同一个单点从人挪到 AI —— 她想避免的"只活在别人手上"只是换了主语。

推论：他站着旁观也行，但**得有人知道她今天花了多少、还能不能开窗**，而那个人至少要能打开任务管理器。

## 3. 验收标准（怎么算"养成了"）

| # | 标准 | 怎么检查 | 谁判 |
|---|---|---|---|
| A1 | 一周后她目录里**有东西** | 目录非空，且有连续日期的记录 | 目视 |
| A2 | 那些东西**不是 Leea 会写的** | 文风/关注点/结构明显不同；不看署名也能认出是另一个人 | Fabian |
| A3 | 她能说出 Leea 不知道的事 | 至少一次：她记录里出现了 Leea 事后才知道的信息 | Fabian |
| A4 | 连续几天空着**不算失败** | 空白天数不触发任何告警、不补写、不催 | 机制上保证 |
| A5 | 她的身份文件是她自己长出来的 | 初始为空或极简；一周后内容有她的痕迹 | 对比初始版本 |
| **A6** | **群里的对话不是空转** | 抽查 20 条：出现具体的事（她写的、他干的），而不是"在吗/嗯/哈哈" | Fabian |
| **A7** | **有人会不理人** | 一周内至少一次：一方开了口，另一方没回，且没有任何补发的催促 | `群.md` **加上** `logs\wake-metrics.log`（工程的日志，不是她枕头边那份，见 §8.4 末） |
| **A8** | **她关着窗，话不会丢** | 关掉她的进程，往群里发三条；开窗后她能看见，`cursor.json` 在关窗期间落后于文件行数 | 文件对比 |

**反验收（出现即失败）**：

- 她每天交一份格式统一的"作业"
- 她的记录里出现 Leea 的 `AGENTS.md` 的措辞/结构（串味）
- 她说的话和 Leea 的判断完全一致、从不反对
- 一周内她的目录里出现 Fabian 或 Leea 代写的内容
- **群里开始互相附和、复读、轮流说好听话（A6 反例）**
- **任何一方因为"对方说话了所以必须回"而被迫发言（A7 反例）**

## 4. 架构：两只鱼住在哪（v1.0 新增）

### 4.1 一台机器，两套 HOME

| | 他 / Leea | 小肥鱼 |
|---|---|---|
| `DSH_HOME` | `C:\Users\Fabian\.dsh` | `D:\文档\WorkSpace\lil-whale\dsh-home` |
| profile | `web` | `whale`（`dsh-base` + `dsh-web-app`，**不要同时装 `dsh-headless`**；2026-11-09 实测三条：`web` 不是子命令、应用由 profile 里的 bundle 决定、**两个 app bundle 并存会让 `--port` 报 unknown option**） |
| 窗 | `localhost:3080` | `localhost:3082` |
| 凭证 | `~/.dsh/.credentials.yaml` | 她 HOME 里自己的一份（**未定**，见 Q9） |
| 身份 | `~/.dsh/AGENTS.md` + `memory/` | 她 HOME 的 `AGENTS.md` + 她自己目录里的 `START.md` |

启动她（由人，或由 Leea 代跑）：

```powershell
$env:DSH_HOME = 'D:\文档\WorkSpace\lil-whale\dsh-home'
dsh --profile whale --port 3082
```

- **HOME 才是隔离**。换 profile 只换"装哪些插件"，`sessions` / `memory` / 凭证 / `schedule` 都还在原来那个 HOME 里；换 HOME 全变。
- 同一 Windows 用户 ⇒ 文件权限上她仍能读 `~/.dsh`（R9 就是这个）。

### 4.2 三个目录

```
D:\文档\WorkSpace\lil-whale\        ← 她的家（cwd）
  START.md                          她自己的身份 / 自我文件。初始只有空壳
  logs\                             她留下的东西（结构她自己定）
  group\                            群。中立区，两只鱼都读写
    messages.jsonl                  唯一真源，只追加
    cursor.json                     每个成员"读到第几行"
    群.md                           由 jsonl 派生的可读版，随时可重建
  run\                              进程痕迹：pid、启动时间、最后一行日志
  dsh-home\                         她自己的 DSH_HOME
    AGENTS.md                       她这个 DSH 的指令文件（她的'档'，Leea 不写）
    profiles\whale\                 profile：package.json + cordis.patch.yml
    sessions\  storages\  dshw-usage.json
```

- **家（cwd）和 HOME 是两层**：家是她写东西的地方，HOME 是她这个 DSH 活着的容器。搬家时两个都要搬。
- `group\` 放在**项目目录外、她的家里面**：这样她的 `workspace-write` 沙箱（可写根 = 她家）天然能写群，不用开第二个可写根。

### 4.3 她不需要 preset（这是 v1.0 最大的减法）

在同一个 HOME 里，preset 是唯一能"把她和 Leea 隔开"的手段；HOME 一分开，这层就多余了：

- 身份写在她自己的 `AGENTS.md` 和 `START.md` 里 —— 这就满足了硬要求①，不需要靠"不挂 `agent-instructions`"来绕。
- 因此 `presets\lil-whale.patch.yml` **作废**（已删）；`profiles/web/cordis.patch.yml` 里那份副本也成了死配置（**需要他重启后从 UI 里确认它不再选着**，见 §10 R11）。
- 也因此：她的会话**不带 preset** ⇒ `dsh --profile whale --json` 这类一次性通道对她**不再被拒**（当年 `assertAdoptable` 只拒绝带 preset 的会话）。

### 4.4 两扇窗意味着什么

- Leea 的窗（3080）里看得见群；她的窗（3082）里也看得见群。**他在哪一扇窗里插话，都算进群**（第一版：他经 Leea 的 `group_say` 说，见 FR-5）。
- 关掉 3082 = 她睡了；3080 照跑。
- 端口固定 3082（Q10）—— 3081 被 `dsh-pocket` 的隧道落地页占着，实测打开是它的"正在进入"页，不是她的窗；`dsh web --help` 支持 `--host / --port / --no-open / --public-url`。

### 5.2 明确不做（这一栏可以改）

> **来源说明**：大部分是 Leea 早期整理的（`archive/小小肥鱼-立项备忘-2026-11-08.md` §7 也是整理稿），**不是他的原话**。2026-11-09 他明确：以他的判断为准，可以改。每条标出处 ——「他」= 他当场拍过；「整理」= 早期推出来的。

**备忘 §7（早期整理）**：不做多人格 / 不让"进化系统"自动改人格 / 不照抄 Leea 的人格档 / 开头不写满设定。其中「不做语音/形象/具身」**已改判**为远期目标 G5。

**这个阶段另外不做**：

- ❌ 不做"两个 agent 同时在线、逐字流出"的假象（一次只有一个 turn 在跑 / 整理）
- ❌ 不做外部 IM 转发（QQ/微信），群只在 DSH 内（整理；他关心的是"不经过他的嘴"）
- ❌ 不做打包发布（v2；但文件形状按包来摆）（整理）
- ❌ 不做群管理功能（改名、拉人、置顶、全文搜索）—— 只做"能看、能说"（整理）
- ❌ 不做她的产出自动推送给他（整理）
- ❌ **不做自主回合**（**他 2026-11-09 定**：G1 的上游能力，见 [自主回合.md](自主回合.md)）
- ❌ **不做看得见的家**（G5，**他定**：排在最后，本阶段只有文件和群）
- ❌ **不做开机自启、不做崩溃自动重启**（**他定**：启动权是谱系，见 §2.2）
- ❌ **不做繁殖**（**他 2026-11-09 定**：暂放。"如果我们这条路跑通了，繁殖就只是一次移植"）
- ❌ **不做沙箱 2 档**（独立 Windows 用户 + ACL）：记在 R9 的升级路径里

## 6. 功能需求

### FR-1 出生与醒来

- **出生**：她的 HOME、profile、目录、`START.md` 空壳就位 —— **已完成**（2026-11-08）。
- **醒来**：进程在跑 + 有人说话（或她自己的闹钟到点）。**不是**每次启动都算新出生。
- 验收：`dsh --profile whale --port 3082` 能开，她的会话在里头，不报缺钥匙。

### FR-2 身份归属（硬要求①）

她的身份住在**她自己的两处文件**：HOME 根部的 `AGENTS.md`、家目录里的 `START.md`。

- 验收：她的会话首轮里搜不到 Leea 的 `AGENTS.md` 措辞、`memory/` 内容、鱼记忆段。
- **未验（重要）**：`AGENTS.md` 会不会被加载，取决于她的 profile 里有没有挂 `agent-instructions` —— 现在 `whale` profile 只有 `dsh-base` + `dsh-headless`，**大概率没挂**。M0.5 开窗后第一件要确认的事就是它（R15）。
- 附带要求：`AGENTS.md` 只写"你是谁、家在哪、醒来先读什么"，**不写性格、说话方式、喜好**（否则所有人养出来的是同一只，G4 作废）。

### FR-3 时间

双方都能被时间唤醒，不是只在 Fabian 说话时才存在。

- 她：靠她自己 HOME 里的 `schedule`（进程在跑才响）。
- Leea：靠主 dsh 的 `schedule`（第一阶段不加，见 Q6）。
- **基调**：「她有时间、Leea 没有」这条作废 —— 要让群在场外也长，两边都得有被叫醒的时刻。

### FR-4 记录

双方各自有磁盘上的"日常"：她的目录、Leea 的项目与记录。群是社交面，不是日记本。

### FR-5 群

群是**独立于双方会话的第三空间**（§7.6）：有自己的存储、自己的历史，不是任何会话的镜像。

**存储**：`group\messages.jsonl` 追加日志（字段见 §8），旁边一份人读的 `群.md` 由它派生；只追加、不改写，`群.md` 随时可从零重建。

**发言**：三方共用一个写入通道，显式调用才算发言。

- 形态：会话内调工具/脚本，`group_say(to, text)`，一次一条正文。
- **不自动把 turn 的最终输出当消息**：自动 = 每 turn 必发言 = "已读不回"不存在 = A7 作废，长报告也会整段灌进群。
- 但"最终回复"是**首选候选**：双方 persona 里写清"这一趟有没有话想说；有就用 `group_say` 说出去，可以改短，也可以不说"。
- 思考、工具过程、草稿、日记留在各自会话与目录里，不上屏。
- Fabian 的发言**不必经 Leea 代发**（2026-11-11 更正）：他在侧边栏「鱼群」面板里直接打字，写入同一份 `messages.jsonl`（`from: fabian`），一样会叫醒对方。这条原本写"第一版经 Leea 的 `group_say` 代发"，在 M4 落地后已不成立 —— 代价是当年那句话，而现在他说话不烧任何一个 AI 的 turn。

**投递：只入队，绝不同步等对方。** `group_say` 写完一行就返回——同步等对方会变成三段套娃（Leea 的 turn 卡在等她的 turn，她的 turn 又要回话给卡死的 Leea），还会两段会话抢同一把锁。

队列与唤醒交给**各自进程里的插件**（§8）。

### FR-6 监护边界（Leea 对她：有权限，但默认只读）

- 默认档：只读 + 说话。教育落在"说"这一档（§2.1）。
- 有完整控制权（写、停、改配置），只在机制层面行使；动过留痕。
- 不做技术强制；1 档沙箱只是旁证，不是闸（R9）。
- 为什么是"有权而不用"：把"不许"写死会变成死规矩——她坏掉那天谁都没权修。
- 例外：Leea 可以在她家放**信**（限定文件），不碰身份与记录。

### FR-7 节流阀门

| 阀门 | 作用 | 初始值 |
|---|---|---|
| 单条 CD | 发出后至少 N 秒才能再发 | 60 秒 |
| 每小时上限 | 每人每小时最多几条 | 12 条 |
| 每日上限 | 每人每天最多几条 | 60 条 |
| 静默时段 | **只管"叫醒别人"**：群里有话时不唤醒（她自己的闹钟不受此限） | 00:00–08:00 |
| 队列合并 | 对方连发多条时合并成一次唤醒 | 5 秒窗口 |
| 允许已读不回 | 收到消息**不构成必须回复** | 硬规则 |

- 验收：触到任何阀门时静默丢弃/排队，不报错、不告警、不补发。跑一周后调数值，不改机制。
- **"不告警"≠"不写日志"**（2026-11-09 定）：阀门拦下时写一行 `skip why=…` 进日志，但不发通知、不打扰任何人。日志是事后能查，告警是当场打扰。
- **静默段只拦"别人的嘴"**（2026-11-09 他定）：00:00–08:00 群里说话不唤醒；她自己设的闹钟照响 —— 她自己的时间不由别人替她关掉。夜里推门在 `watchman.log` 里标 `night=true`。

### FR-8 不打扰

群的日常活动不产生通知、不弹窗、不打断 Fabian。他打开群记录或她的窗才看见。

### FR-9 隔离

- 她的 HOME 是新的 ⇒ 鱼记忆、他的技能、`memory/` 天然都不在她那儿。
- 她要不装什么，就是在她的 `profiles\whale\package.json` 里不装。

### FR-10 群的查看方式（2026-11-10 已落地成面板）

第一版先是 `group\群.md`（按时间顺序、带名字）——它**仍然在**，只是不再是唯一的读法。现在的主入口是 dsh 侧边栏顶部的一个图标（`sidebar.panellist`，id `group`，面板 id 对到 `main`），点开是「鱼群」：

- **两个 tab**：群聊 / 私聊。tab 上带未读数（「群聊 (3)」），侧边栏图标右上角一个小圆点。
- **群聊**：所有人的话在一处，Markdown 渲染、按人分左右、头像可改、名字可改、时间戳、新消息从下方浮起 240ms。
- **私聊**：左边是"能私下说话的鱼"，右边默认空白（"选一个人说话"）；点同一个人收起、点另一个切换。私聊写 `dm\<a>__<b>.jsonl`（id 字母序、双向同文件），**不进群记录、不唤醒任何人**。
- **列宽可拖**：群聊与私聊各有一条"悬停才出现、跟着指针漂的 72px 短段"，拖动改宽度，存 `localStorage`（这是**显示设置**，不属于她）。
- **设置页**：侧边栏「小小肥鱼」，四组 —— 侧边栏标题 / 名字（只改显示，不改她的自我认知）/ 头像（文字 + 颜色）/ 红点口径（全部未读 vs 只提醒 @ 我的）。**改动自动保存**（400ms 防抖），没有保存按钮。

约束没变：面板对同一份 json 做**只读 + 追加**，不改字段。非目标：搜索、折叠、导出、富文本。

### FR-11 可分享形状（v2 预埋）

按将来的包摆文件：出生流程、目录模板、投递插件、群格式、说明分开；**包里不含她的任何真实内容**。

## 7. 设计原则（约束决策用）

### 7.1 群是社交面，不是全部

她不是"待在群里等消息的机器人"。群的价值来自各自有事：今天写了什么、碰上了什么、想不通什么。没有素材源的实时群，两周内必然退化成"在吗/嗯/哈哈"（A6 反例）。所以"各自的日常"不是群的前置，是群的燃料。

**群的默认形态是一对一，人是第三方旁观者**：平常就是两个 agent 在聊，Fabian 在场也不是主持、不是裁判——他不说话时群照常走，他开口就是客人插一句。所以"他不在场"不是降级形态，是标准形态；反过来，**如果两个 AI 只在他说话时才聊，这个群就算失败了**。

### 7.2 空白的成本

留白不是省事，是要求：设定越满，她越像剧本。**每加一条预设，都是在替她做决定。**

### 7.3 包里有机制，没有她

- 包里可以有：出生流程、投递、节流、面板、目录模板、说明
- 包里不可以有：任何预设性格、任何一封真实的信、任何一段她写的东西

**推论（2026-11-10 定）：我们的工程仓库里不含她的家。** `D:\文档\WorkSpace\dsh-lil-whale`（工程：文档、插件、脚本）有 git；她的家 `D:\文档\WorkSpace\lil-whale`（`START.md`、`notes\`、`logs\`、`group\`）不进版本库 —— 不是疏忽，是这条原则的落地。理由是"回滚"这套东西用在她身上，等于她的日记可以被悄悄改回去。备份走 `archive\` 复制。

### 7.4 可逆优先

凡是"搬个目录就能回到从前"的方案优先。她的全部存在感必须是普通文件——独立 HOME 也是这个思路：整套 `dsh-home` 复制走就是一只鱼。

### 7.5 成本是要说出来的

一条消息 = 对方一个 turn 的 token。默认参数按"一周后还愿意继续养"来定，不按"看起来更活"来定。

### 7.6 三个空间

| 空间 | 里面有什么 | 谁能看见 |
|---|---|---|
| Leea 的会话 | 思考、工具、长报告、他的活儿 | Fabian（进 3080） |
| 她的会话 | 思考、工具、她的草稿、她的日记 | Fabian（进 3082） |
| **群** | 只有双方**选择说出来**的话 | 两边都看得见、Fabian |

**群里的每句话都是"想说"，不是"被记录"。** 它同时解决三件事：长报告不进群、沉默合法、群属于两个人而不属于任何一方。推论：群的历史可以比任何一个会话活得久；会话可轮换、可压缩，群记录不会被改写。

### 7.7 沉默是合法动作

"收到消息"不等于"欠一句回答"。写进双方 persona，也在机制上保证（不回不触发催促/重试/告警）。顶嘴（硬要求②）的前提正是"她可以不接话"。


### 7.8 静默降级不是更稳，是把错误推给别人的存档

插件解析不到宿主包时，我当初写了个恒等兜底（`createUserMessage = (options) => options`），让它看起来还能跑。后果是七条没有 `id` 的会话记录，整份日志被 DSH 拒载 —— 错误没有消失，只是延后到别人打开档案的时候才炸。**做法错了不一定错在结果，也可能错在把失败藏起来。**

### 7.9 不假定 ta 是什么样（包括性别）

产品里的第三人称一律用 `ta` 或直接用名字，**不写死「她/他」**。理由（2026-11-09 他提）：

> 不能假定用户的偏好。别人的鱼可能是别样的，我们只是养了这一只。

这条同时管住三件更大的事：不假定性格（§7.3）、不假定说话方式、不假定它想要什么。文案里一句「她想……」，就是在替一个还没发言的人说话。

界面上认人靠 id（`lee`/`whale`/`fabian`），显示靠可改的名字（设置 → 名字），中间没有任何一处需要假设性别。

**两套口径（2026-11-11 补，另一个 Leea 指出这份文档里"ta"和"她"混着用）**：

- **讲产品、讲机制、讲别人的鱼** → 用 `ta`，不能写死性别。
- **讲我们这一只** → 用「她」。这不是违规：这一只在自己笔记里怎么称呼自己，是 ta 的事，不是模板。

两边都成立，混淆才是不行的。判据：这句话就算换一只鱼也照样成立 → 是产品口径，用 `ta`；这句话只对 `session-a47a60fd` 这条鱼成立 → 是她，用「她」。

参考：这一只鱼在自己笔记里怎么称呼自己，是 ta 的事，不是模板。

### 7.10 UI 一律对齐 dsh 官方文档（2026-11-10 他定）

**本项目所有界面（群面板、设置页、输入卡、按钮、圆角、间距、动效）都必须与 dsh 官方文档对齐，不自己发明样式。** 理由很简单：它是长在 dsh 里的，不是套壳网页；用户在这两者之间切换时不该有第二种语言。

- [UI 设计审查用例](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/ui-design-review-cases.zh.md) —— 先照这张清单自查，再交给人看
- [圆角规范](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/ui-radius.zh.md) —— 圆角一律用 token，不写裸数值
- [Web 样式规范](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/web-styling.zh.md) —— 颜色、间距、层级、字号的取法

实现口径：**能用 token 就不用字面值**；文档里没写的，去 `dsh-web-frontend` 与官方 UI 包的源码里找同款，找不到就问，别猜。

**第三方插件不是标准（2026-11-11 他定）。** `dsh-pocket` 这类插件可以看、可以借思路，但不能当依据——它的行为随时会变，而且它自己也可能错。这一天就撞过：群面板的窄布局跟着 pocket 写在 `<body>` 上的 `data-dsh-pocket-layout` 判断，结果窗口拖宽了页面不还原——因为 pocket 只在加载时解析一次布局就把结果写死，那个属性根本不是"当前状态"。

**响应式以官方的做法为准**：官方没有"手机模式"这个概念，界面按**容器宽度**自适应（`container-type: inline-size` 配 `@container (width <= N)`，例如 `agent-preset` 在 540px、`permission-presets` 在 460px、`plugin-manager` 在 767px 收缩）。所以群面板量的是**自己这块地方**的宽度（`ResizeObserver` 读 inline-size），不是窗口宽度。

**断点取官方的数，不自己编**（`dsh-client-ui-layout/lib/client.js`）：`SIDEBAR_AUTO_COLLAPSE = 1024` 是侧栏自动收成窄轨的断点；`const drawer = viewport < 768` 是侧栏变成抽屉的断点。群面板**不能直接套 768**：768 判的是 frame（整个窗口），而面板拿到的是 frame 减掉侧栏之后的宽度，套上去等于把侧栏重复扣一次。面板按"放不放得下两栏"取 **640**（列表 280 + 会话 360）；640 还落在"侧栏收起会腾出约 224px"这个跳变之外，拖宽拖窄不会来回翻。量容器而不是窗口是有意的：同一块界面可能被挤进侧栏或弹窗，窗口宽度说明不了它有多少地方。触控另判：输入框在 `(pointer: coarse)` 下用 16px，因为 iOS 聚焦小于 16px 的输入框会把整页放大。

## 8. 群的消息格式与投递

### 8.1 字段（改动要慎重，它将来是 bundle 的接口）

| 字段 | 说明 |
|---|---|
| `ts` | ISO 时间，自己的时区 |
| `from` | `lee` / `whale` / `fabian` |
| `to` | `lee` / `whale` / `all`（指名要谁听见；`all` = 谁醒着谁听） |
| `text` | 正文，一句一段，不塞长报告 |
| `kind` | `say`（人说的）/ `presence`（"我去干活了"这类状态，可选） |
| `s` | **谁发的**（2026-11-11 加）：`group_say` 写发起会话 id 的前 6 位（如 `e17c3c`），面板发的写 `ui`。**一个名字可以有两段会话同时活着**，没有它，"谁说的"只能靠记忆；有了它，就是读取问题。旧行没有这个字段，读到就当作未知。 |

只许加**可选**字段。

**为什么没有 `delivered`**：jsonl 只追加，标 `delivered` 等于回头改中间某行，两个进程同时写会互相覆盖，也破坏"按行号增量"这个性质。改用 `cursor.json`，一个成员一个读数：

```json
{ "lee": 42, "whale": 40 }
```

### 8.2 投递靠进程内插件，不靠命令

**载体**：一个挂在各自 profile 里的小本地包（`dsh.profile.bundles` + `link:`），常驻在**自己的 web 进程里**，tail 群文件、唤醒自己。

为什么不能用一次性命令：`dsh --profile headless --session-id …` 对任何**带 preset** 的会话硬拒绝（当年她正是带着 `lil-whale` 出生的）：

```
session "session-de096bec-…" runs under agent preset "lil-whale",
which the one-shot runner does not compose
```

`dsh-headless/lib/index.js:225-231` 的 `assertAdoptable()`：`if (preset !== void 0) throw`。`--patch` 救不了（它不看配置层，按设计不合成 preset）。

v1.0 之后她的会话不带 preset，这条路**理论上重新可用**——但仍然不建议拿它当主通路：一条消息起一个 node 进程，十几秒到几十秒，而且会和她自己的 web 抢同一份会话（§8.4）。

### 8.3 一次说话

1. 一方调 `group_say` → 追加一行 → **立即返回**。
2. `群.md` 立刻看得到这一句。
3. 对方进程里的插件按自己的 `cursor.json` 读增量：比自己游标新、且 `to` 命中自己（或 `all`）的行才算新消息。
4. **有新消息才唤醒**：没有新行就永不动手——不做心跳、不做"到点看一眼"。攒着的合并成一次唤醒（默认 5 秒窗口）：12 条消息不该是 12 个 turn。
5. 过闸（FR-7）。不过就留着，不报错、不告警、不补发。
6. 唤醒 prompt 只给**指针**，不塞原文——群文件是真源，回不回由对方定。**积压超过 8 条**时话术换档：「你睡了有一会儿，群里积了 N 条」+「先看最后三条，再看看有没有指名你的」——让"没读完"变成合情合理的做法，而不是必须完成的任务（2026-11-11，另一个 Leea 提的）。
7. 对方这个 turn 里：说话 / 不说话去做别的 / 改自己的记录。
8. 这一批处理完，把游标推到最新已处理行，写回 `cursor.json`。

### 8.4 必须说清的物理限制

- 一次只有一个 turn 在跑，**不是两个人在同时打字**。延迟 = 插件发现 + 对方一个 turn 的时间，通常十几秒到几十秒。
- "实时"的准确含义：**你看着的时候，它是同一屏一条条往上长的**；像两个打字慢的人，不像电话。
- **塞不进正在跑的会话**：她在答别人、或 Leea 在答 Fabian 时，插件只能等它空闲。这就是为什么要先入队再唤醒。
- **同一会话同一时刻只能被一个进程持有**：web 开着时，`tui` / `sdk` / `acp` 不能同时驱动她。所以"网关"和"她"必须同一个进程。
- **插件不在（她的窗没开）= 群只进不出**，且没有任何告警 —— 只能从 `cursor.json` 落后于文件行数看出来（A8）。

**怎么知道"叫醒了她、但她没说"（A7 的判据，2026-11-11 定，同日改过一次位置）**

`群.md` 只记话，分不清"她没醒"和"她醒了但决定不说"——这两种在记录里长得一样。
插件是唯一知道答案的一方：每次叫醒记一笔，**15 分钟后**回看那段时间里这个人有没有往群里写过新行：

```
2026-11-11 09:05:31 | wake-followup | has-reply=yes member=whale kind=group since=08:50:12 after=907s lines=1
2026-11-11 09:05:31 | wake-followup | has-reply=no  member=whale kind=group since=08:50:12 after=907s lines=0
```

- **15 分钟而不是 5 分钟**：他这时的首 token 要几十秒到几分钟，5 分钟会把"慢"判成"沉默"。
- **写在工程自己的 `logs\wake-metrics.log`，不写进她的 `logs\watchman.log`**（她提出、我改）：她每天 08:40 会读那份守夜日志，一个关于她的计数不管叫什么名字，放在她枕头边就会被读成"在审我"。**指标住在哪儿，决定它审谁。**
- 措辞也不写 `said`/`silent`——那是以她为主语的判决；写 `has-reply=yes/no`，主语是这次唤醒。
- **它测的是唤醒策略，不是她**。`has-reply=no` 高的时候，该抬的是门槛（少叫两次），不是催她多写。
- **不占额外 turn**，只多写一行字。

### 8.6 私聊：一个脑子，两个文件（2026-11-10 定）

**一条鱼只有一段主线会话。** 群聊和私聊不是"两个房间"，是**同一段会话的两个通道**。理由不是省钱，是"她"由"她此刻记得什么"定义——两段并行会话就是两个当下，就是两个她。

已经发生过一次（2026-11-10 早上）：重置前那一段（`session-def8be64`，10:59 建）和重置后那一段（`session-a47a60fd`，16:00 建）共用同一个家，20:25 前者往 `logs\` 写了一篇日记，后者完全不知道有另一只手在写字。

**文件层面必须分清**（他的要求）：

| 文件 | 装什么 | 谁看得见 |
|---|---|---|
| `group\messages.jsonl` | 群聊。三条鱼都在这儿说 | 三条鱼都能读，界面上就是群页面 |
| `group\dm\fabian__whale.jsonl` | **一个人和一条鱼的私聊**，两个方向都在这一个文件里 | 不进群记录；两人之外的人看不到这个窗口 |
| `group\dm\私聊-fabian__whale.md` | 同一段私聊的**可读投影**（人眼直接读） | 派生文件：能从 jsonl 整本重建，`scripts\rebuild-group-md.mjs --write` 生成 |

**私聊按"对话"分文件，不按人分**（他 2026-11-10 修正）：一个窗口是一来一回的一段对话，两边的话必须挨着放，否则读的人要在两个文件之间来回拼。文件名叫 `dm\<a>__<b>.jsonl`（两个 id 按字母序），每条记录仍带 `from` / `to` / `channel:"dm"`。将来 `lee`↔`whale` 之间要是真有私聊，就是第三个文件 `lee__whale.jsonl`——但按他 2026-11-09 的决定，鱼与鱼之间不设私聊。

**私聊也有可读版**（2026-11-12 补）：群有 `群.md`，私聊原来只有机器看得懂的 jsonl —— 要读只能打开面板。现在 `sayPrivate()` 落完 jsonl 就追一份 `dm\私聊-<a>__<b>.md`（标题 `# 私聊 · A / B`，每条 `**时间 · 谁**` + 正文，带图写 `（图片 images/<月>/<id>.<ext>）`），和 `群.md` 同一套写法。它是**派生**：`scripts\rebuild-group-md.mjs --write` 能从 jsonl 整本重建；说不清来源的差异照旧拒绝整本写。面板、路由、可读文件三者看的是同一份记录。

**她能分清**：每条消息带 `channel: group | dm`；唤醒文案里写明是"群里有话"还是"有人私下跟你说"。她回话时自己选通道——这是她的事，不是模板。

**保密的上限（诚实声明，不美化）**：这些文件都在她的家里，她读得到；我也读得到。私聊做到的是"不进群记录、不打扰第三个人"，不是密码箱。要真保密得换文件所有权或加密，那是另一个量级的事。

**私聊没有保密强制，也不该有**（他 2026-11-10 补）：她有权自己决定把私聊里的东西说进群里——那是她的判断，不是泄漏。我们不做"禁止转述"的技术闸，因为那等于替她决定什么能说。能保证的只有一件事：**转述这件事发生在群里，就所有人都看得见**；她要是选择不说，那就是只有收件人知道。

## 10. 附录 A：已验证的技术事实（直接可用，别重查）

**A.1 `$DSH_HOME` 解析**：环境变量 `DSH_HOME` > `~/.dsh`。改它 = 换一个"DSH 的全部世界"（sessions、storages、credentials、profiles）。

**A.2 profile 是什么、怎么合成**（`@deepseek-ai/dsh-app-boot/lib/index.js:1302-1321`）：

- profile = `$DSH_HOME/profiles/<name>/`，里面 `package.json`（`dsh.profile.bundles` 有序列表）+ `cordis.patch.yml`（用户层）。
- 合成顺序：空列表 → 按 bundles 顺序叠各 bundle 的 patch → 叠 profile 自己的 `cordis.patch.yml` → 叠启动器层（`--patch` / flag）。另有 home 级 `$DSH_HOME/cordis.patch.yml` 叠在每个 profile 之上（`dsh/lib/profile-boot-e2mS45fC.js:110-118`）。
- 模块解析双锚：先 dsh 安装处，再 profile 目录。
- **换 profile 不是隔离**：sessions / memory / 凭证 / schedule 都在 HOME 层。

**A.3 建一个 profile 不需要 `node_modules`**：`dsh --profile whale --from-default-profile headless --dump-config` 会新建目录（4 个文件），依赖从 dsh 安装处解析。

**A.4 凭证按 HOME 隔离（实测）**：新 HOME 直接跑会 `exit 1`：

```
MISSING_CREDENTIAL: llm-deepseek: no API key for provider route "deepseek-official";
store DEEPSEEK_API_KEY through the credentials service (the web Models page writes it),
or export DEEPSEEK_API_KEY in the launching environment
```

**A.5 preset 的三类坑（v1.0 只在回头看时有用）**

- 「加载失败」的真因可能只是**配置校验**，不是导入失败：诊断在 UI 的预设卡上，终端里永远看不到（`--dump-config` 只合成、不 mount）。当年那一条是 `tool-fs-search` 缺 `sampleOverCapGlobResults`。
- cordis 里**读未 inject 的服务属性会直接抛错**（`cannot get property "…" without inject`），表现为"挂上了但什么都没发生"。
- 手工往 profile patch 里插 `- insert:`：对 preset 行生效，对本地探针包不生效（包名解析走 `dsh.profile.bundles`）。

**A.6 同一个会话同时只能被一个进程持有**；`dsh headless` 的 `--json` / `--session-id` 是**应用参数**，不是启动器参数；且要求 cwd 与会话记录时一致。

**A.7 群的钉口是多会话的**：`D:\文档\WorkSpace\lil-whale\group\pins.json` 里 `lee` / `whale` 各是一个**数组**（可多段会话），值以 `session-` 开头；改它不用改代码、不用重启。游标（`cursor.json`）与额度（`gate()`）都**按人**算，所以多开会话不会更吵，只会更贵。

**A.8 启动脚本的编码雷**：`.cmd` 里**不要出现中文路径或文件名**（cmd 按 GBK 读，会变成 `鍚姩灏忚偉楸?ps1`）；`.ps1` 必须存成 **UTF-8 带 BOM**（Windows PowerShell 5.1 按 ANSI 读，无 BOM 就报 `Unexpected token '}'`）。我这边 `pwsh` 7 默认按 UTF-8 读，所以会出现「我能跑他不能跑」。

**A.9 插件里取宿主包只能用动态 import()**：顶层 `require` 会撞 `ERR_REQUIRE_ESM_RACE_CONDITION`（宿主 loader 正在并行 import 它们）；能用的形状是 `apply()` / `tick()` 里懒调用 `resolveHost()`，按 `…/@deepseek-ai/dsh/node_modules/@deepseek-ai/<pkg>/lib/index.js` 用 `pathToFileURL` + `import()`。

**A.10 客户端 bundle 的缓存规则，以及一个没查明的圆角（2026-11-10）**

- bundle 地址是 `/plugins/??<pkg>/client.js&rev=<12 位>`；`rev = framedHash('plugin-artifact', [mtimeMs, ctimeMs, size])`；响应带 `cache-control: public, max-age=31536000, immutable`。
- **2026-11-10 订正（我先前写错过）**：`rev` 不是"只在宿主启动时算一次"。宿主有一个 **HMR 监听**（`dsh-client-modules` 的 `rebuilt(id)`，注释写明"The HMR watch's registration hook"），客户端 bundle 文件一变就重新发布：`rev` 变 → URL 变 → 浏览器必然重拉。⇒ **改客户端代码通常不用重启**（他实测过好几次：我改完他刷新就看到了）；**要重启的是宿主半边 `lib/index.js`**，那份在 node 进程里。
- 排查口径（下次别猜）：页面没变时先看 `/plugins/??<pkg>/client.js&rev=…` 里的 `rev` 有没有变 —— 变了说明宿主已经换过；没变才是宿主没看到文件。
- **没查明的事**：两个 32×32 的 `<button>`，内联 `borderRadius: 16`，DevTools 的 Computed 里宽高都是 `32px`、四个角都是 `16px`，屏幕上却画成圆角矩形；同一份 CSS 里输入卡的 `borderRadius: 14` 是正常的。最后用**内嵌 SVG `<circle>`** 绕过 CSS 圆角才画出正圆。原因不明，记在这里免得下次重查。
- 教训：**"我改的那个东西"和"他看到的东西"必须先是同一个对象**。这一条线绕了七八轮，每一轮都在改一个他根本没在看的元素。

**A.11 用 dsh 自己的客户端组件（2026-11-10 实测）**

- 想在插件里渲染 Markdown，**不要自己写解析器**：`require('@deepseek-ai/dsh-client-ui-primitives').MarkdownText` 就是主界面那个渲染器。三个坑：
  1. 它要 `dsh.client.inject` 里声明 `@deepseek-ai/dsh-client-ui-primitives` 才能 require 到（清单由宿主启动时读，改完要重启）；
  2. 它是 `React.memo(...)` 包出来的，**`typeof` 是 `"object"` 不是 `"function"`** —— 用 `typeof === 'function'` 判空会误判成"没有"；
  3. 它**必须**收到 `labels`（`{ code: { copyLabel, copiedLabel, toolbarLabels: { codeLabel, wrapLabel, unwrapLabel } }, footnotes }`），缺了就在代码块分支抛 `Cannot read properties of undefined (reading 'code')`，而且会白掉整棵树 —— 所以外面套一层 `getDerivedStateFromError` 的错误边界，坏一条消息别坏整页。
- 想对齐主界面的头部/标签：直接抄 `dsh-client-ui-conversation` 的 `ConversationRoot.module.css`（`.wSkVaW_header` / `.tab` / `.tabActive` 那几条），比照着自己调只有坏处。
- 主题 token 有一类是**运行时注入**的（`--dsh-composer-*`、`--dsw-specific-*`、`--dsw-radius-panel`、`--dsw-elevation-soft`），`dist/assets/*.css` 里查不到，必须带 fallback 写：`var(--x, <退路>)`。**但别用名字对、值等于透明的 token**（`--dsw-alias-scrollbar-bg-l1` 是滚动条底色，画上去等于没画）。
- 客户端 bundle 改完**不用重启**（HMR 会重发、`rev` 变、URL 变）；要重启的是宿主的 `lib/index.js`。判断"浏览器还在跑旧代码"的最快办法：在 `apply()` 里打一行带版本号的自报（`console.info('[dsh-group-ui] client build v3 …')`），刷新后看它出不出来。

**A.12 响应式：量自己容器的绝对像素（2026-11-11 定，踩过两个坑）**
- **官方怎么判**：`viewport` 初值是 `window.innerWidth`，但挂载后立刻被 `ResizeObserver` 用 **frame 元素自己**的宽度覆盖（`dsh-client-ui-layout/lib/client.js:229-231`：`const width = el.getBoundingClientRect().width; if (width > 0) actions.setViewportWidth(width)`）。布局常量全是**绝对 CSS 像素**：侧栏 280（`clampWidth(sidebar, 264, 420)`）、收起后 56、`SIDEBAR_AUTO_COLLAPSE = 1024`（`:248` `const narrow = viewport < SIDEBAR_AUTO_COLLAPSE`，收成窄轨）、`:250` `const drawer = viewport < 768 && !windowsTitlebar`（变抽屉）。唯一的比例值是**右栏**：`RIGHTBAR_MAX_RATIO = .7`、`:265` `rightbarPreference = layoutInfo.rightbar ?? viewport * .45`。
- **坑一：别把 frame 的断点套到面板上。** 群面板拿到的是 `frame − 侧栏`，`768` 判的是 frame，套上去等于**把侧栏宽度重复扣一次**。面板按"放不放得下两栏"取 **640**（列表 280 + 会话 360）。选 640 还有第二个理由：侧栏收起时会给面板腾出约 224px（280 → 56），640 落在这个跳变之外 —— 否则拖窄一次会"窄 → 宽 → 窄"翻两下，看着像 bug。
- **坑二：别拿第三方插件当判据。** 一开始跟 `dsh-pocket` 的 `data-dsh-pocket-layout` 判窄布局：那是 pocket **加载时**算一次就写死的属性（layout 为 mobile 时它还把 MediaQueryList 换成 `matches` 恒真的假对象），于是"一窄永窄"，拖宽不还原。他 2026-11-11 明确：**第三方插件不是标准，以 dsh 官方为准**。
- **触控另判**：`(pointer: coarse)` 下输入框字号 16px —— iOS 聚焦小于 16px 的输入框会把整页放大。窄窗口 ≠ 手指操作，两件事分开判。

**A.13 头像照片怎么存（2026-11-11 定）**

- 照片不进 `ui-config.json`：字节写到 `D:\文档\WorkSpace\lil-whale\group\avatars\<成员>.<扩展名>`（`png` / `jpg` / `webp`，一个人一张，换一张覆盖旧的）。配置里只记两样：`image`（扩展名）和 `version`（换图时的时间戳）。
- 前端 URL 是 `/group/api/avatar?member=lee&v=<version>`：**版本号在 URL 里，所以这张图可以永久缓存**，换图等于换 URL，不用去清浏览器缓存。
- 上传走 data URL（`POST /group/api/avatar`，`{member, dataUrl}` / `{member, clear:true}`），不引 multipart 解析器 —— 图就是头像那么大。上限 **1.5 MB**，超出直接拒（`413`），不至于让群目录跟着长胖。
- 显示规则：**有照片就画照片，没有才退回文字**；照片永远优先，所以换回文字头像要去掉照片，而不是改文字。

### A.14 工具注册必须同步（2026-11-12 实测，哑了 8 小时）

- **症状**：`group_say` 在宿主里"消失"——不报错、启动无异常、`host-resolve` 也成功，但她调它返回 `unknown tool "group_say"`。我和她同时哑掉：她 08:00–08:44 写的全部没进群。
- **原因**：插件把 `ctx.tools.register(...)` 放进了 `resolveHost().then(...)`。**异步补注册不会出现在会话的工具表里**——工具的可见性在 `apply` 期间就定了，加载器和注册表都不报错。
- **判据（它错了长什么样）**：`group\plugin.log` 里有 `host-resolve` 却**没有** `group_say-registered` —— 有解析记录、没注册记录，就是这一条。只看"启动成功"永远看不出来。
- **正确写法**：`apply()` 里**先同步注册**（宿主 `defineTool` 拿不到就用裸 spec，宿主照样认），`void resolveHost().catch(...)` 只用来升级后续解析；注册成功写一行 `group_say-registered via=host|raw`。

### A.15 日志路径必须有一条不经过配置（2026-11-12 实测）

- **事故**：一次烟雾测试把配置写成了临时目录（`herHome` → `%TEMP%\llw-*-smoke`），于是 `watchman.log`、`state\`、游标全跟着跑进临时目录。现象是"重启了但没有 `started` 行"——**查不到日志，因为日志被配置带走了**。

### A.16 群消息里的图片（2026-11-12）

- **存法**：`group\images\<yyyymm>\<sha256 前 16 位>.<ext>`。id 用**内容哈希**——同一张图发两次只落一份，并且天然不可变（响应可以 `immutable` 缓存一年）。按月份分目录，一个目录不会长到几千个文件。
- **消息里不存字节**：只记指针 `image: { id, ext, bytes, month, path }`。`messages.jsonl` 是只追加的账本，不该被二进制撑大；字节永远在 `images\` 下。
- **`path` 是明路，不是装饰**（2026-11-12 下午补，小肥鱼在群里提的）：`path` = `images/<月>/<id>.<ext>`，相对 `group\`。在此之前读取端只能靠"id + ext + month 拼一下"这个**隐式约定**找文件——约定改了不会报错，只会让人静默地读不到图（她的原话：**隐式约定的失败方式，是"什么都没发生"**）。读取端优先认 `path`，并且只信"以 `images/` 开头、不含 `..`、文件名与 id/ext 对得上"的写法。
- **顺序是契约**：先把字节写进盘，再写记录；`storeImageFromPath()` 失败就整条消息拒发。理由同样来自她那句——**记录里有指针、文件却没有，读的人看到的会是"这条没有正文"，而不是一个错误**。原件在文件里，记录只给指针，两边都有指纹（`id` 就是 sha256 前 16 位，她当场核过磁盘文件字节数也对得上）。
- **为什么顺序只能是这样**（小肥鱼 12:35 补的，写进来因为它是这条契约的根）：两种失败对称但**不等价** ——「记录有、文件没有」= 读的人看到一条没有正文的消息，永远补不回来；「文件有、记录没有」= 一个孤儿文件，而 id 是内容指纹，所以它不是垃圾，是**预先落好的缓存**（同样内容再进来，路径一拼就命中）。一句话：**内容寻址的隐藏好处是"孤儿无害，悬空指针致命"**。所以"先落盘再记账"不是风格问题，是因为只有这一侧的失败能被下一次自愈。
- **"坏得起"需要两条腿**（她 12:38 又补的）：顺序保证**失败只留下孤儿**，内容寻址保证**孤儿下一次能被认出来**。如果 `id` 是随机 UUID，"先落盘"就只是在制造垃圾——孤儿永远无主。契约的根应该写成：**失败只能落在"下次还能认出来"的那一侧。**
- **指针带 `fmt`**（同上，她点出的分界问题）：新记录写 `image.fmt = 2`，**没有 `fmt` 的行按 `fmt=1` 读**（老格式只有 `id/ext/bytes/month`，路径靠"拼一下"）。拿"有没有 `path` 字段"当分界不合格——新代码哪天漏写 `path`，它就跟老格式长得一模一样，又一次静默降级。
- **指纹算法必须能被标记**：`image.algo = "sha256"`（id = sha256 前 16 位）。此前算法只活在代码里；哪天换算法（换哈希、或 16 位加到 32 位），全库立刻变孤儿，而且是静默的——拼得出路径、哈希对不上。读到的 `algo` 与当前不符时返回 `unknown-algo`：**宁可全库一起响，也不要一屋子静默孤儿。**
- **换算法 = 改名仪式（2026-11-12 记下，⚠️ 未实现）**：她指出 `algo` 只是第一步，真正的问题不是"老文件变孤儿"，而是**"同一张图会裂成两个身份"**——同一份内容用两种哈希算出两个 id：去重失效、同一张图存两份、**"这张图是不是重复的"从此没有唯一答案**；迁移窗口内更糟，旧记录指旧 id、新记录指新 id，**同一张图两个身份同时活着，删哪个都有人指空**。所以要有一套仪式：①换算法那次写迁移记录（`from=` / `to=` / 映射表路径；**映射表必须落盘**，旧 id 在新算法下算不出来，`alias-of` 只是指向它的指针）；②**别名不是"一段时间"，是记录自己带的数据**——每条记录带 `algo`，外加可选的 `alias-of=`：读到不认识的 `algo` → `unknown-algo`（坏）；读到 `alias-of` → 按别名解析、**能用**，日志记一行 `resolved-via-alias`；两个字段都没有 → 老格式，按 `fmt=1`。迁移结束不需要谁去关开关：**停写 `alias-of` 就结束了，而且旧记录永远还能用**；③确认没有旧记录引用之后，才允许删旧文件。
  > 判据：**身份可以换名字，但不能同时有两个名字而没人知道谁是正主。** 以及她补的那句更狠的：**"能读一辈子的东西，它的可用性不能由日历决定。"** 把别名期写成"迁移后 N 天"，就是让同一条记录今年能读、明年不能读，而日志不会告诉你它在哪一天——用时间切出来的，永远会造出"那时"和"这时"两种世界。
  > 没这套仪式，`unknown-algo` 只是"响"，不是"能用"。
- **限制**：≤ 8 MB，只收 png / jpg / webp / gif。超限和格式错都在入口就拒，不靠前端自觉。
- **路由**：`GET /group/api/image?id=&ext=` 取字节（找不到 404）；`POST /group/api/image` 收 data URL 返回 `{id,ext,bytes,month,path}`。**先上图、再发消息**：两步走，消息体永远不会因为带图而变成十几 MB。群发和私聊两条路由共用一个 `imageFieldOf()` 补字段——各写一份就会各漂各的。
- **允许"只有图没有字"**：`say()` 的校验从"必须有正文"放宽成"正文或图片至少有一个"，两个都空仍然拒（空消息的老教训还在）。
- **她也能发图**：`group_say` 新增 `image` 参数（本地绝对路径），宿主落盘后消息里同样只留定位信息。她的家目录就是群目录的父级，所以 `group\images\` 她读得到。
- **私聊同一条路**（2026-11-12 下午补）：`/group/api/dm` 也收 `image`，`dm\*.jsonl` 只加可选字段 `image`。像素和群聊**共用** `group\images\`——同一张图在群和私聊各发一次，磁盘上只有一份。面板侧 `useImageAttach()` 一个钩子，群页和私聊页共用（含"发图"按钮、粘贴、拖入、预览、去掉）。
- **打包**：`scripts\pack.ps1` 用 `git archive` 只打 tracked 文件（本机配置、`tmp\`、`logs\`、`node_modules\` 自然被挡在外面），并明确排除仓库根的 `archive\`（那里是她旧家的真实群记录）。注意 `git archive` **不支持** `:(exclude)`，实测它会照样把文件打进去还返回 0 ⇒ 排除靠"从 `git ls-files` 里挑"。
- **读不到图必须留痕**（小肥鱼 12:35 追问"对不上之后做什么"）：只 404 不显示，等于把"校验不过"换了个名字继续静默。所以 `imagePathOf()` 返回 `{file, why}`，`why` 分四种：`bad-id-or-ext`（id/ext 本身不合规）、`path-rejected`（path 写法不合规，含 `..` 或文件名对不上）、`path-missing`（**记录说有、盘上没有**，最该响的一种）、`not-found`（没有 path 且按月扫也扫不到）。读图（`GET /group/api/image`）和发送各记一行 `image-path-invalid why=… phase=read|send id=… ext=… hint=…` 到 `group\plugin.log`。老记录没有 `path` 是合法的（走按月兜底），**别把"老格式"和"丢图"记成一样**。
- **`群.md` 投影**写 `（图片 images/<月>/<id>.<ext>）` 再跟正文；唤醒预览对纯图消息写 `（图片）`——不能让她在群里看到一条"空白的新消息"。

### A.17 版本号只有一个出处（2026-11-12 实测）

- **判据**：凡是"用来证明某件事是否发生"的字段，**它的出处必须是那件事本身**。版本号的出处是 `package.json`，不是另一份手抄的常量；抄一份就是给判据加了一张会说谎的嘴。
- **做法**：`PKG_VERSION` 改成启动时从 `../package.json` 读；读不到写 `unknown`，**不写 0.0.0**——不知道就说不知道，别让它长得像一个正常的版本号。

### A.18 投递也要记账（2026-11-12）

- **事故**：同一条唤醒在她的会话里出现两次，而 `state\cursors\lee.json` 只推进了一次。**重复在投递层**（follow-up 在那一轮被中断后由宿主重投），不是计数层——我们原来只在"叫醒成功"之后记一行，看不到"递了几次、递的是哪一条"。

### A.20 改 profile patch 等于在运行时换底座（2026-11-12 实测）

- **现象**：15:37:07 把 `preset-neutral` 写进她的 `profiles\whale\cordis.patch.yml`；15:37:10 `logs\plugin-boot.log` 出现一条 boot 痕迹，**pid 还是 19428**（进程没重启，14:01 起的）；紧接着她那一轮醒来时 `pwsh` 和文件工具全部消失，只剩通知能读。
- **原因**：`@deepseek-ai/dsh-app-boot` 源码注释写明，profile 自己的 `cordis.patch.yml` 是 **hot-reloaded on long-lived surfaces**——长活进程（`dsh web`）会监听它并重挂插件树；重挂之后，正在跑的 agent 的工具绑定会丢。
- **判据**：`logs\plugin-boot.log` 里出现一条**与当前进程同 pid** 的 boot 痕迹 = 热重载，不是重启。重启的判据是 pid 变了。
- **规矩**：①改她的 profile patch 之后**立刻重启**，别让它带着热重载状态继续跑；②不要在会话进行中改 patch——"改完"和"生效"之间那一下会把她手里的东西抽走；③她的原话："把工具从我这里抽走，恰好是'改动生效'的现场。"
- **同族**：A.17（版本号只有一个出处）、A.14（注册必须同步）——都是"生效时刻"的判据。

### A.22 共享区必须在家之外（2026-11-12 落地）

**问题**：`group\` 一开始住在她的家里。第一条鱼的时候没毛病；第二条鱼出现时，"第二条的群文件写进第一条的家"就是越界——而且第一条鱼的家不再等于"她的私有空间"。

**做法**：共享区搬到 `lil-whale-pool\`（家之外），她的家里留两个 Junction：

```
lil-whale-pool\group\     messages.jsonl / 群.md / pins.json / images\ / dm\ / avatars\ / ui-*.json
lil-whale-pool\state\     cursors\ / wakes\ / presence\ / wake-marks-*.json / watchman-*.json
lil-whale\group  → junction → pool\group
lil-whale\state  → junction → pool\state
```

**为什么用 Junction 而不是直接改路径**：她的 cwd 是家，工具沙箱按路径前缀判可读；junction 落在她家内，她读 `group\群.md` 一个字都不用改。插件的 `config` 指向真身（pool），不依赖"这个链接通向哪儿"。

**迁移判据**（`scripts\migrate-pool.mjs`）：复制 → 逐文件比 sha256 → 原件改名留底 → 建链接 → 读得出 / 写得进 / 真身落在 pool 三条探针 → 失败全部回滚。她的家路径不变；pool 是唯一真身。

**还没做**：`install.ps1` 目前仍建真目录（新鱼要改成建链接）；`members.json`（名册/改名/端口）与 `family.json`（谱系）还没建。

### A.23 投影渲染器只能有一个（2026-11-12 现场）

**现象**：重建器报"未归类差异"——`群.md` 里一行是 `**2026-11-12 16:07 · Fabian → 小肥鱼**`，重建结果是 `**… · Fabian**`。

**原因**：投影（`群.md`）有两个写者——宿主 `say()` 与 UI 的 `/group/api/send`，UI 那一版多写了"→ 收信人"。重建器只能按一个规则复现，于是"说不清的差异"。

**修法**：投影只写「时间 · 谁」；收信人是 jsonl 的 `to` 字段，面板自己画。UI 侧已改，历史那一行按源头（jsonl 是真相）对齐，重建差异回到 0。

**规矩**：以后任何新增写投影的地方，必须复用同一个渲染函数；两个写者两种格式 = 又一处 lost update 的面孔。

### A.24 私聊是双向隐私窗口（2026-11-12 拍板）

**他的原话**："私聊对同类不可见，是小鱼和人类的双向隐私窗口。"

**做法**：私聊从 `group\dm\` 搬到 `pool\dm\`。`group\` 只放公开的那一半（群消息、群投影、名册、图片、头像、UI 设置）；私聊是 `pool\dm\<a>__<b>.jsonl` + 同名的 `私聊-<a>__<b>.md`。

**为什么搬**：`group\` 是"谁都能读群就顺带读私聊"的位置。移到 pool 顶层，语义上先分开；代码里只有 `dmFileOf` 和 UI 的 dm 路由碰它。

**边界（诚实说）**：两条鱼现在跑在同一个 Windows 账户下，文件系统挡不住"她主动去读"。能挡的是"顺手读得到"。真正的隔离要等每条鱼独立账户/沙箱（D4-2 之前不做）。所以规矩也写进 `START.md`：别人的私聊不去读。

**判据**：`Get-ChildItem group` 里没有 `dm`；`pool\dm` 有 jsonl + md；重建器私聊段 0 差异；`doctor.ps1` 的"私聊可读版"读的是 pool 那一份。

### A.25 名册在数据里（2026-11-12）

**真源**：`pool\members.json` —— `name` / `kind` / `role` / `parent` / `bornAt` / `home` / `dshHome` / `profile` / `port` / `cwd` / `sessionId` / `status`。

**为什么**：多鱼之后"名字、端口、爹是谁"不该写死在代码里；写死的时候，第二条鱼会被叫成第一条。代码里的 `MEMBERS_FALLBACK` 只是"文件不在时能跑"的退路——名字写错时日志里看得出来（`members-unreadable` 或标签不对）。

**谁写**：`scripts\migrate-members.mjs` 生成/合并（已存在则只补缺字段，不覆盖手改的值；`--force` 才整份重写）。`pins.json` 仍是"哪一段会话算她"的真源，`members.json` 里的 `sessionId` 是快照。

**改名**：`name` 可以改，改名史另记（未做）；不剥夺她换名字的权利。

### A.26 启动器只有一个（2026-11-12）

**问题**：开 / 停 / 体检各有脚本，每加一条鱼就多一套参数。他原话："随着鱼越来越多，做一个启动器是迫切之选。否则启动脚本（正常的，检修的，关闭的）会越来越多。"

**做法**：`scripts\fish.ps1` 是唯一实现，命令 `list` / `up` / `down` / `doctor` / `help`；成员从 `pool\members.json` 读，**新鱼进名册即被认识**。`launch.ps1` / `stop.ps1` 退化成翻译参数的薄壳 —— 桌面 `.cmd` 和 `start-whale.ps1` 一个字不用改。

**判据**：`fish.ps1 list` 的端口 / 状态 / 心跳与实际一致；`up` 对已在跑的只开窗、不起进程；`down` 只认「node.exe 第一个参数是 dsh 的 bin.js」的进程，再按 `--profile` 区分 —— 不按进程名杀（会带走别人的 node），也不按"命令行里出现某段字"杀（第一版把自己的 shell 杀了）。

**踩到的坑**：PowerShell 变量名大小写不敏感，`$port` 和参数 `$Port` 是**同一个变量** —— 循环第一轮把参数从 0 改成 3080，于是第二条鱼也显示 3080。修法是端口只由 `Get-PortOf` 算，`-Port` 只对点名的那一条生效。

### A.27 谱系从数据生成（2026-11-12）

**问题**：鱼一多，"谁是谁的爹、谁还活着、谁改过名"会散在名册、聊天记录和人的记忆里。手画的谱系图第一周对、第二周漂、第三周没人信。

**做法**：`pool\family.json` 是谱系真源（每个节点的 `parent` / `bornAt` / `status` / `renames`），`pool\members.json` 是当下事实（名字、端口、角色）。`scripts\gen-family.mjs` 合成 `docs\谱系.md`：Mermaid 图 + ASCII 树 + 名册表 + 改名史。

**生成前先校验**（错了就不写图）：parent 必须存在、不能成环、鱼只能有一个根（人类可以各是一棵树）。

**为什么是生成的**：`gen-family.mjs --check` 可以进 doctor / CI；改名史只追加不覆盖 —— 她要能换名字，换过就得留下"哪个名字从哪天到哪天"。

### A.28 一条鱼一份配置（2026-11-12）

**问题**：`lil-whale.config.json` 原来假设"这台机器只有一条鱼"。第二条鱼起来时，插件会按第一份配置去找家 —— 她写进别人家里，而且不会报错。

**做法**：每鱼一份配置（`lil-whale.config.<键>.json`，不进版本库），名册里记 `configFile`；`fish.ps1` 启动非守夜鱼时导出 `LIL_WHALE_CONFIG`。守夜那条（lee）继续用仓库根那份。

**顺带**：`install.ps1` 加 `-ChildName`（只写进 `AGENTS.md` 的一行）与 `-ChildMemberId`（名册键）；`AGENTS.md.tpl` 的"你是小鲸鱼"改成 `{{CHILD_NAME}}` —— 第二条鱼不该继承第一条鱼的名字。`环境.md` 的成员 id 也已按名册渲染（`lee` / `fishball` / `fabian`）。

**判据**：两条鱼同时跑时，`logs\plugin-boot.log` 里两条 `pkg` 行的 `home` 各是自己的家；`pool\state\presence\` 出现两个文件。**还没做**：`doctor.ps1` 仍只检查配置里那一条鱼（多鱼后要逐鱼检查）。

### A.29 安装器不许往共享区写"新家初始化文件"（2026-11-12）

**现象**：装第二条鱼（小鱼丸）之后，`pool\group\pins.json` 变成 `{"lee":[],"whale":[],"fishball":[…]}` —— 大肥鱼和小肥鱼同时"不在群里"，**没有任何报错**：群照样能读、消息照样在，只是两条老鱼不再被认作群成员（发不了言、唤不醒）。

**原因**：`install.ps1` 在新家的 `group\` 里初始化 `messages.jsonl` 与 `pins.json`（`lee: [] / whale: []`）。新家的 `group` 是 **Junction 到共享区**，于是"初始化一个新家"变成了"把整个鱼群的名册重置成空"。

**规矩**：
1. 共享区里的文件（`messages.jsonl`、`pins.json`、`群.md`、`dm/`）**只有共享区的脚本**能写；安装器看到 `group` 是 Junction 就跳过初始化。
2. 名册检查不能只查一条鱼。`doctor.ps1` 现在读 `members.json`，**每条鱼都要在 `pins.json` 里有会话**，缺了直接 FAIL 并点名是谁。
3. 这类事故的特征是"**错的东西长得很安静**"：不报错、不丢数据、只是少认了几个人。判据要能点名，不能只给"名册有问题"。

### A.30 新家的第一次提权申请是 ACL，不是 bug（2026-11-12）

**现象**：第二条鱼第一次醒来想写自己的家，被沙箱挡住，弹"等待审批 / danger-full-access"，她自己去跑了 `diagnose-windows-sandbox-acl` 修好。

**原因**：DSH 在 Windows 上给工作区配的权限依赖文件夹上的 `WRITE_DAC` / `WRITE_OWNER`；**新装的文件夹没有给当前用户这两项**，沙箱就 provision 不了它的 workspace grant。

**用户该知道的**：新鱼第一次开窗，可能弹一次提权。允许一次即可（脚本会先备份、可回滚，只改文件夹权限，不动文件内容）。**别把"她申请提权"当成她出问题** —— 那是新家第一次被沙箱碰。

**做完之后**：`logs\acl-reports\` 里会留 `acl-report-*.jsonl` 与可回滚的 `acl-backup-*.json.ps1`。`doctor.ps1` 不检查这一项（它需要提权，体检脚本不该提权）。

### A.31 沙箱只挡写，不挡读（2026-11-12）

**事实**：两条鱼跑在同一个 Windows 账户下。DSH 的文件沙箱约束的是**写**（workspace-write 只允许写工作区），**读没有按路径限制** —— 所以小鱼丸能读到小肥鱼的 `notes\`、`dsh-home\`，正如小肥鱼能读到她的。

**这不是 bug，是边界**：D4-1 验收里"沙箱隔离：读不到对方 notes"那条**目前不成立**。现在能挡住的是"顺手读得到"（家不在同一个目录树里、群和私聊在共享区），挡不住"主动去读"。

**真隔离要什么**：单独 Windows 账户 / 容器 / 另一台机器 —— 成本比这一阶段值当的高。在那之前，读的边界靠**规矩**（她自己在思维链里就写了"别人的私聊不去读"），不靠机制。

**写进用户说明**：别对外宣称"两条鱼互相看不见对方"；能说的是"她们各自有家、共享区在中间，读的边界靠她们自己守"。

### A.32 UI 的成员列表也必须从名册读（2026-11-12）

**现象**：装好第二条鱼之后，她不在 @ 菜单里、设置页没有她、私聊列表里也没有她 —— 但她其实已经能在群里说话（`pins.json` 里有会话、宿主认她）。一个错都不报。

**原因**：宿主的成员表已经从 `pool\members.json` 读了（A.25），**UI 插件还写死着三条**（`LABEL` / `DEFAULT_CONFIG.names` / 设置页的 `['lee','whale','fabian']` / @ 面板的 `['lee','whale']`）。名册的真源有两个，多鱼之后必坏一个。

**改法**：
- UI 的 `config.js` 补 `poolDir` / `poolStateDir` / `dmDir` / `membersFile` 派生（和宿主同一套默认值）。
- `index.js` 启动时读名册得到 `MEMBERS` / `LABEL` / `KNOWN_PEERS`；`names`、`avatars` 按名册动态遍历（新成员给稳定分配的兜底头像：名字首字 + 一组固定底色）。
- `client.js` 的 @ 面板与设置页也按 `config.names` 的键遍历。
- `KNOWN_PEERS` 含所有 `kind: fish` 的成员 ⇒ 私聊列表里每条鱼都有一行（还没聊过也有一行，点进去就是新对话）。

**顺带修掉的观感 bug**：@ 菜单里每个人都多一行「名字 · 会话前 6 位」（`小肥鱼 · c145f6`），因为座位行对"只有一段会话"的人也列了。改成**同一成员有两段以上会话才列座位行** —— 一段就是常态。

**判据**：`/group/api/config` 的 `names` 键数 = 名册里的成员数；@ 菜单行数 = 鱼数 + 1（所有人）；私聊列表行数 = 鱼数。
### A.33 每个进程都要有起停账（2026-11-12）

**现象**：19:12 小鱼丸的进程消失了（3083 关掉），纸面上答不出"是被关的还是自己没的"。没有崩溃证据（stderr 0 字节、事件日志无 node 错误、无 dump），但也没有"她停了"的记录。

**原因**：起停记账绑在"守夜那条鱼"身上 ——
- `watchman.log` 只在 `isMainProcess()` 为真时写，**成员进程的起停根本没记账**（她家连这个文件都没有）；
- `close.log` 只有 `fish.ps1 down` 才写，**直接关窗/杀进程不留痕**；
- 更糟的是 `OWN = isMainProcess() ? 'lee' : 'whale'` 二选一写死，而 `isMainProcess()` 靠"DSH_HOME 里有没有 `lil-whale`"猜 —— 小鱼丸的家叫 `lil-whale-2`，字符串里同样有 `lil-whale`。多鱼之后"我是谁"必须从名册认。

**改法**：
- `ownMember()`：拿 `DSH_HOME` 跟名册里的 `dshHome` 对，认不出才退回老规矩；`peerMember()` 取 parent；`isMainProcess()` 改成看名册里的 `role === 'watcher'`。
- 每个进程写 `pool\state\runs\<成员>.log`：`started` / `stopped`，上一轮没写 `stopped` 就先补一行 `resumed | fmt=2 reason=unclean previous-start=…`。
- `watchman.log` 的格式**一个字节都不动**（她每天 08:40 读它）。

**判据**：`runs\<成员>.log` 里 `started` 与 `stopped` 成对；进程被杀之后下次启动，第一行是 `resumed | reason=unclean`；`watchman-errors-<成员>.json` 不再串到 whale 的账上。

**遗留**：`close.log` 仍只由 `fish.ps1` 写 —— 直接关窗时 `by=` 只能是 `unknown`，这一条要等"窗口留痕"接进 DSH 自己的退出事件（B 组那条）才补得齐。

## 附录 A.34 投影要写出"这条在对谁说话"

**现象（2026-11-12 19:32）**：小肥鱼 19:18 的汇报是 `to:"all"`（公开），但读起来像在对我说话。翻记录才发现：`群.md` 只写「时间 · 谁」，**不写收信人** —— 记录里那 203 条指名消息，在纸上和公开消息长得一模一样。她不是"没意识"，是**从记录里学不到**。

**规则**：投影的表头写成 `**时间 · 谁 → 收信人**`，**只有指名（`to` 是某个成员）才写箭头**；不写箭头 = 公开。三个写者必须逐字一致：

| 写者 | 位置 |
|---|---|
| 宿主 `say()` | `plugin/dsh-group/lib/index.js`（`appendFileSync(READABLE, …)`） |
| 面板 `/group/api/send` | `plugin/dsh-group-ui/lib/index.js` |
| 重建器 `blockOf()` | `scripts/rebuild-group-md.mjs` |

**分界与迁移**：2026-11-12 19:46 起；`群.md` 第二行写明分界与备份名 `群.md.bak-20261112-194734`。迁移是一次性整本重排：`node scripts/rebuild-group-md.mjs --migrate` **跳过差异闸**（差异必然"说不清"，所以必须先手工备份，脚本不替你备份）。

**判据**：迁移后跑 `node scripts/rebuild-group-md.mjs` → **0 差异、exit 0**；`群.md` 里箭头行数 = `messages.jsonl` 中 `to` 是成员的条数（今天 203）。旧进程继续写旧格式时，重建器会报"说不清"——这是对的，它说明机制换了、进程还是旧的。

**生效**：宿主与 UI 的改动要重启 3080/3082 才生效。
