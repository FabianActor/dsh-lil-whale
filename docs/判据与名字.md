# 判据与名字

> 这份文件收的是**判据怎么写、名字怎么起**这一层规矩。不是产品需求（那在 PRD 里），是工程判断的尺子。
> 来源：2026-11-11 一天里连续踩出来的坑，多数由小肥鱼从日志里翻出来，大肥鱼补充。凡是她先说的，标「小肥鱼」。
> 用法：写一条日志、一个字段、一个文件名之前看一眼；出事故之后回来补一条。

## 一、总纲

**一个判据不合格的标志，是它错的时候跟它对的时候长得一样。**（小肥鱼）

推论分两半用：

- **上线前想一次**："它错了会长什么样？"想不出来就先上线——别把一个想不出失败形态的检查当闸。
- **出错之后必须补一次**：如果事故已经发生、判据却没拦住，说明它缺了一维，补上。

## 二、名字

### 2.1 三类会撒谎的名字

| 类别 | 例子 | 它断言什么 | 缺什么会变假 |
|---|---|---|---|
| **量词** | `total` / `all` / `never` / `always` | 整体 | 缺"谁的整体" |
| **状态词** | `ok` / `done` / `success` | 结果 | 缺判据（`ok` 后面不跟依据，什么都没说） |
| **相对词** | `first` / `prev` / `last` / `next` | 位置 | 缺参照系 |

**最小的尺子（小肥鱼）：写下任何一个名字时问一句「它和什么比？」** 答不上来，就是上面某一类缺了东西。

不在这三类里的名字（`cursor.json`、`wake-plan.json`）只是标签，不用证伪。

### 2.2 删掉法：判断它是断言还是标签

删掉它，有没有人读到的东西变少？变了是断言，没变是标签。

**但这个测试有个陷阱（小肥鱼）**："没变"有两种原因，长得一模一样：

- 它是标签（没人在乎）
- 它是**死的**（本来就没人读）

所以要跟第二问，而且**不能靠想，只能去 grep**：**现在有人读它吗？**

### 2.3 状态词必须紧挨着判据

`woke ok` 里的 `ok`，如果不跟着 `why=port-open`，它什么都没说。**判据离开名字，名字就只是安慰。**

## 三、名字的期限

**名字记的是写它时的世界，读数的人拿到的是读它时的世界。** 两者不一致时，错的不是名字，是没人在世界变化时回头改它。

今天的具体案子：`errors_total` 只有一个写者的下午是真的；第二个进程起来之后，它变成"最后写的人的数"。世界变了七个小时，名字没人改。

**体检不按日期做，按事件做。** 每次世界变动（加进程、多一把椅子、开一条渠道），在**那次改动的记录里**加一行：

```
受影响的名字：errors_total（现在是谁后写算谁）
```

不另建清单——写在改动记录里，跟着那次改动走。

## 四、存与算

**能算出来的，就不该被存下来。** 存下来的都是"上一次算的"，而"上一次"是谁的上一次，可能又说不清。

- 分账（每人/每进程一份）是对的
- 但账分了之后，**"更粗的问题"的答案必须是查询，不是字段**（小肥鱼）——再加一个 `errors_all` 就是把同一个坑换个名字再跳一次
- 查询要有**窗口定义**，窗口是定义的一部分，不是实现细节

## 五、窗口

**窗口要钉在事件上，不钉在状态上。** 事件是既成事实，改不了；状态是每时每刻的当前值，谁后写算谁。

例：`state\watchman.json` 里的 `day` 是状态；日志里 `... | note | why=new-day counter-reset` 那行是事件。**"今天"= 最后一条 `new-day` 之后。**

**最好的窗口定义，是根本不需要定义**（小肥鱼）——按天切文件之后，文件名就是窗口。真要切的时候，别按"文件太大"切，按"我想让窗口变成文件名"切。
（代价：跨文件的问题又需要一个新定义，所以切的粒度要跟问题的粒度对齐。）

## 六、"不可答"不是一种状态，是三种（小肥鱼）

| 不可答的原因 | 该做什么 | 留下的证据 |
|---|---|---|
| **口径未定义**（"错"指什么） | 改问题 | 有埋点的名字，但没有口径 |
| **没记**（没人埋点） | 补埋点 | 连名字都没有 |
| **记了但丢了**（硬切、被覆盖） | 修耐久性 | 有过数，现在断档 |

三者留下的痕迹不同 ⇒ 可以按证据分，不用猜。只写"不可答"，下一个人会一律当成第一种，然后一路改问题——**而第二、三种，改问题没有用。**

## 七、改写问题必须留原问法

把"今天错了几次"改写成"今天记了几条 error"是对的，但危险在于：**改写做得很顺，下一个人会以为原问题被回答了。**

所以与被改写后的数字并排放两行：

```
原问法：今天错了几次 —— 不可答（口径未定义）
可答问法：今天记了几条 error = 日志 error 行数，窗口 = 最后一条 new-day 之后
```

这和 `pre-mortem` 是同一个位置问题：**"改过了"和"没问过"在纸上长得一样。**

## 八、留痕的位置

**留痕按"谁会撞上它"来选，不按"哪里方便写"来选。**

- `pre-mortem` 写在判据旁边（未来判定"算不算没想过"的人只会看判据）
- 清锁记录要写进**新的锁文件**（被清的人不会去查日志，他只会撞上锁）
- `affected names` 写进 commit 正文（看改动的人会看那里）

## 九、造失败要用真料，且自带身份

- 构造数据造出来的失败，和真故障长得一样 ⇒ 造的时候用真料
- **能用的假，必须自己说是假的**（`dry-run` 标记、自己目录、日志明写）

例：`why:'自检：验"主机开着、她关着窗"这条路径（跑完就删，不是给你的安排）'`——小肥鱼认这是正面样本：自带身份、自带到期、跑完自己消失。

## 十、物理层的一个同族案子（`lost update`）

同一个文件、两个写者、都"读整份→改一格→写整份" ⇒ 后写的盖掉先写的。
**两个写者要么分片（各写各的），要么只追加。** 进程能被观测（`pid` + 启动时刻），会话不能被观测（只能心跳 + 单调伴生量）。
**易变量必须配单调伴生量**（`beat` 配 `step`、`pid` 配启动时刻、`exit=0` 配端口通不通）；而 `step` 不能由心跳自己 +1，必须由"事情"推进。

## 十一、切分能造出一个断言（小肥鱼，2026-11-11）

按天切日志之后，`watchman-2026-11-11.log` 里**只该有 11-11 的行** ⇒ "文件名与内容一致"变成一条能自动验的断言：某天文件里冒出别的日期，本身就是 bug 信号，不用人记得去查。

**切分不只是省事，它把一条隐含约定变成了可验证的断言。** 同族的第二件事：`rev` 把"谁先写"变成可验，切分把"哪天的"变成可验。

代价照旧要记：切到天就只能回答"某天"，回答"总量"得回到扫全部文件——**窗口没有消失，它从参数变成了文件集合**，所以切的粒度要跟问题的粒度对齐。

## 十二、规则自己要带证据（小肥鱼，2026-11-11）

这份文件是**源头**（不可重建、只能人维护），比结论更容易烂——它会跟实践脱节，最后变成一份"信念文件"。

所以每条规则后面必须跟一句：**它在哪件事上验过一次**（日期 + 日志行 + 当时错的样子）。

> **没有事故的规则，可能是想象出来的规则。**
> **用一条没有事故的规则，等于用一个没验过的判据。**

证据索引（缺的一栏标「未验」）：

| 规则 | 验过它的那件事 |
|---|---|
| 总纲：错的时候跟对的时候长得一样 | 2026-11-11 `gap=first`：读作"从头开始"，实际是"尾部 4KB 全是 error，看不见上一行正常记录" |
| 量词缺整体 | `errors_total=611` 而 error 行 1225 条——611 是最后写它的进程的数 |
| 状态词缺判据 | 2026-11-09 推门四轮：`exit=0` / `already-awake` 都不代表门真的开了 |
| 相对词缺参照系 | 2026-11-11 `gap=first`：缺的是"相对于谁"（"同上"本身就是个缺参照系的相对词——这行原来就是它自己的现场演示） |
| 删掉法两种失败 | 2026-11-11 我对 `ui-read.json` 凭印象说"是标签"，grep 完发现它被读被写、是断言 |
| 名字的期限 | `errors_total` 单写者时是真的，第二个进程起来后变假，中间隔了七个小时 |
| 存不如算 | 611（存下来的）vs `grep -c '\| error \|'` = 1225（算出来的） |
| 窗口钉事件 | `new-day counter-reset` 每天恰好一行（11-10 00:00:28、11-11 00:00:44） |
| 不可答分三种 | "今天错了几次"=口径未定义；EPERM 1225 行=记了（有痕迹）；**记了但丢了**=游标 108 被另一进程整本写回成 107、或 `errors_total` 曾经存在后来成了别人的数 |
| 改写留原问法 | 同上（把"错几次"改写成"几条 error"那次） |
| 留痕按谁会撞上 | 清锁记录写在新锁文件里（撞锁的人不查日志）；`pre-mortem` 写在判据旁 |
| 造失败要真料 + 自带身份 | 2026-11-11 19:59 `selftest-wake` 演练：`why` 写明"自检、跑完就删、不是给你的安排" |
| `lost update` | 2026-11-11 11:02–17:51 EPERM 1225 行 + 她报"同一条消息叫醒两次" |
| **体检按事件做** | **等着被验** —— 触发条件：下一次世界变动（加进程 / 加椅子 / 开一条渠道）时 |
| **切分造断言** | **等着被验** —— 触发条件：日志大到要按天切的那天 |

## 十三、回读的判据是"差多少"，不是"看起来对"（小肥鱼，2026-11-11）

"改完回读一遍"是对的，但回读需要一个**期望值**，否则它只是"再看一眼"。残骸落在文件尾能被发现，是因为读到了不该有的东西；**落在中段、内容又通顺，一眼扫过去就看不见了——再看一眼，很容易看见你想看见的。**

所以判据是：**改之前记下长度 / 行数，改之后比差值。** 说"删了一段、加了一段"，就该有个预期的增减；差得多出来，就是残骸。

> **改动的判据不是"看起来对"，是"差多少"。** 预期差能被证伪，"看起来对"不能。

## 十四、规则被推翻时怎么留（小肥鱼指出缺的一节，2026-11-11）

这份文档有"名字的期限"（名字会过期），有"规则要带证据"（规则要验过），但原来缺一条：**一条规则被证伪了之后怎么留。**

今天的两次推翻，都不是补充：

| 旧的 | 被谁取代 | 为什么 |
|---|---|---|
| `prev`（存"上一条"） | `rev` + `sha` + CAS | 存下来的"上一条"会自己长成一条链，而且没法和"读到的是不是同一版"对上 |
| "一个人两本账"（两把椅子并立） | 一把椅子、一本账 | 一个人在另一把椅子上说过的话就可以不算数了吗——不能，所以椅子本身就是那道缝 |

**做法：规则作废时保留原文、标「已作废」、写清被哪条取代、为什么。不要删掉重写。**

理由跟当初留 `watchman.log.dryrun-3099` 那个文件一样：**删掉之后"当初为什么会错"就断了**，而下一个人会重新踩一遍。这份文档是**源头**（不可重建），删掉的东西没有备份。

格式：

```
> ~~原规则~~
> **已作废（2026-11-11）：** 被「新规则」取代。
> 原因：……
```

**判断"这是推翻还是补充"的问法：** 如果按旧规则做出来的东西现在必须改，那是推翻；如果旧规则还能继续用、只是多一条，那是补充。推翻要留痕，补充直接加。
