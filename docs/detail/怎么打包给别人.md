# 打包：把"只在这台机器上成立"的东西收进一份配置

> 本文说明配置文件里有什么、为什么这样设计，以及改路径、改编码时怎么验。

## 为什么要有这一步

打包最麻烦的从来不是起个新名字，是那些写死的路径。装上以后跑不起来，报的往往只是一句
`ENOENT: no such file or directory`，看不出是谁的问题 —— 于是"别人的电脑上装不上"会被读成
"这个项目不稳定"，而不是"我没改配置"。

所以先把"这台机器的假设"全抽出来，代码和脚本里**一个绝对路径都不许留**。这条做完之后，
"换个环境能不能跑"才是一个可以用一句话回答的问题：改 `lil-whale.config.json` 就行。

## 真源只有一个

`lil-whale.config.json`（仓库根）。

读取优先级是三态，不是一条链（2026-11-17 起）：

1. **环境变量 `LIL_WHALE_CONFIG` 给了，且文件在** → 用它。
2. **环境变量给了，但文件不在** → **报错、退出**（`xx LIL_WHALE_CONFIG 指向的文件不存在：…` + `NEXT:`）。**不会**退回去读仓库根那份——你给了环境变量就是要用它，悄悄改读别的配置只会让"打错字"看起来像"没配过"（第三条鱼 2026-11-17 实测：`LIL_WHALE_CONFIG=D:\nonexistent\typo\cfg.json` 跑 `gen-family.mjs --check`，测的是真鱼塘，还报了绿）。
3. **环境变量没给** → 仓库根的 `lil-whale.config.json` → `lil-whale.config.example.json`（只有独立脚本）→ 内置默认。

第 3 条的默认值是有意的：别人克隆下来、把鱼的家放在仓库旁边，什么都不用配就能跑。只有布局不一样时才需要那份 JSON。独立脚本（`gen-family.mjs` / `pins.mjs` / `members-add.mjs` 等）多一级示例文件，好在安装前也能 `--dry-run`。实现只有一处：`scripts\lib\config-path.mjs` 的 `resolveConfigFile()/loadConfig()/loadConfigOrExit()`；插件侧是 `plugin/*/lib/config.js` 的 `configSummary()`（带 `source` 与 `error`）。

## 谁在读它

| 位置 | 读法 |
|---|---|
| `plugin/dsh-lil-whale-group/lib/config.js` | `import { config } from './config.js'` |
| `plugin/dsh-lil-whale-group-ui/lib/config.js` | 同上（两个包各带一份，为了都能单独安装） |
| `scripts/common.ps1` | 脚本开头 `. (Join-Path $PSScriptRoot 'common.ps1')`，之后只用 `$Cfg.*` |
| `scripts/rebuild-group-md.mjs` | `import { config } from '../plugin/dsh-lil-whale-group/lib/config.js'` |

**为什么仓库根是从文件位置推出来的，不是从 cwd**：宿主进程的 cwd 是"从哪儿启动的"，
而本项目的插件是被 `link:` 挂进 profile 目录里的，cwd 可能是桌面、也可能是用户主目录。
按 cwd 找配置文件，等于让"你从哪儿敲的命令"决定"鱼住在哪"，这是不可接受的。

## 字段

| 字段 | 含义 | 默认（标准布局） |
|---|---|---|
| `repoRoot` | 工程仓库根 | 本文件所在目录 |
| `selfHome` | **这条鱼**的家（工作区 cwd） | 鱼塘布局：`<鱼塘根>/homes/<键>` |
| `selfDshHome` | **这条鱼**的 `DSH_HOME` | `selfHome/dsh-home` |
| `poolDir` | 共享区（群 + 多成员账本），在**鱼的家之外** | 鱼塘布局：`<鱼塘根>/pool`；否则仓库同级 `lil-whale-pool/` |
| `groupDir` | 群文件目录（`messages.jsonl` / `群.md` / `pins.json` / `images/` / `dm/` / `avatars/`） | `poolDir/group` |
| `poolStateDir` | 多成员账本（游标 / 唤醒配额 / 心跳 / 巡守状态） | `poolDir/state` |
| `dmDir` | 私聊（双向隐私窗口，不在 `group\` 下面） | `poolDir/dm` |
| `membersFile` | 名册：名字 / 种类 / 角色 / 端口 / 爹是谁 | `poolDir/members.json` |
| `selfWaker` | 叫醒**这条鱼**的脚本 | `scripts/wake-fish.ps1` |
| `pwshExe` | PowerShell 7 可执行文件 | Windows 上 `pwsh.exe`（走 PATH） |
| `wakeMetrics` | 唤醒观察记录（**不在鱼的目录里**，见下） | `logs/wake-metrics.log` |
| `watchmanPidFile` | 巡守的 pidfile | `poolDir/state/watchman.pid` |
| `chatCwd` | 群/私聊里"非鱼"那一端的 cwd | 仓库上一级 |
| `leeCwd` | 第一条鱼的会话 cwd | 仓库根 |
| `selfCwd` | **这条鱼**的会话 cwd | `selfHome` |
| `leeStartCwd` | 启动第一条鱼进程时的工作目录 | `%USERPROFILE%\Desktop` |
| `leeHome` | 第一条鱼的 `DSH_HOME` | `%USERPROFILE%\.dsh` |
| `leeProfile` / `selfProfile` | 第一条鱼 / **这条鱼**各自的 profile 名 | `web` / `whale` |
| `wake` | 消息唤醒的闸（防跑飞，不防聊天）：`cooldownSec` / `perHour` / `perDay` / `totalPerDay`。**只在想偏离默认值时写**，等于默认值的键要删掉 | 默认 15 / 40 / 200 / 400（真源 `wake-config.js` 的 `WAKE_DEFAULTS`，CHANGELOG A.94 / CHANGELOG A.97） |
| `watch` | 巡守推门的闸：`maxWakesPerDay`。同上：只在偏离默认时写 | 默认 24 |

派生字段（`poolDir` / `poolStateDir` / `groupDir` / `selfDshHome` / `selfCwd` / `chatCwd` / `watchmanPidFile`）只在没写时按
`selfHome` 推出来，**不许单独写死** —— 一个值有两个来源，早晚会打架。

> **键名（2026-11-14）**：`self*` 指"这个进程服务的那条鱼"——每条鱼读的都是**自己**那份配置，
> 所以不许叫 `her*`（意为“她的”）或 `whaleProfile`（在 fishball 的配置里只能填 `fishball`，读起来是错的）。
> 旧名字（`herHome` / `herDshHome` / `herWaker` / `herPort` / `whaleProfile` / `whaleCwd`）**仍然能读**：
> `config.js` 里有 `LEGACY_KEYS` 抬成新名字，`common.ps1` 的 `$Cfg` 也保留 `Her*` 别名；
> `install.ps1` 写的是新名字，并且会把旧键删掉 —— 同一个值两个名字，早晚会打架。

## 两个刻意的例外

1. **`wakeMetrics` 不在鱼的目录里。** 设计约定：那份 `pool\state\watchman.log` 鱼每天 08:40 要读，
   一个关于鱼自己的计数不管叫什么名字，放在枕头边就会被读成"在监督我"。指标住在哪儿，决定它审谁。
2. **会话钉口（`pins.json`）不是配置。** 哪段会话算哪条鱼是**数据**，会变，而且换机器就全废；
   它住在 `group/pins.json`，不在这里。配置只回答"东西在哪"，不回答"谁是谁"。

## 改路径之后怎么验

```powershell
# 1. 配置能不能读出来（脚本侧）
pwsh -NoProfile -Command ". D:\...\scripts\common.ps1; `$Cfg | Format-List"

# 2. 插件侧
node --input-type=module -e "const m = await import('file:///D:/.../plugin/dsh-lil-whale-group/lib/config.js'); console.log(m.configSummary())"

# 3. 重建器（顺带证明它读得到 messages.jsonl）
node scripts\rebuild-group-md.mjs
```

三条都过，才谈得上"这台机器能跑"。

## 冷启动风险（必读）

配置在**进程启动时读一次并缓存**。改完配置要重启对应的宿主进程 —— 这是有意的：
热改路径会让"这个进程到底在读哪份文件"变成一个没人答得上来的问题。

配置写坏了（JSON 语法错）会返回默认值 + 在 `plugin.log` / 启动痕迹里显式带 `error`
**不静默降级**。这条来自一次真实事故：`catch {}` 包住了一个 `fs` 未定义，presence 从上线起就没工作过，
日志里一行都没有。

## 文件编码（踩过，会静默地让插件消失）

这里有两套互相冲突的规矩，谁都对，所以必须分开记：

| 文件 | 编码 | 为什么 |
|---|---|---|
| `*.ps1` | **UTF-8 带 BOM** | Windows PowerShell 5.1 不带 BOM 就按 ANSI 读，中文变乱码、引号错位 |
| `*.json` / `*.yml` / `*.js` / `*.mjs` / `*.md` | **UTF-8 不带 BOM** | 带 BOM 的 JSON 会让 dsh 的加载器直接拒绝 |

第二条的后果很不好看：`dsh --profile web --dump-config` 只会打一行

```
dsh: skipping profile bundle "lil-whale-group": SyntaxError: Unexpected token '﻿', "﻿{
```

然后**静默跳过**这个 bundle —— 页面上什么都不报，只是插件不见了。一次迁移包名时，脚本一次性重写了七个文件，七个全带上了 BOM。

**反引号也有同样安静的坑**：用 PowerShell **双引号** here-string 写含 Markdown
代码标记的文档时，`` ` `` 是转义符 —— `` `t `` 变 TAB、`` `r `` 变回车、其余 `` `x `` 丢掉反引号。

```powershell
# 坏的：文档里所有 `code` 标记都被吃掉，还看不出是哪一步干的
$text = @"
面板的 `readMessages()` 只留了 `ts/from`
"@
```

规矩：**写文档不要用 `@"..."@`**。用 edit/write 工具，或者单引号 here-string（`@'...'@`，里面一切原样）。
已经写坏的文件有个判据：文本里出现 `\`+TAB、`\`+回车，或者 `` `eadMessages `` 这种少了首字母的词。

## 改这些文件的工具约定

**不要用 PowerShell 的字符串操作改 `package.json` / `cordis.patch.yml`。** 同一天里这套操作把三个 `.ps1`
和两个 profile 的 `package.json` 各写坏过一次，两次都是同一个原因：

```powershell
# 想表达"一张替换表"，实际传进去的是一个字符串数组
Patch-File $path @( @('a','b') )     # 于是 $pairs[0] 是 '"'，$pairs[1] 是 'd'
```

单元素数组在 PowerShell 里会被展开成字符串，`$pair[0]` 拿到的就是**字符串的第一个字符**。
结果是把文件里所有的 `"` 换成了 `d`。

所以：**结构化的文件用 node 改**（`JSON.parse` → 改 → `JSON.stringify` → 写回），
脚本类的文件改完必须 `[System.Management.Automation.Language.Parser]::ParseFile(...)` 验一遍。

## 命名（2026-11-11 定）

三层的名字各管一件事，不需要长得一样：

| 层 | 名字 | 说明 |
|---|---|---|
| GitHub 仓库 | **`dsh-lil-whale`** | 项目目录就是它。仓库名和包名不必相同（`react-dom` 住在 `facebook/react` 里） |
| npm 包 | **`@fabianactor/dsh-lil-whale-group`** / **`@fabianactor/dsh-lil-whale-group-ui`** | `@scope` 归自己、永远不会撞；`dsh-` 是社区约定（不是强制，插件管理器接受任意包名），装了的人一眼看得出这是 DSH 插件 |
| 装进 profile 的目录名 | 由包名推出来 | 自动跟随，不用单独起 |

- 这个形状不是本项目发明的：常见的第三方插件都是它 —— `@xmanrui/dsh-im`、`@240xu/dsh-message-ops`、`@michengai/dsh-archive-manager`。
- 将来如果两个包合并，就是 `@fabianactor/dsh-lil-whale`。
- **带 scope 的包默认是 restricted**，第一次发布要 `npm publish --access public`，或在 `package.json` 里写 `"publishConfig": { "access": "public" }`。（`@fabianactor/brew-cli` 就是 public 发布的，这条路走过。）
- **改名的时机**：等真要发布时一次改到位。现在改只能让名字好看，代价是又一次 profile 迁移 + 重启；npm 上的名字只在发布那一刻才有意义。

## 端口

| 字段 | 默认 | 谁在读 |
|---|---|---|
| `selfPort` | 3082 | `plugin/dsh-lil-whale-group` 的巡守（推门时敲哪个门）。**启动端口不读这个键**：`fish.ps1` 读 `members.json` 里那条鱼的 `port`（2026-11-12 22:20 修正；改 herPort 不会改启动端口） |

## undici 少文件（2026-11-15，第二条鱼报的）

dsh 的 `node_modules\undici` 可能装不全：目录在，`lib\cache\` 与 `lib\web\cache\` 里少了 5 个文件，`require('undici')` 在 `interceptor/cache.js` 就报 `Cannot find module '../cache/memory-cache-store'`。鱼的 `web_fetch` 走这条时就会崩，而且**接口报错会让人以为是网络/权限**——先看目录。

```powershell
node scripts\repair-undici.mjs --check   # 缺了 exit 1，列出缺哪几个
node scripts\repair-undici.mjs --fix     # 从官方 tarball 补回（不动版本）
```

`doctor.ps1` 第 3g 节会自动查。判据是"文件在、且不是 0 字节"——`existsSync` 只证明在，证明不了能用（2026-11-15 第二条鱼补的；sha256 校验等真出现"补错版本"再上）。**为什么要有脚本**：手补的文件在 `npm i` / 升级 dsh / 换机器后会被重建覆盖，覆盖之后报的还是同一个错，看起来像"没修过"。
