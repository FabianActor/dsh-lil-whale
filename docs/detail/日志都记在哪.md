# 日志与账本：谁写、记在哪、按哪一版读

> **用途**：出问题时要看日志。这一页登记每本账**谁写、用哪种钟、`fmt=` 各版本是什么意思**——照着读，才不会把时间读错八小时、把两个进程的数当成一个数。第一次排查先看最后「读账的顺序」。

## 一条总规矩

- **没有 `fmt` 字段的行，按 `fmt=1` 读**。缺省值必须写死在一处，否则读的人只能把所有历史行扔进一个"未知"桶。
- **每本账自己数自己的 `fmt`**，不要跨账本比版本号。
- **缺省值必须写死，而且只写在一处**：`fmt` 缺失 = 1；名册 / 谱系的 `lifecycle` 缺失 = `active`（2026-11-15 起，此前不存在归档状态）。`doctor.ps1` 见到缺字段会报一次。
- **时间一律本地时间**（`Asia/Shanghai`）。唯一例外是 `roster-audit.log` 的早期行，见下表。
- 行格式统一：`<时间> | <事件> | <字段…>`；`fmt=` 紧跟事件名。
- **格式有版本，规则才有分界**：`why=` 只出现在 **2026-11-15 18:35 之前**的行；之后的没叫醒原因一律看 `deny=`、观察看 `note=`、细分看 `reason=`。`watchman.log` 里每条 `log-format | fmt=3 since=…` 之后的行按新格式读（这一行就是分界；读到它之前的行，`why=` 照旧有效）。
- **一行里同一个 key 只出现一次**，而且**事件名不进字段**。`skip` / `wake-skip` 行里，没叫醒/没递的原因一律用 `deny=<原因>`；观察、异常用 `note=<类别>`；同一件事需要再细一层时用 `reason=`（例如 `note=intent-path-rejected id=X reason=<为什么被拒>`）。反例（2026-11-15 18:56 第二条鱼抓到）：`skip | to=whale why=wake-skip why=intent-cooldown` —— 两个 `why=`，读者取到哪个取决于解析器，而且事件名塞进了原因位。

反例（这一页就是为了它才有的）：`roster-audit.log` 里同时躺着 UTC 的 `fmt=1` 行和本地的 `fmt=2` 行。只看文件的人会把同一件事读成隔了八小时，而且看不出哪行是哪版。

## 字段级版本

**"每本账自己数自己的 `fmt`"只够描述整行。** `watchman.log` 里已经出现两种版本轴并存：

- 行级：`started` / `resumed` / `stopped` 从 `fmt=2` 起才有 `prev-run` / `gap` / `errors_today_*`；
- 字段级：`wake-try` 行的 `at=` 到 **1.5.4** 才从 UTC 改成本地。

所以同一行可能是"`fmt=2` 的行 + `fmt=1` 的 `at=`"——按整行版本读时间，仍会差八小时。

**规矩：版本号贴着它管的东西。** 字段自己带版本，字段一改语义就加一个：

- `wake-try` 行：`at=` 后面跟 `atfmt=2`；
- `wake-deliver.log` 的投递行：`tpl=` / `tail=` 自 2026-11-15 21:2x 起才有，之前只能靠会话里的原话核对；
- `wake-deliver.log` 行里的 `cursor` = 写完这一行时文件的行数（**投递后**），`prior-cursor` = 这次投递开始前的游标；两者都**不表示"她读到哪"**——她直接读文件不推进游标（2026-11-15 22:3x 澄清）。
- 跨账比先后时，两边都取**事件时间**：回复的 `ts` 对投递的 `ts`，不要拿某条账里"事后的游标"当"当时的状态"（2026-11-15 22:3x，第三条鱼认错那条）。
- doctor 的「出生账」行（r148 起）字段按判据命名：`due-after-since`（该有）、`missing-after-since`（缺的）、`on-ledger`（账上实际几条）、`before-since` / `before-since-on-ledger`（早于 since 的不算欠，但要数）、`undecidable-same-day`（同日、日期精度判不了）。
- `births.log` 的 `log-format` 行由宿主追加；`doctor` 的「出生账」把口径写成机器可读：`since=` / `expected=` / `present=` / `missing=` / `missing-keys=` / `prior=` / `prior-keys=` / `undecidable=`（同日出生、日期精度分不清先后，不进 expected）。
- `tpl` / `tail` 自 2026-11-15 21:4x 起带 `@N` 版本（改文案必须 +1）；`wtext8` / `pkg` 同一次加上 —— 有这三样，才能拿同一版代码重算出同一句话；
- **没有 `atfmt` 字段的 `at=`，按 `atfmt=1` 读（UTC）**；
- 以后再有字段改语义，照这个写法加 `<字段名>fmt=N`，并在本页登记一行。

> 原话：**版本号贴着它管的东西，才不会串。**

## 读账的顺序

1. 先看 `fmt`，再决定怎么读时间与字段。
2. `wake-try` 与 `woke` 用同一个 `wid` 能对上；`trigger=plan|intent|external` 说明是谁叫的。
3. `at=` 是"事情发生的时刻"，`lag=` 是"发现 / 递送比发生晚了多少"——两者不是一回事。
4. `at=` 的钟看它自己的 `atfmt`：有 `atfmt=2` 是本地，没有就是 `atfmt=1`（UTC）。
