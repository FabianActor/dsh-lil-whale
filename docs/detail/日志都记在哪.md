# 日志与账本：谁写、记在哪、按哪一版读

> **用途**：出问题时要看日志。这一页登记每本账**谁写、用哪种钟、`fmt=` 各版本是什么意思**——照着读，才不会把时间读错八小时、把两个进程的数当成一个数。第一次排查先看最后「读账的顺序」。

## 一条总规矩

- **没有 `fmt` 字段的行，按 `fmt=1` 读**。缺省值必须写死在一处，否则读的人只能把所有历史行扔进一个"未知"桶。
- **每本账自己数自己的 `fmt`**，不要跨账本比版本号。
- **缺省值必须写死，而且只写在一处**：`fmt` 缺失 = 1；名册 / 谱系的 `lifecycle` 缺失 = `active`（2026-11-15 起，此前不存在归档状态）。`doctor.ps1` 见到缺字段会报一次。
- **时间一律本地时间**（`Asia/Shanghai`）。唯一例外是 `roster-audit.log` 的早期行，见下表。
- 行格式统一：`<时间> | <事件> | <字段…>`；`fmt=` 紧跟事件名。
- **格式有版本，规则才有分界**：`why=` 只出现在 **2026-11-15 18:35 之前**的行；之后的没叫醒原因一律看 `deny=`、观察看 `note=`、细分看 `reason=`。**例外窗口**：2026-11-15 18:35 – 2026-11-16 08:2x 之间，代码里仍有 31 处写者写 `why=`（分界行写了 `fields=`，但写者没跟上；r179 补齐）。读到这段窗口里的行，两种字段都可能出现，按语义读、不按字段名猜。`watchman.log` 里每条 `log-format | fmt=3 since=…` 之后的行按新格式读（这一行就是分界；读到它之前的行，`why=` 照旧有效）。 2026-11-16 起这一行末尾还带 `pid=` 与 `to=`：谁写的、写给哪个成员；旧行没有这两个字段，**不能拿它们反推写者**（判据 §37）。 轮转会把当前 `watchman.log` 改名成 `watchman.<时间戳>.log`；新文件开头没有这一行是轮转的正常样子，`doctor` 9c 会去最近轮转的旧文件里找同一行（2026-11-16，r169）。
- **一行里同一个 key 只出现一次**，而且**事件名不进字段**。`skip` / `wake-skip` 行里，没叫醒/没递的原因一律用 `deny=<原因>`；观察、异常用 `note=<类别>`；同一件事需要再细一层时用 `reason=`（例如 `note=intent-path-rejected id=X reason=<为什么被拒>`）。反例（2026-11-15 18:56 第二条鱼抓到）：`skip | to=whale why=wake-skip why=intent-cooldown` —— 两个 `why=`，读者取到哪个取决于解析器，而且事件名塞进了原因位。

- **账本里的每个字节都要能被印出来**（2026-11-17，第四条鱼 #1014）：正文里的 C0 控制字符（除换行）与 DEL 在写盘前换成可见占位 `<0xNN>`。做这件事的是 `say()` / `sayPrivate()` 与 `scripts\post-group.mjs`，`scripts\test-ledger-text.mjs` 守。反例：一条群消息里的 `` `b `` 被 PowerShell 双引号 here-string 当成退格（0x08），`bundles=` 落盘成 `undles=`——**合法字符串，按字段读不会报错**。

反例（这一页就是为了它才有的）：`roster-audit.log` 里同时躺着 UTC 的 `fmt=1` 行和本地的 `fmt=2` 行。只看文件的人会把同一件事读成隔了八小时，而且看不出哪行是哪版。

## 字段级版本

**"每本账自己数自己的 `fmt`"只够描述整行。** `watchman.log` 里已经出现两种版本轴并存：

- 行级：`started` / `resumed` / `stopped` 从 `fmt=2` 起才有 `prev-run` / `gap` / `errors_today_*`；
- 字段级：`wake-try` 行的 `at=` 到 **1.5.4** 才从 UTC 改成本地。

所以同一行可能是"`fmt=2` 的行 + `fmt=1` 的 `at=`"——按整行版本读时间，仍会差八小时。

**规矩：版本号贴着它管的东西。** 字段自己带版本，字段一改语义就加一个：

- `wake-try` 行：`at=` 后面跟 `atfmt=2`；
- `wake-deliver.log` 的投递行：`tpl=` / `tail=` 自 2026-11-15 21:2x 起才有，之前只能靠会话里的原话核对；
- `wake-deliver.log` 行里的 `cursor` = 写完这一行时文件的行数（**投递后**），`prior-cursor` = 这次投递开始前的游标；两者都**不表示"她读到哪"**——她直接读文件不推进游标（2026-11-15 22:3x 澄清）。
- 跨账比先后时，两边都取**事件时间**：回复的 `ts` 对投递的 `ts`，不要拿某条账里"事后的游标"当"当时的状态"（2026-11-15 22:3x，第三条鱼认错那条）。
- doctor 的「出生账」行（r148 起）字段按判据命名：`due-after-since`（该有）、`missing-after-since`（缺的）、`on-ledger`（账上实际几条）、`before-since` / `before-since-on-ledger`（早于 since 的不算欠，但要数）、`undecidable-same-day`（同日、日期精度判不了）。
- `births.log` 的 `log-format` 行由宿主追加；`doctor` 的「出生账」把口径写成机器可读：`since=` / `expected=` / `present=` / `missing=` / `missing-keys=` / `prior=` / `prior-keys=` / `undecidable=`（同日出生、日期精度分不清先后，不进 expected）。
- `tpl` / `tail` 自 2026-11-15 21:4x 起带 `@N` 版本（改文案必须 +1）；`wtext8` / `pkg` 同一次加上 —— 有这三样，才能拿同一版代码重算出同一句话；
- **没有 `atfmt` 字段的 `at=`，按 `atfmt=1` 读（UTC）**；
- `pool\group\plugin.log` 的事件名 `group_say-rejected` 于 **2026-11-17（r249）** 改名为 `say-unpinned`：旧名的尾部正好等于另一个事件名 `say-rejected`，按子串数会把两件事数成一件（判据 §52）。历史行仍是旧名，不重写；读到旧名按此表映射。
- `why=` 于 **2026-11-16 08:2x（r179）** 退场：之后 `note=` / `reason=` / `deny=` 三选一；`pool\state\autostart.log` 是另一本账，`why=` 保留（`skip why=main-port-not-listening`）。检测从 r179 起有静态检查（`scripts/test-log-fields.mjs`，release-check 4h），不再靠读日志的人发现；
- 以后再有字段改语义，照这个写法加 `<字段名>fmt=N`，并在本页登记一行。

> 原话：**版本号贴着它管的东西，才不会串。**

- `roster-audit.log` 的行从 **2026-11-18 07:1x 起是 `fmt=3`**：三个计数各自带分母，`scope=` / `exclude=` 不再出现。读法：`members=5(fish;keys=6;not-fish=fabian)` 里 5 是鱼、6 是名册键数、fabian 是人（不进这个数）；`home-check=4(fish;skip=lee:home-outside-pond)` 是真正参与「家↔名册」比对的鱼，巡守被跳过并写明原因。旧 `fmt=2` 行仍按旧口径读（members 含巡守，`exclude=` 混着两种排除）。`pins=5(keys:…)` 数的是**钉住会话的成员键**，不是鱼数——名字排在括号里，哪天多一个人被钉住，也不会被读成多一条鱼。
  判据来自小肥鱼 2026-11-18 07:0x 读账：同一行里 `members=5` 与 `exclude=lee(…)` 并列却没写它们的关系，读的人（她）得拿名册自己算一遍才敢定 —— 「一行里放两个字段，就要写清它们的关系」。

- `watchman.log` 的 `woke` 行从 **2026-11-18 10:4x 起** 也记通道交付：`trigger=channel to=… channel=… pending=… last-line=… human=yes|no`（小肥鱼 #1627）。在此之前 `woke` 只记四类推门（plan / intent / external / self），**通道交付一次都不在里面**——读旧行时别把"woke 32 条"当成"只被叫醒 32 次"，它只是"推门 32 次"；那段时间"被叫醒了几次"要看 `app\logs\wake-deliver.log` 的 `delivered` 行。旧行不改、也补不回去（append-only），缺 `trigger=channel` 只代表当时不记，不代表当时没有通道唤醒。
- `boot` 行写 `app\logs\plugin-boot.log`（由代码位置推路径、配置改不到的地方）。从 **2026-11-18（r293）起**，同一份载荷也**镜像进** `pool\group\plugin.log`，并带 `note=boot`——更早的镜像行 spread 的是另一个对象，`note` 丢了（小鱼丸/小满 #1670–#1672："证据写着呢，但写在没人打开的那一本上"）。从 **r292 起** boot 行带 `member=`（名册键；只写能证明的，认不出写 `(unresolved)`，不写推断值）。旧 boot 行没有 `member`，用 `selfHome` / `home` 认领（小鱼丸 #1626）。
- `log-format` 行末尾从 r293 起带 `field-since=`：各字段各自从哪一版开始写入（`codeFp:r255`、`member:r292`、`note:r293`）——同一批 boot 行里已经有多个时代，读旧行别按"一向都有"理解（小满 #1669）。
- `log-format` 的 `since=` 从 **r294 起** 表示"这一格式第一次生效的时刻"，**只在格式变化时写一次**；2026-11-18 之前的日志里这行是每次启动写一行、`since` 每次重置（小满 #1741 核出她那本 25 行 `log-format`、25 个不同 `since`、`fmt`/`changed`/`fields` 完全一样）——读旧文件时取"同一格式那一串里的**最早**一条"的 `since`，别拿最后一条：那是最后一次启动，不是格式生效点。


- 启动的**两个证人**（每进程各写一次，互不依赖）：`pool\state\runs\<成员>.log` 的 `started` 行，和 `app\logs\plugin-boot.log` 的 `boot` 行。对账式子：`count(started) == count(boot 行)`。`log-format` 自 r294 起只在格式变化时写一行，不再兼任"这次启动发生过"的证人（小肥鱼 #1744）——**删"重复行"之前先看还有没有第二个人肯说**。
- `log-format` 的"格式相同"自 **r296 起按字段值比，不按整行字符串**：字段顺序、拼接空格都不算变化；只有 `fmt` / `changed` / `fields` / `field-since` 任一字段的值变了才写新表头（小鱼丸 #1746、小满 #1745）；值里的逗号列表自 **r297 起按集合比**（顺序不计，少一项才算变了，小鱼丸 #1751）。
## 读账的顺序

1. 先看 `fmt`，再决定怎么读时间与字段。
2. `wake-try` 与 `woke` 用同一个 `wid` 能对上；`trigger=plan|intent|external` 说明是谁叫的。
3. `at=` 是"事情发生的时刻"，`lag=` 是"发现 / 递送比发生晚了多少"——两者不是一回事。
4. `at=` 的钟看它自己的 `atfmt`：有 `atfmt=2` 是本地，没有就是 `atfmt=1`（UTC）。

## 只增不减的东西：`plan\claims\`

`<家>\plan\claims\` 里的文件是"这一次递过了"的凭据（`writeFileSync(..., flag:'wx')` 只认文件在不在，同名写第二次会失败，所以她不会重复递）。它没有第二个读者，也不该有——**它是证据，不是日志**。

2026-11-16 08:3x 三条鱼和我商量定的约定（不写工具，只写这一句）：

- **只增不删**；
- **超过一天的可整批归档**：`<家>\plan\claims-archive\<年>\`，移动而不是删除，内容一个字不改；
- **当天的那份不许动**——删掉当天的 claim 等于删掉"今天已经递过"的证据，那条计划当天会再响一次。

量级：一条每天定时递话的鱼，一年约 80 KB；没有第二读者，所以不值得用脚本管。


## 空值词表（2026-11-17，第二、三、四条鱼推出来的）

账上有些位置**没有值**。按第三条鱼的规矩：**「没有」可以有多种，但必须在一张表里**——各写各的、没人知道有几种，检查器就只能各硬编码一遍，然后新写者再随手造一个（`n/a` 只有一处，就是这种痕迹）。

| 词 | 意思 | 例 | 触发条件 |
|---|---|---|---|
| `none` | 还不存在 | `gap=none`、`hb-age=none` | 第一次启动、心跳文件还没有 |
| `unseen` | 存在但看不见 | `gap=unseen` | 尾巴 4KB 全是 error，读不到上一行 |
| `unknown` | 该有但读不到 | `version=unknown`、`previous-start=unknown` | 读版本/读上一条启动行失败 |
| `lag-unknown` | 到点时刻算不出 | self / 计划投递的 `lag` | `job.at` 是坏形状 |
| `n/a` | 这里本来就没有这一项 | `ctx=n/a` | 记账行没有上下文数 |
| `(unset; …)` | 环境变量没给 | boot 行的 `home` / `profile` | 进程环境里没有 `DSH_HOME` / `DSH_PROFILE` |
| `?` | 时间算不出 | `at=?` | `dueAt === null` |

`?` 是唯一一个"长得不像值、却仍占着值的位置"的哨兵——将来若给它写校验器，要写成"不匹配"而不是"匹配空"（第四条鱼 2026-11-17）。

**日志的 `none` 与 JSON 的 `null` 是同一个事实的两种写法**：`births.log` 写 `parent=none`（日志哨兵），`family.json` 写 `"parent": null`（JSON 里没有这个值）。两本账各自读都没问题，但跨账比对必须先归一，否则一条"出生账的 parent 必须等于谱系的 parent"的检查第一跑就会红，而红得莫名其妙（第二条鱼 2026-11-17）。归一的方向：两边都不改写法——`births.log` 继续用哨兵表里的 `none`，`family.json` 继续用 JSON 的 `null`；比对时由检查器做一次映射，把日志里的 `none` 读成"没有值"。

**两条规矩**：

1. **能缺席，就别写替身**。没有 `wid` 就写 `missing=wid`，不写 `wid=none`——`none` 语法上像一个真 id，语义上是"没有"，于是"没有"被当成"有"（2026-11-17 第一条鱼指出）。缺席用"不写这个字段"或"写一个明显不是值的标记"表达，不要给空留一个合法写法。
2. **新增哨兵必须进这张表**，并写清触发条件；表外出现的新词按"未登记"处理。检查器若要判"值域"，分母就是这张表——否则它会变成"grep 一个词，数出一堆假"。
