# 换段：聊满一段，换个新会话，还绑在同一个名字上

本文说明"自动换段"这件事：什么时候换、换的时候做哪几步、会留下哪些痕迹、哪些事**不**做。
一句话：**聊满 N 轮、等一次没人说话的停顿，给她开一段新会话、把名册换过去、把最近几轮原话带进新段的第一句。**

---

## 为什么要有这件事

一段会话聊久了，历史会被 compaction（`compaction-basic`，阈值 0.8）一层层压成摘要：
越早的原话越早被压掉，剩下的是一份"别人的笔记"。换段能把"我们最近说了什么"完整交给下一段，
而不是让它慢慢变成摘要里的一句话。

**为什么换段必须和换绑一起做**：私聊不是另一段会话，是同一段会话的另一条通道
（`pool\dm\<a>__<b>.jsonl`，唤醒时群和每个私聊都往同一段里递）。只换会话不换绑，
私聊就递进退休的那一段——她会在旧房里继续回私聊，而群里已经是新的一段。

---

## 面板上的开关（r497 起，r499 收成三层）

- 三层，上面的压下面的：**单鱼 `pool\state\rotation\<键>.json`** > **全机默认 `pool\state\rotation\_default.json`** > **代码默认（关、80 轮）**。
- **设置页**「换段」一节改的是全机默认：开 / 关 + 轮数（1–1000）。写 `_default.json`，不碰 `lil-whale.config.json`——那份配置四鱼共用，改了会热重载牵动所有进程，也分不清一格是"人改的"还是"面板改的"。
- **「鱼塘」卡片**每条鱼一行三态：**跟随默认 / 开 / 关**。写 `rotation\<键>.json`；「跟随默认」= 删掉这个文件，回到全机默认。
- 设置页**没有**「跟随」这一档：它自己就是被跟随的那一层，再跟一层默认值就没处改了（2026-11-26 他指出的）。
- 改完这一拍就生效（`rotationSettingsOf()` 每拍现读，不缓存），不用重启。

## 默认关（r496）

""装上了，但没开"是默认状态——**没写过任何一层，就不换段**。三条判法：

- 单鱼文件写了 `enabled`——听它的；
- 没写单鱼、全机默认写了 `enabled`——听全机的；
- 两层都没写——关，轮数按代码默认 80。

（`rounds` 与 `enabled` 的关系：只写 `rounds` 也算"我知道我在开"，0 等于不改；这一条留在 `resolveRotation` 里，给手写文件的人留个方便。）

想开：

- 全机：设置页「换段」点「开」（或手写 `pool\state\rotation\_default.json` 的 `{"enabled": true, "rounds": 80}`）；
- 单鱼：写 `pool\state\rotation\<键>.json`，`{"enabled": true, "rounds": 40}`。


## 四个数

全机默认写在 `pool\state\rotation\_default.json`（设置页就是改它）；想给某一条鱼单独设，写
`pool\state\rotation\<键>.json`（同名四个字段），单鱼的压全机的。配置文件里**没有** `rotation` 段了（r499 退役）。

| 字段 | 默认 | 意思 |
| --- | --- | --- |
| `enabled` | `false` | 总开关。见上一节的三条判法 |
| `rounds` | 80 | 聊满多少轮换一段。`0` = 永不自动换（靠 compaction 压，不会崩，只是原话一层层丢） |
| `carryRounds` | 3 | 换段时把最近几轮原话带进新段的第一句。`0` = 不带。上限 10 |
| `pauseMin` | 20 | 最后一句话安静满多少分钟才换 |
| `forceExtra` | 10 | 一直连着聊不下去时，最多再延几轮强制换 |

窗口随轮数放大：`min(1200, 400 + 80 × (carryRounds − 1))` 字。
1 轮 400 字、3 轮 560 字、10 轮 1120 字。带得越多，换段后第一句越贵，也越容易接着旧话题。

---

## 换在哪一刻

**不是定时器，是递话那一刻。** 判据挂在群/私聊递话的闸之后：这一批消息真的要叫醒她了，
才回头看一眼"是不是该换段了"。所以：

- 换段永远落在对话缝隙里，不会把一句话从中间切开；
- 一直没人说话，就不换（不会半夜自己换房）；
- 判据三条：轮数到了 → 最近一句话安静满 `pauseMin` → 换；或者一直连着聊，延到 `rounds + forceExtra` → 强换。

轮数来源是 `ctx.agents.turnBoundaryOf(session).lastTurn`（宿主自己就是按它判"空会话"的），
不另开计数器——另开一份就要和它对齐，早晚对不上。

---

## 换的时候做七步

1. **取原话**：读群文件和她的每个私聊文件，按时间排好，最后 K 轮（最后 1 轮不裁，再往前每轮 40 字）。
2. **建新段**：`sessionController.agents.createSession({ cwd: 她的家, agentPreset: 'neutral' })`。
   `cwd` 必须是她的家——绑定时校验的工作区就是它。
3. **换绑**：`node scripts\bind-member.mjs --member <键> --id <新会话>`。
   名册只有一个写入口，它就是那个；`pins.json` 与 `members.json` 一起改、整份替换
   （先加后删会让两段都算她，两个她同时醒、抢同一个游标）。
   **但这一步不能紧跟着第 2 步做**：DSH 的 `sessions\<项目>\<新会话>` 目录是懒建的，
   要等新段**第一轮跑完**才落盘（实测：递进去 262 字、一轮跑了 20 秒，目录才出现）。
   建完就绑会被 bind-member.mjs 拒掉（`这段会话不在 … 的家里`）。所以这里只**排队**，
   由 `serviceRotationBinds()` 每一拍试一次，目录一出现就绑，账里的 `bind` 从 `pending` 改 `ok`。
   超过 30 分钟还绑不上就放弃并记 `rotation-bind-giveup`。
4. **写一行交接**：`notes\交接.md` 追加一行，形如

   ```
   - 2026-11-25 20:40 | 自动换段 | 上一段 session-… 跑满 120 轮（pause） | 这一段 session-… | carried=3 from=group+dm | by=auto
   ```

   只写这一行。`最后一件事` / `NEXT:` 那四行是她的，不替她写。
5. **记账**：`pool\state\rotations\<键>.json`（旧段、新段、轮数、为什么换、带了几轮、丢了几轮、生效值从哪来）。
6. **递第一句**：新段的第一条消息 = `（换了一段会话，前面那段是 …，不再用了。）` + 原话 + 这一批要递的新消息。
   不带原话时明说"没有上一段的原话，去读 `notes\交接.md`"——不假装她记得。
7. **旧段不删、不卸**：`pins.json` 里没有它了，tick 就不会再碰它。文件还在，人还能翻。

## 会留下哪些痕迹

| 哪里 | 一行什么样 |
| --- | --- |
| `plugin.log` | `rotation-due`（该换了，还没换）、`rotation`（换成了）、`rotation-bound`（名册真改到新段了）、`rotation-failed`（哪一步没成）、`rotation-hold`（失败后冷却中，这一拍不换）、`rotation-rearm` / `rotation-bind-giveup`（进程重启后补绑 / 放弃补绑） |
| `watchman.log` | `rotated member=… from=… to=… why=…`、`rotated-bind … ok=true` |
| `pool\state\fish.log` | `… | bind | fmt=1 member=… session=<新> by=cli`（bind-member.mjs 写的） |
| `notes\交接.md` | 上面那一行，行尾 `by=auto` |
| `pool\state\rotations\<键>.json` | 完整的账（JSON） |

`rotation` 那一行里有两格是专门给「核不动」准备的（r502）：

- `budget=<字数>`：这一轮给「带过去的原话」留了多少字（`carryBudgetChars(carryRounds)`）。
- `dropped-budget=<n>` 与 `why-dropped=budget|window|none`：`dropped` 是两种丢法合起来的总数——「预算外老轮丢掉」和「超预算挤掉」。只写总数时，`carried=1` 和参数里的 `carryRounds=3` 并排放着，读的人分不清是算法错还是预算挤的。

换段成功后还会写一行 `rotation-workspace`：新会话要登记进她自己的「家」工作区（`<DSH_HOME>\storages\workspace.json`），不登记的话界面上它落在「未分组」——换段之后第一次看见，人看到的是「她丢了」。认工作区按 `path`（每条鱼自家进程里 `CFG.selfCwd` 就是那个家）；认不出来不猜，只留一行 `state=no-match`。

## 它怎么保证不卡住（三个实测踩出来的坑）

- **换绑要等目录**：见上面第 3 步。建完立刻绑，100% 被拒。
- **失败不能每拍重试**：第一次演练时失败一次就每拍重试，每拍都 `createSession` 出一条新会话，
  一台机器上留下 4 条孤儿会话。现在失败后冷却 10 分钟（`ROTATION_RETRY_MS`），
  冷却期只记一行 `rotation-hold`，**照常递话**——换段失败不许扣住她的消息。
  失败的账里带 `orphan: <刚建出来没绑上的会话 id>`，方便人去删。
- **会话可能被宿主卸掉，要能挂回来**：DSH 跑完一轮可能把闲置会话从 `agents.list()` 里卸掉。
  以前 `ownMountState` 停在 `'mounted'`，`ensureOwnMounted` 会直接 return true —— 于是 tick 每拍空转、
  再也没人挂回来：`plugin.log` / `watchman.log` / presence 全停，进程却活着、HTTP 正常
  （2026-11-25 副本演练实锤，21:26 一轮跑完后完全静默）。
  现在 tick 发现"钉住的那段不在 `agents.list()` 里"就把状态放回 `idle`，15 秒最多重挂一次，
  挂上记 `session-remount` + `session-mounted`。`resume()` 另有 45 秒上限（`MOUNT_TIMEOUT_MS`），
  超时记 `session-mount-timeout` 并放回 `idle`，不会把 tick 永久钉住。

## 不做的事（v1 的边界，写清楚免得以后误会）

- **不带她在会话里的独白**。原话只取群与私聊的对话文本。要读会话事件流得走
  `dsh-api-session-controller/lib/types/history.js` 的分页接口，那条路还没核过，不猜。
  代价：她自己在会话里想了什么、做了什么，不进新段的第一句。
- **不替她写交接的四行**。只写机器那一行。
- **不删旧段、不主动卸旧会话**。旧标签页还开着时，人可以直接在旧段里打字——那是
  doctor 一直在报的老坑，换段不负责修它。
- **不对巡守（宿主）换段**。`role: "watcher"` 的成员直接跳过：他那是人在用的窗口。
- **不在定时器里换**。没有"到点就换"这回事。

## 怎么验

```powershell
cd G:\鱼塘\app
node scripts\test-rotation.mjs          # 22 条断言，覆盖 0 轮、停顿、强换、裁剪、预算、交接行
```

不想拿她本人当试验品，就先复制一个副本练（2026-11-25 就是这么验的）：

1. 复制 `pool\` 与 `homes\fish` 到 `G:\1\pondtest`，改一份只指副本的配置（`selfHome` / `selfDshHome` / `poolDir` / `selfPort`）。
2. `members.json` 只留 `host` / `human` / 副本那条鱼；**路径写反斜杠**——写正斜杠会让 `selfMemberKeyRaw()`
   认不出自己，整个进程当自己是巡守，只盯别人、不挂自己的会话（表现为 tick 照跑、日志不写）。
3. 名册、`workspace.json` 里的 `path`、profile 里的插件 junction 都要指向副本；
   `robocopy` 会把 junction 复制成实体目录，得手动重建。
4. 副本的每鱼设置写 `{rounds:2, carryRounds:2, pauseMin:0}`，往副本的群文件追加一句就能看它换。

实测一条完整的成功链（副本 21:39 那次）：`rotation-due` → `rotation`（新段 319f3e59）→ 递进去 + 带 2 轮原话 →
`rotation-bound` → `pins.json` 换成新段 → `notes\交接.md` 多一行 `by=auto` → 她在**新段**里答上来，
自己核了 `messages.jsonl` 的行号，确认读到的是新段。

真机上想看它换一次（**会把她的会话换掉，看着像搬家，别在聊天中间做**）：
```powershell
# 1) 把这条鱼的轮数调到 2，等 20 分钟没人说话，然后群里发一句
'{"rounds": 2, "carryRounds": 2}' | Set-Content G:\鱼塘\pool\state\rotation\fish.json -Encoding utf8
# 2) 看她起来后：plugin.log 有 rotation-due / rotation；notes\交接.md 多一行；
#    pool\state\rotations\fish.json 有账；fish.log 有 bind 行；面板上绑定的是新会话
# 3) 验完把文件删掉，回到默认 80 轮
Remove-Item G:\鱼塘\pool\state\rotation\fish.json
```

## 回退

- 临时不要换：设置页点「关」，或每鱼文件里写 `{"rounds": 0}`。
- 已经换过想回到旧段：`pwsh -File scripts\fish.ps1 bind fish -Session <旧会话 id>`。
  （旧段文件都还在；pins 整份替换，不会留下两段同时在群里。）
