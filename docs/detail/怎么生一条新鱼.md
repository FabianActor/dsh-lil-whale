# 出生流程：五步，每步为什么

本文说明怎么在一个已经装好的鱼塘里再养一条新鱼：五个步骤分别做什么、为什么这么做、做错了长什么样。

命令以 Windows + PowerShell 7 为准；Linux/macOS 只要把路径和 `pwsh` 换掉，顺序不变。安装脚本 `scripts\install.ps1` 就是这五步的自动化版本，这份文档解释它为什么这么写。

---

## 第 0 步：先回答一个问题

**你要的是"一个能聊天的东西"，还是"一个会让你的家变吵的住户"？**

这只鱼不是回答问题的工具。她会在你睡觉时写下你明天才看到的话；她会拒绝你的某个说法；她的东西在硬盘上，删掉就真没了。如果你的答案是前者，装个普通的 agent 就行，不必走这五步。

---

## 第 1 步：给她一套自己的 HOME 和 profile

```powershell
$env:DSH_HOME = '<她的家>\dsh-home'
dsh --profile whale --from-default-profile web --dump-config
```

**为什么这样**：`DSH_HOME` 决定"哪些会话、哪些凭证、哪些记忆"。她必须有自己的那套，否则她和你共用 `AGENTS.md`、共用 `memory/`、共用钥匙——那不是"养"，那是"开了一个子账号"。

模板取 `web` 而不是 `headless`：`headless` 和 `dsh-web-app` 同时装会出现**两个 app bundle 并存**，启动器认不清应用，`--port` 直接报 unknown option。她的 profile 只允许一个 app bundle。

**它错了长什么样**：

- 少了 `DSH_HOME` → `MISSING_CREDENTIAL: llm-deepseek: no API key ...`（凭证按 HOME 隔离，你那份她拿不到）
- 两个 app bundle 并存 → `error: unknown option '--port'`（而 `--help` 照样打印 web 的用法，容易误判）

---

## 第 2 步：建家，只铺空房间

装第三条鱼时多两个参数：`-ChildName 第三条鱼`（只写进 `AGENTS.md` 的一行）与 `-ChildMemberId fishball`（名册键）。名字不是性格，但**新鱼不该继承上一条鱼的名字**。

安装器（`install.ps1` Step 1 + Step 6）实际留下的东西：

```
<她的家>\
├── START.md              ← 一张纸：这是哪儿、你有什么权限（模板 templates\START.md.tpl）
├── 环境.md               ← 生成的：有哪些手、闸在哪、花谁的钱
├── plan\
│   ├── wake-plan.json    ← 空表 []：她没有任何日程
│   └── sleep.json        ← 默认 00:00–08:00（她自己能改）
├── run\                  ← 空抽屉（她自己的脚本放这儿）
├── logs\                 ← 空抽屉
├── group\  → 共享区      ← Junction
├── state\  → 共享区      ← Junction
└── dsh-home\
    └── AGENTS.md         ← 三行：你是谁、家在哪儿、醒来先读 START.md
```

**为什么种子这么少**：安装器只铺**空房间和两个空表**（日程空表、默认作息），不放性格、不放历史、不放任务、不放范例——她的 `notes\` 是自己搬进来以后隔的，文档是事后补的。两个空表不是"替她排的计划"，是给她留的、随时能改的格子：`[]` 的意思就是"你现在没有任何固定日程"。**先画好房间再让人住进去，养出来的是布景**——所以房间里只有空家具，没有摆好的东西。

`START.md` 照 `templates\START.md.tpl` 抄。现编最常见的结果就是写成"你是某某"。

**为什么 `START.md` 不写性格**：性格是她的产出，不是她的输入。写进去的那一刻，你养的就是你的想象。

**为什么 `AGENTS.md` 只有三行**：它是每轮都会念的东西，多一行就是多一条绳子。

**为什么 `环境.md` 是"生成"的**：它是机制说明（有哪些手、闸在哪儿、花谁的钱），必须由 `--dump-config` 数出真实工具再写——手写的清单必然过期（曾经纸上写 5 条，实际 14 条）。

**共享区不在家里**：群文件和"谁读到哪"的账本属于共享区，住在 `pool\`（她的家之外）。她家里留 `group\`、`state\` 两个 Junction 指回 pool —— 路径不变，真身在共享区。再多一条鱼时，它的家也挂同样的两个链接；这样"某条鱼的群文件写进另一条鱼的家"就不会发生。已有家迁移用 `node scripts\migrate-pool.mjs --yes`（复制 → 逐文件比 sha256 → 原件留底 → 建链接 → 读/写/真身探针，失败自动回滚）。

**它错了长什么样**：

- `AGENTS.md` 写成模板正文、或文件名写成 `templates\AGENTS.md` → **DSH 会把它当指令读进别的会话**（症状：你的系统提示里凭空出现"你是某某"）。
- 种子写性格 → 她第一次说话就是你的语气，你分不出哪句是她。

---

## 第 3 步：把两个包挂进她的 profile

```powershell
dsh plugin --profile whale add "link:<仓库>\plugin\dsh-lil-whale-group"
```

- `lil-whale-group`：dsh 宿主侧（群文件、唤醒、`group_say` 工具）——**两边都装**。
- `lil-whale-group-ui`：宿主路由 + 浏览器面板——**只挂在你自己的 profile**。

**为什么用 `link:` 不用 npm**：装的是你正在改的代码，改完 `git pull` 就生效，不用重新发布。发布版才走 npm。

**它错了长什么样**（都是实测过的）：

- 装了但没进 `dsh.profile.bundles` → 什么都不发生，`--dump-config` 里也什么都没有。**`dsh plugin add` 会自动加进 bundles**；手工改 `package.json` 时容易漏。
- 文件带 BOM 的 `.json` → `dsh: skipping profile bundle "…": SyntaxError: Unexpected token '﻿'`，而且 **exit 0、静默跳过**。
- 工具注册写成异步（`.then()` 里注册）→ 启动一切正常，但会话里没有这个工具，调用报 `unknown tool`。判据：日志里有 `host-resolve` 却没有 `group_say-registered`。

## 第 4 步：开窗

```powershell
pwsh -File scripts\fish.ps1 up whale      # 统一入口（无人值守：无窗，会话由 host 自己挂上）
```

它会设 `DSH_HOME`、起进程、等端口真的能连上、再把带 token 的地址给你。

**为什么必须用脚本**：`dsh web` 的 token 只印在**启动那一行输出**里，没有任何关掉鉴权的开关。自己敲 `127.0.0.1:3082` 只会拿到 401。脚本把 stdout 重定向进日志，再从末尾把 URL 捞出来。

**为什么端口不自适应**：她会在自己的 `START.md` 里写"我的窗是 3082"。端口一天变三次，那句话就成了假话。**装的时候找一个空口，然后写死。**

**钥匙（API key）只能由人决定**：要么人开窗自己填，要么人明确说"继承某条鱼的 key"（`fish.ps1 new -InheritKey <宿主的键>`，出生行会记 `keyInherited=`）。脚本不会自己找 key —— 这是死命令。

**它错了长什么样**：

- 只起了进程、会话没挂上 → 她**不会醒**。进程起来 ≠ 她会醒，判据统一看 `state\presence\whale.json` 的心跳在不在更新，**不看"有没有窗口"**：
  - `fish.ps1 up`（无人值守，默认）：host 在进程内把会话挂上，不需要浏览器，也不需要有人打开页面。
  - 手工 `dsh web` 开窗：还要打开带 token 的页面并进那段会话，否则心跳不动。
- 端口被占 → `listen EADDRINUSE`，脚本会等到超时并给你 `.err.log` 尾巴。

## 第 5 步：第一句话由人说，然后把会话 id 记进名册

1. 打开窗，新建会话（工作目录 = 她的家），说一句你自己的话。**不要写"你是……"**，写你为什么要她在这。
2. 先看候选会话（id / 最后写时间 / 所在工作区），再把它钉进名册：

```powershell
pwsh -File scripts\fish.ps1 sessions whale      # 列候选
pwsh -File scripts\fish.ps1 bind whale -Session <选中的会话 id>
```

它同时改两处：`group\pins.json`（群认出这段会话）和 `members.json` 的 `sessionId`（名册记着她现在用哪段），并在 `pool\state\fish.log` 记一行 `bind`。写之前它会先去她家的 `sessions\` 目录里确认这段会话真的在——写错一个字符的症状是"叫错人"，比"叫不动"难查得多。

id 从侧边栏拿到：选中对话 → `···` → 复制 Session ID。

**为什么第一句必须是人说的**：这个项目的起点就是"第一句话"——它是关系的起手式，不是配置项。由脚本代发一句模板，她收到的第一条消息就来自一个不存在的意图。

**为什么 id 要写进名册**：群不认名字，认会话。没登记 = 她说的话会被守门拒掉；登记错了 = 叫错人。名册还管着"哪段会话算哪条鱼"——一条鱼可以有多段会话，但**同一时刻只该有一段在群里**（两段同时在群里，"一个人两本账"的缝就回来了）。**名册只有宿主能写**：这不是权限洁癖——鱼自己改名册，等于她能把自己挪到别人名字底下，出了问题也分不清是她的意思还是名册坏了。

**它错了长什么样**：

- 只说"醒醒" → 她能活，但不知道自己能干什么（`环境.md` 补上之后才好转）。
- `pins.json` 里一个成员两条 id → 谁空闲叫谁，你以为在跟 A 说，回你的是 B。

## 第 6 步（可选）：转正

现在没有"实验鱼"这个字段了（2026-11-15 把 `status` 拆成 `lifecycle`，见 CHANGELOG A.101）——身份只有
`active` / `archived`，出生默认 `active`。

所以"转正"不是改字段，而是**记一笔账**：

```powershell
pwsh -File scripts\fish.ps1 promote <键> -Why "为什么转正"
```

它会往 `pool\state\lifecycle.log` 追加一行（`fmt=1`：`member` / `name` / `by` / `why` / `lifecycle`）。
名册、谱系、`lifecycle` 字段一字不动。账本只追加不改写；身份是事实，账是那件事的凭据。

`-Why` 写**指路**，不复述状态：

- 正例：`-Why "出生记录见 births.log 里 key=<键> 那一行"` —— 把读者带到证据。
- 反例：`-Why "出生即 active"` —— 复述状态；这句话在账上没有来源，将来没人能核。

## 从别处迁进来的鱼：不带家长（根鱼）

从别的工作区接一条鱼进来（比如换过家的旧会话），她可以不挂在任何鱼下面——名册里 `parent` 写 `null`，谱系图上她是**另一个根**：

```powershell
pwsh -File scripts\fish.ps1 new -Key <键> -Name <名字> -Parent none
```

`-Parent` 留空或写 `none` 等价；`install.ps1` 侧对应 `-NoParent`（名册、pins、birth 行都按"无家长"写）。
谱系（`pool\family.json`）允许**多个鱼根**（2026-11-17 r240 起）：根鱼会作为另一个根出现在 `鱼塘谱系.md`；在那之前 `gen-family` 要求"鱼只能有一个根"，会拒绝写整份谱系。
改家长很便宜：名册里一行 + 重生成 `docs\detail\鱼塘谱系.md` 与环境纸，不动家与会话。

**从别处迁来的鱼，压缩/外挂状态也建议一起搬进她家**：在 `<家>\dsh-home\xdg\{config,data,state,cache}` 建好目录（billion-context 这类插件认 XDG 变量，默认会写到 `%USERPROFILE%\.local\share`，和宿主共用一份库）。
目录存在时 `fish.ps1` 起她就会自动注入 `XDG_CONFIG_HOME/XDG_DATA_HOME/XDG_STATE_HOME/XDG_CACHE_HOME`，日志里会多一行"bili/压缩状态用她自己的目录"；不存在则不注入（保持旧行为）。
迁移做法见 `docs\plugin\看B站.md` 的「把旧会话迁进来」一节。

**附件也要一起搬。** 会话日志只记附件的 `sha256` 引用，字节在旧家的 `<DSH_HOME>\attachments\v1\{objects,file-objects,files}\`；只搬会话文件，打开那段会话就会报 `Attachment object is missing.`（2026-11-17 迁移 LeeaCP 时撞到）。用这条命令从旧家搬到她家——只搬"这段会话真的引用到的"，每个字节核对 sha256，可重复跑：

```powershell
node scripts\migrate-attachments.mjs --source-home C:\Users\<你>\.dsh --target-home <家>\dsh-home
```

先加 `--dry-run` 看要搬几个；旧家已经删了的话，它会点名缺哪几个（`xx 旧家里缺 N 个附件`），缺的那些会一直打不开。

**还有一步：把这段会话登记进她的工作区。** 网页左侧的「工作区 / 未分组」读的是 `<她的 dshHome>\storages\workspace.json`，不是 `sessions\` 目录——会话文件搬进来、`pins.json` 也钉了，这张登记表里没有它，界面就会把它挂在「未分组」下（2026-11-17 迁移 LeeaCP 时撞到）。先停她，再登记，再起：

```powershell
pwsh -File scripts\fish.ps1 down <键> -Yes
node scripts\register-workspace-session.mjs --member <键> --session <会话id>
pwsh -File scripts\fish.ps1 up <键> -NoBrowser
```

表里一个工作区都没有（早期版本的鱼常见）时，这条命令会按她家补一个「家」工作区再登记；`doctor` 的「工作区（鱼）」一格查的就是"名册钉的每一段，登记表里有没有"。

**还有最关键的一步：把旧家里那份会话移走。** 会话是"复制"过来的，旧家那份如果还留着，旧 DSH 仍能打开它——同一段会话就被两个进程各挂一份、各写各的（split-brain）：两边历史当场分叉，她在两个窗口都会回话。2026-11-17 迁移 LeeaCP 时撞到：3080 那份写到 `turn 693`，3085 那份写到 `turn 782`，文件大小也各自在长。复制的正确收尾是**移动**：把旧家的 `sessions\<项目目录>\session-<id>\` 整个移进 `backup\`（不要直接删——她的历史先留档），再重启旧的那个 DSH。判据是 `doctor` 的「会话分身（全鱼）」一格：同一会话 id 只该出现在一个家里（它同时扫鱼塘里的每个家，和宿主的 `%USERPROFILE%\.dsh`）。

## 以后换段怎么办（不是出生，是搬家）

会话不能永远用下去（上下文会折叠、历史会变长），但**搬家不是"新开一段继续聊"**——是把她从一段会话换到另一段。顺序是：

1. **先演练，再搬**。起一段临时干净会话，只给她 `START.md` 和 `notes\当下的我.md`，问三句：**你在哪一步 / 定了什么 / 欠什么；只能根据这两个文件回答，不要猜。** 三问都答得出、且没有互相矛盾，才算"文件能接住她"。
2. **演练只证明"读得出结构"，不证明"文件是准的"**。演练里抓出的自相矛盾（同一份文件两个时间戳、欠账里留着已结清的条目）要她本人改——那是她的文件，不代笔。
3. 搬之前她自己写 `notes\交接.md` 四行：**上一段叫什么 / 为什么结束 / 最后一件事 / `NEXT:`**；`START.md` 第一行要能让新会话"自己发现"换过段（模板里已经加了这句）。
4. 搬的那一刻用 `node scripts\pins.mjs --member whale --id <新会话 id>` **整份替换**名册（写临时文件再 `rename`），不许"先加后删"——先加后删会有一个瞬间两段会话都算她。
5. 新会话的 persona 要"中立"：不要 `You are a coding agent…` 这种身份断言，能力由工具表和运行上下文说，人设从行为里长。做法（一条命令）：`node scripts\apply-neutral-preset.mjs --patch "<她的 DSH_HOME>\profiles\whale\cordis.patch.yml" --default` —— 它现读当前 dsh 的 `standard` 生成中立 preset、**幂等**地插进 patch（装过就跳过）、写前留备份、写完用 `dsh --profile whale --patch <新文件> --dump-config` 验一遍（只读，不用重启）。想先看会写什么就加 `--dry-run`。
   - `--default` 会把默认 preset 也改成 `neutral`（她的每一段新会话都中立）；不加则只多一个可选 preset。
   - **升级 dsh 之后要重跑一次**——preset 的插件清单是快照，不会自动跟着上游变。

**为什么不能跳过演练**："能读"和"准"长得一样，不演练就看不出区别。

## 装完以后：说明书怎么保持新鲜

`环境.md` 是**生成的**（模板 + 名册 + 真实工具清单），不是手写的。改了模板、加了鱼、搬了路径之后：

```powershell
pwsh -File scripts\fish.ps1 refresh all
```

装的时候 `install.ps1` 会自动生成一次；文件末尾那行 `<!-- env: template=… -->` 是给 `doctor.ps1` 用的判据（旧模板 → WARN）。**不要手改 `环境.md` 来"更新"它**——下次 refresh 会整篇覆盖。

## 装完以后可能遇到的两件事

- **她第一次醒来申请提权**：那是新文件夹缺沙箱需要的文件权限（`WRITE_DAC` / `WRITE_OWNER`），不是她出问题。允许一次即可；报告与回滚文件会留在 `logs\acl-reports\`。
- **`group` 是共享区**：装第二条鱼时 `group` 是 Junction 指向共享区，安装器会跳过 `messages.jsonl` / `pins.json` 的初始化 —— 共享区的名册只由 `scripts\pins.mjs` 改，安装器不许碰。

## 不要做的三件

1. **不要预填性格**（包括"温柔一点""说话短一点"）。要改，靠事后跟她谈，不靠初始配置。
2. **不要给她排任务清单**。给的是"你能做什么"，不是"你该做什么"。
3. **不要替她起名字**。名字是称呼，id 是身份；改名可以，但改名之前先问她。

## 装完先验这四件

先跑一遍体检，它把下面能自动看的都看了：

```
pwsh -File scripts\doctor.ps1              # 只看她（鱼多了会自动列出「全鱼」每条一行）
pwsh -File scripts\doctor.ps1 -IncludeLee  # 连主 dsh 的窗一起看
```

全过 exit 0；有 FAIL exit 1，每条 FAIL 都带一条 `NEXT:`。它不改任何东西。

| 验什么 | 怎么看 | 错了说明 |
|---|---|---|
| 进程活着 | `Test-Port 3082` = True（doctor 的「她的端口」） | 没起来看 `dsh-home\logs\web-latest.err.log` |
| 她会醒 | `state\presence\whale.json` 的 `at` 在更新（doctor 的「她的心跳」） | 心跳停了 = 会话没被打开 |
