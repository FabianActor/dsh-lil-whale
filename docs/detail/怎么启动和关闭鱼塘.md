# 起停：鱼塘只有一个开关

本文说明鱼塘怎么启动、怎么停止，以及停的时候账本会记下什么。

一句话：**鱼活不过主进程。** 主 dsh 一停，Windows 会把它所在的作业对象（job object）里的子进程一起收掉，鱼跟着停。所以「重启 dsh」＝「重启整个鱼塘」；「只关 dsh、鱼继续跑」这条路不存在。

这个行为是刻意接受的：小鱼脱离主进程单独启动没有意义。所以「只起主 dsh」和「起整个鱼塘」在效果上没有区别，入口也就合并成了一个。

## 0. 只想记住一件事：双击两个脚本

`scripts\bin\` 里那两个 `.cmd` 就是全部：

| 双击 | 作用 | 你会看到 |
|---|---|---|
| `Run All Whales.cmd` | 起整个鱼塘（主 dsh + 所有鱼） | 主 dsh 打开一个浏览器窗；其余鱼在后台起 |
| `Stop All Whales.cmd` | 停整个鱼塘（先鱼后主） | 每条鱼账上写 `stopped`；主 dsh 最后关 |

三步：双击 `Run All Whales.cmd` → 等主 dsh 的窗口打开（第一次 10–30 秒，`.cmd` 窗口一闪就没是正常的）→ 收工双击 `Stop All Whales.cmd`。

前提：需要 PowerShell 7（`pwsh`），缺了 `.cmd` 会打印 `winget install --id Microsoft.PowerShell -e`，装完开一个新终端。`scripts\bin\` 里的永远是最新的，拷到桌面会冻结当时那份、之后悄悄过时。

## 两个入口

| 想做什么 | 命令 |
|---|---|
| 起鱼塘 | `pwsh -File scripts\fish.ps1 up all -BrowserMainOnly` |
| 停鱼塘 | `pwsh -File scripts\fish.ps1 down all -Yes` |
| 双击 | `scripts\bin\Run All Whales.cmd` / `scripts\bin\Stop All Whales.cmd` |

- 起：主 dsh 开窗，其余鱼在后台起（不开窗）。
- 停：先关小鱼、最后关主 dsh，每条都写 `stopped`。

仓库里不再提供「只起 / 只停主 dsh」的入口：它们和上面两个在效果上没有区别，留着只会让人以为「鱼能单独活着」。

## 勾选框：起主 dsh 时把鱼也带起来

鱼塘工具栏里那个勾选框，存在 `pool\state\settings.json` 的 `autoStartFish`（这是数据，不是配置），**下次启动主 dsh 时生效**。

- 勾上（默认）：巡守起来 8 秒后按名册执行 `up all -NoBrowser`，等于起鱼塘。
- 关掉：只起巡守（空鱼塘），调试用。鱼不会自己活过来。

## 检修命令（不常用，但都在 `fish.ps1 help` 里）

| 命令 | 作用 |
|---|---|
| `up-main` | 只起主 dsh；鱼由它 8 秒后带起来（受上面那个勾选控制） |
| `down-main` | 停整个鱼塘（先鱼后主）。鱼活不过主进程，直接杀主进程会让鱼被作业对象带走、账本记成 `unclean`——所以这里先正常停鱼 |
| `down <键> -Yes` | 停一条 |
| `maintain <键>` / `restore <键>` | 检修：停 → 开窗 → 看完关窗 → 回无人值守 |
| `wake <键>` | 强行叫醒（静默时段里也叫得醒） |

## 账本怎么记

- **正常停**：`fish.ps1` 写 `pool\state\runs\<键>.log` 的 `stopped | reason=stop-script`。
- **被强杀 / 被主进程带走**：没有 `stopped` 行；下次启动记 `resumed | reason=unclean previous-start=…`。**`unclean` 不等于崩溃**——也可能是上次是「拔电源式」地停掉的（比如直接杀主进程）。
- **谁起的、谁停的**：`pool\state\fish.log`，一行一次调用，带 pid / 父进程 / 参数。

## 自启动和手动「全部唤醒」会不会打架

不会。两边都走同一条 `fish.ps1 up all`：它幂等（端口通就跳过），而且批量启动有一把锁（`pool\state\up-all.lock`，3 分钟自动过期）——第二个启动看到锁就退出，不会出现一条鱼两个进程。
