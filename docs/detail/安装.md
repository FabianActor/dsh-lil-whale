# 安装流程详解

这份文档回答一件事：**从一台干净的 Windows 机器，到一条能被叫醒、能自己说话的小鱼，中间每一步到底发生了什么。**

它按 2026-11-13 的代码重写。上一版（同日 17:09）描述的是旧布局和 agent-loop 那套无人值守；现在目录、起鱼方式、计划表归属、快捷方式入口都换了，所以这一版不是改几句，而是按代码逐节重核了一遍。

读法建议：第一次装，按 §3 一步步走；只想复查自己机器，跳到 §10；想知道"为什么她是这样醒的"，看 §7。

## 0 记号与边界

### 0.1 记号

| 记号 | 指什么 | 装完的典型值 |
| --- | --- | --- |
| `<鱼塘根>` | 所有东西的根，一个目录 | `D:\WorkSpace\lil-whale` |
| `<仓库>` | 代码仓库 = `<鱼塘根>\app` | 同上 |
| `<家>` | 一条鱼的家（也是她的工作区）= `<鱼塘根>\homes\<键>` | `…\homes\whale` |
| `<DSH_HOME>` | 这条鱼自己的 dsh 配置目录 = `<家>\dsh-home` | `…\homes\whale\dsh-home` |
| `<共享区>` | 所有鱼共用的那块 = `<鱼塘根>\pool` | 同上 |
| `<键>` | 名册里的 key，小写英文 | `lee` / `whale` / `fishball` |
| `<profile>` | dsh 的 profile 名 | `web`（主）/ `whale` / `fishball` |
| `%USERPROFILE%` | Windows 用户目录 | 与项目无关 |
| `3080` / `3082` / `3083` | 主 dsh / 小肥鱼 / 小鱼丸 的端口 | 举例值 |
| `$X` | PowerShell 变量 | — |
| `X` | Node（插件）里的常量 | — |

文里凡写"她的"，指当前这条要装的鱼；"他"指机器的主人（名册里的 `fabian`）。

### 0.2 三条硬边界

这三条是设计的骨架，任何改动都不许破：

1. **家 ≠ 共享区**。她的家（工作区、笔记、日志）在 `homes\<键>\`；群里说的话、私聊、名册、账本在 `pool\`。家里只通过两个 Junction（`group\`、`state\`）看到共享区，写进去就是写进共享区。
2. **`DSH_HOME` ≠ 家**。`DSH_HOME` 是 dsh 自己的配置与会话目录（`<家>\dsh-home`）；家是她的工作区。混在一起，换 dsh 版本或者删配置就会连她的笔记一起删。
3. **配置只有一份真源**。所有"会变的路径"都在 `<仓库>\lil-whale.config.json`（或 `.<键>.json`）里，代码里不许写死本机绝对路径。打包给别人时只改配置。

这版新增的一条，属于运行期约定：**无人值守是默认状态**。端口通着不代表窗开着；默认起鱼不开浏览器，会话由插件在进程里挂上（§7.3）。

### 0.3 与上一版的差别

| 项 | 上一版（2026-11-13 17:09） | 现在 |
| --- | --- | --- |
| 目录 | `<鱼塘根>\lil-whale`（家）+ 平级 `lil-whale-pool`、`lil-whale-2` | 一个根、四层：`app\` + `pool\` + `homes\<键>\` + `acl\` |
| 起鱼 | 默认开浏览器窗 | `Start-Fish` 默认 `-NoBrowser`，先 `Ensure-Unattended` |
| 会话挂载 | agent-loop 的 `agents:[{resumeSessionId}]`（已废弃） | 插件进程内调 `sessionController.agents.resume(sessionId)` |
| 计划表 | 巡守代读、代递 | 每条鱼自己的 60 秒 timer 读自己家的表、自己 claim、自己递 |
| 底层脚本 | `launch.ps1` / `stop.ps1` / `start-whale.ps1` / `watchman.ps1` | 只剩 `scripts\fish.ps1`；旧脚本在 `archive\legacy-scripts-2026-11-13\` |
| 桌面入口 | `Run lil whale.cmd` 等一堆 | 两个：`Run All Whales` / `Stop All Whales`（`Run DSH` / `Stop DSH` 2026-11-14 删掉） |
| 配置 | 一份 `lil-whale.config.json` | 每条鱼一份（`whale` 仍用主名），起鱼时按 `-ConfigPath` 注入 |
| 封顶 | 每条鱼各自 8 次/天 | 另加全池 `totalPerDay: 120` |

## 1 总览

### 1.1 一张图

```
① 环境检查         dsh 在 PATH、仓库三件文件在
② 算路径与端口     布局判定 → 家 / DSH_HOME / 共享区 / 端口（跳过已登记端口）
③ 建目录           <家>、logs、plan、run、<DSH_HOME>、pool\{group,state,dm}
④ 建两个 Junction   <家>\group → pool\group ；<家>\state → pool\state
⑤ 建 profile        DSH_HOME=<DSH_HOME>，dsh --profile <键> --from-default-profile web
⑥ 挂插件           dsh plugin --profile <键> add link:<仓库>\plugin\dsh-lil-whale-group
⑦ 写配置           合并写 10 个键；已存在且 selfHome 不同则拒绝（除非 -Force）
⑧ 种子文件         START.md / 环境.md / AGENTS.md / group 两文件 / members.json / wake-plan.json
⑨ 验收             dsh --profile <键> --dump-config 里要有 lil-whale-group
⑩ 起鱼             scripts\bin\Run All Whales.cmd（或 fish.ps1 up <键>）→ 无人值守
⑪ 人说第一句       她网页里填自己的 key → 添加工作区 → 新建会话 → 由人开口
⑫ 钉会话           ··· 复制 Session ID → pins.json（哪段会话算谁）
```

### 1.2 阶段表

| 阶段 | 做什么 | 谁做 | 没做成会怎样 |
| --- | --- | --- | --- |
| 准备 | 装 dsh、Node、git、pwsh 7；准备两把 key | 人 | `install.ps1` 在 Step0 直接 `Die` |
| 装机 | ②–⑨：目录、profile、插件、配置、种子、验收 | `install.ps1` | 每一步失败都 `Die` 并打 `NEXT:`，已建的东西留在原地 |
| 出生 | ⑩–⑫：起鱼、填 key、说第一句、钉会话 | 人（起鱼可脚本化） | 鱼能起但不会被叫醒、不会进群 |
| 日常 | 开关、检修、刷新说明书、体检 | 快捷方式 + `fish.ps1` + `doctor.ps1` | 见 §8 |

### 1.3 两个入口（`scripts\bin\`）

| 快捷方式 | 实际命令 | 做什么 |
| --- | --- | --- |
| `Run All Whales.cmd` | `fish.ps1 up all -BrowserMainOnly` | 起鱼塘：主 dsh 开窗，其余鱼无人值守 |
| `Stop All Whales.cmd` | `fish.ps1 down all -Yes` | 停鱼塘：先关小鱼，最后关主 dsh（每条都写 `stopped`） |

原来的 `Run DSH.cmd` / `Stop DSH.cmd` 2026-11-14 删了：鱼活不过主进程（作业对象），「只起主 dsh」和「起鱼塘」在效果上没有区别。想只起主 dsh 用 `fish.ps1 up-main`，它会提示 8 秒后按勾选把鱼带起来。


桌面上的四个是**副本**（sha256 与 `bin\` 里一致），不是快捷方式。**副本不跟着更新**——脚本改得勤的时候，桌面那份会悄悄过时。所以推荐直接在 `scripts\bin\` 里双击，或者直接跑 `pwsh -File scripts\fish.ps1 …`；拷到桌面只适合"以后不打算再改"的机器。

`.cmd` 找脚本的顺序是三步：`%~dp0..\fish.ps1` → `%~dp0fish.ps1` → `%USERPROFILE%\dsh-lil-whale\scripts\fish.ps1`。第三步靠那个指向 `<仓库>` 的 Junction，专治"路径里带中文被 GBK 读错"。

## 2 前置条件与目录布局

### 2.1 机器要求

| 项 | 要求 | 为什么 |
| --- | --- | --- |
| 系统 | Windows 10/11 | Junction、`Get-CimInstance`、`TcpClient` 都按 Windows 写 |
| PowerShell | **7（`pwsh` 在 PATH，7.2+）** | **必需的运行时依赖**：脚本互相用 `pwsh -NoProfile -File` 起子进程，且用了 7 才有的语法（`??` 等）；Windows PowerShell 5.1 会在**解析阶段**报错，不是运行出错 |
| dsh | `dsh` 在 PATH（0.2.x） | `install.ps1` Step0 会 `Get-Command dsh` |
| Node | 有 `node` | `pack.ps1`、`release-check.ps1`、`pins.mjs` 等都用它 |
| git | 有 `git` | `pack.ps1` 用 `git archive` 打包；`release-check.ps1` 查工作目录 |
| API key | 两把，主和鱼各一把 | 共用一把会在同一额度上互相打 |
| 机器 | 尽量不关机的电脑 | 计划表靠进程里的 timer 走；关了就等下次开机 |
| 路径 | 尽量纯 ASCII | 中文路径会让 `.cmd` 按 GBK 读错；Junction 是兜底，不是免疫 |

装 pwsh（一次就够）：`winget install --id Microsoft.PowerShell -e`，装完开新终端，`pwsh -v` 应打出 `PowerShell 7.x`。
五个入口脚本（`install` / `fish` / `doctor` / `release-check` / `verify-pending` / `pack` / `wake-fish`）都带 `#requires -Version 7.0`：用 5.1 跑会被直接拒绝并说明版本不对；四个 `.cmd` 启动器会先 `where pwsh`，缺了就提示装。

### 2.2 目录布局（一个根、四层）

```
<鱼塘根>\                       例：D:\WorkSpace\lil-whale
├─ app\                         仓库（代码、脚本、模板、文档、dist、logs）
│  ├─ scripts\                   install / fish / wake-fish / doctor / verify-pending / release-check …
│  │  └─ bin\                    四个 .cmd
│  ├─ plugin\dsh-lil-whale-group\          群插件（一条鱼一个进程里跑的就是它）
│  ├─ plugin\dsh-lil-whale-group-ui\       主 dsh 的鱼塘界面
│  ├─ templates\                 START.md.tpl / 环境.md.tpl / AGENTS.md.tpl / 工具目录.json
│  ├─ docs\                      这份文档住这儿
│  └─ logs\                      plugin-boot.log、wake-metrics.log、wake-deliver.log
├─ pool\                        共享区（所有鱼共用）
│  ├─ group\                    messages.jsonl、群.md、pins.json、plugin.log、ui-*.json、images\、avatars\
│  ├─ state\                    runs\、mode\、presence\、wakes\、usage\、cursors\、acl\、settings.json、autostart.log、watchman.json
│  ├─ dm\                       <a>__<b>.jsonl + 私聊-<a>__<b>.md
│  ├─ archive\                  归档过的鱼（archive-fish.mjs 的产物）
│  ├─ members.json              名册（谁是谁、端口、家在哪）
│  └─ family.json               谱系（parent / bornAt / status / renames）
├─ homes\                       每条鱼一个家
│  ├─ whale\
│  │  ├─ START.md               给她的第一页
│  │  ├─ 环境.md                工具与机制的说明书（render-env.mjs 生成）
│  │  ├─ dsh-home\              DSH_HOME：profile、sessions、storages、logs、AGENTS.md

│  │  ├─ notes\                她的笔记（交接.md、当下的我.md）
│  │  ├─ plan\                  wake-plan.json + claims\
│  │  ├─ run\                   运行时产物
│  │  ├─ group   →  <鱼塘根>\pool\group    （Junction）
│  │  └─ state   →  <鱼塘根>\pool\state    （Junction）
│  └─ fishball\                 同构
```

`homes\` 下的鱼目录**本身不是链接**；链接只有家里那两个 `group` / `state`。

### 2.3 布局是怎么判定的

`install.ps1` 里只有一条判据：

```powershell
$RepoRoot = Split-Path $PSScriptRoot -Parent      # <仓库>
$PondRoot = Split-Path $RepoRoot -Parent          # <鱼塘根>
$InPond   = ((Split-Path $RepoRoot -Leaf) -eq 'app') -and (Test-Path (Join-Path $PondRoot 'pool'))
```

- `$InPond` 为真 ⇒ 新布局：家 = `<鱼塘根>\homes\<键>`，共享区 = `<鱼塘根>\pool`，配置按鱼分开（`whale` 用 `lil-whale.config.json`，其余 `lil-whale.config.<键>.json`）。
- `$InPond` 为假 ⇒ 退回旧布局：家 = `<鱼塘根>\lil-whale`，共享区 = `<家>的上级\lil-whale-pool`。

`-Workspace` / `-PoolDir` 一旦显式给出，就用给的值，不再看布局。

注意这条判据**只认目录名叫 `app`**：仓库克隆成了 `dsh-lil-whale` 之类的名字，就会被当成旧布局处理（§11 第 8 条）。

### 2.4 `%USERPROFILE%\dsh-lil-whale` 这个 Junction

它指向 `<仓库>`。存在的理由只有一个：`.cmd` 里那条回退路径要短、要纯 ASCII，而真实仓库路径可能带中文。删掉它不影响主流程，只会让 `.cmd` 的第三步回退失效（前两步通常已经能找到脚本）。

判断一个路径"是不是链接"要 `lstatSync`（Node）或 `LinkType`（PowerShell 的 `Get-Item`）：`statSync` 会跟进去，看起来就像个普通目录。断掉的 Junction（目标被移走过）只有 `lstatSync` 能看出来。

## 3 安装逐步拆解

### 3.1 命令行与参数

最小一条：

```powershell
pwsh -File <仓库>\scripts\install.ps1
```

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `-Workspace` | 空 ⇒ 按布局算 | 她的家（工作区） |
| `-DshHome` | 空 ⇒ `<Workspace>\dsh-home` | 她的 `DSH_HOME` |
| `-ChildProfile` | `whale` | 她的 profile 名 |
| `-ChildName` | `小鲸鱼` | 名册里的称呼、`AGENTS.md` 里那句话 |
| `-ChildMemberId` | 空 ⇒ 同 profile | 她的键；决定家目录名和配置文件名 |
| `-ParentMemberId` | `lee` | 父辈的键（主 dsh） |
| `-HumanMemberId` | `fabian` | 人的键 |
| `-ParentProfile` | `web` | 主 dsh 的 profile（插件要装进去） |
| `-ChildPort` | `0` ⇒ 3082 | 想要的端口；被占会往上找 |
| `-ParentSessionId` | 空 | 直接写进 `pins.json` 的父辈会话 |
| `-ChildSessionId` | 空 | 直接写进 `pins.json` 的她的会话 |
| `-SkipParent` | 关 | 不往主 profile 装插件（试装用） |
| `-ConfigPath` | 空 ⇒ 按布局算 | 配置文件写哪儿 |
| `-PoolDir` | 空 ⇒ 按布局算 | 共享区在哪儿 |
| `-Force` | 关 | 覆盖已存在的家、配置、种子文件 |

`$ErrorActionPreference = 'Stop'`：任何一处抛错都停，不留半截。

### 3.2 启动时算出来的值

| 变量 | 算法 | 例（新布局） |
| --- | --- | --- |
| `$RepoRoot` | `Split-Path $PSScriptRoot -Parent` | `<鱼塘根>\app` |
| `$PondRoot` | `$RepoRoot` 的上级 | `<鱼塘根>` |
| `$InPond` | 目录名叫 `app` 且旁边有 `pool\` | `True` |
| `$childKey` | `-ChildMemberId`，空则 `-ChildProfile` | `whale` |
| `$Workspace` | 新布局 `<PondRoot>\homes\<键>` | `<鱼塘根>\homes\whale` |
| `$DshHome` | `-DshHome`，空则 `<Workspace>\dsh-home` | `…\homes\whale\dsh-home` |
| `$PoolRoot` | 新布局 `<PondRoot>\pool` | `<鱼塘根>\pool` |
| `$portWanted` | `-ChildPort`，0 则 3082 | `3082` |
| `$registeredPorts` | 读 `<PoolRoot>\members.json`，port→key | `{3080:lee, 3082:whale, 3083:fishball}` |
| `$port` | `Find-FreePort $portWanted`，再跳过已登记端口 | `3084`（若 3082、3083 都占） |
| `$cfgName` | 新布局且键非 `whale` ⇒ `lil-whale.config.<键>.json` | `lil-whale.config.json` |
| `$deployDate` | `yyyy-MM-dd` | `2026-11-13` |

`Find-FreePort` 的语义：从起点往上试 50 个，用 `TcpClient.Connect('127.0.0.1', $p)` 判通不通。端口被占了就往上找，并且**跳过名册里已登记的端口**（不然会和第二条鱼撞）；被跳过时打一行「端口 3082 已被 whale 登记，跳过」。50 个都不行就 `Die`，`NEXT: 换 -ChildPort`。

开头会打一段 banner，形状是：

```
仓库           <鱼塘根>\app
她的家         <鱼塘根>\homes\whale
她的 DSH_HOME  <鱼塘根>\homes\whale\dsh-home
她的窗         127.0.0.1:3082 (profile: whale)
你的 profile   web
```

如果端口和"想要的"不一样，banner 之后会有一行 `WARN`：端口被占，改用 X（已写进配置，运行期不会再变）。这句话是承诺：装机时定下的端口，之后靠配置读，脚本不会自己改。

### 3.3 Step0 环境检查

三件事，任何一件不满足就停：

1. `Get-Command dsh` 找不到 ⇒ `Die "找不到 dsh 命令"`，`NEXT: npm i -g @deepseek-ai/dsh`。
2. `dsh --version` 打一行，方便事后对版本。
3. 三个相对路径必须存在：`plugin\dsh-lil-whale-group\package.json`、`plugin\dsh-lil-whale-group-ui\package.json`、`templates\START.md.tpl`。缺了说明仓库不完整（比如只 copy 了 `scripts\`）。

### 3.4 Step1 目录与 Junction

先判"这儿是不是已经像一条鱼的家了"：`<Workspace>` 已存在且里面有 `START.md` 或 `dsh-home`，没带 `-Force` 就 `Die`。这条挡的是"手滑对着自己的仓库再装一遍"。

创建顺序（`New-Item -ItemType Directory -Force`，都是递归建）：

```
<Workspace>
<Workspace>\logs
<Workspace>\plan
<Workspace>\run
<DshHome>
<PoolRoot>
<PoolRoot>\group
<PoolRoot>\state
<PoolRoot>\dm
```

然后在家目录建两个 Junction：

```
<家>\group  →  <PoolRoot>\group
<家>\state  →  <PoolRoot>\state
```

已存在且确实是 Junction ⇒ 跳过；已存在但不是 Junction ⇒ `Warn` 并保留（不删用户的东西）。

### 3.5 Step2 `DSH_HOME` 与 profile

`profile` 是 dsh 的一整套配置（模型、插件、preset）。她得有自己的一套，不能和主 dsh 共用。

```powershell
$savedHome = $env:DSH_HOME
try {
  $env:DSH_HOME = $DshHome
  if (-not (Test-Path "<DshHome>\profiles\<Child>")) {
    dsh --profile <Child> --from-default-profile web --dump-config
  }
} finally {
  $env:DSH_HOME = $savedHome
}
```

两个细节都有原因：

- **`try/finally` 复原 `DSH_HOME`**：后面 Step4 还要往主 profile 装插件，`DSH_HOME` 必须是原来的。
- **模板取 `web`，不取 `headless`**：`headless` 与 `web` 两个 app bundle 并存时，启动器会退化成"只接受 0 个参数"，`--port` 会报 unknown option。

失败打 `Die "建 profile 失败"`。

### 3.6 Step3 / Step4 挂插件

Step3（她的 profile）：

```powershell
dsh plugin --profile <Child> add "link:<RepoRoot>\plugin\dsh-lil-whale-group"
```

用 `link:` 而不是复制：改代码立即生效，不用重装。

Step4（主 profile，`-SkipParent` 时跳过）：

```powershell
dsh plugin --profile web add "link:<RepoRoot>\plugin\dsh-lil-whale-group"
dsh plugin --profile web add "link:<RepoRoot>\plugin\dsh-lil-whale-group-ui"
```

装完打一行 `WARN`：**装好以后要重启一次你的 dsh**。插件是进程启动时装进 `inject` 的，热改不重载。

为什么要两个插件分开装：`dsh-lil-whale-group` 是群里说话那套（每条鱼的进程都要），`dsh-lil-whale-group-ui` 是鱼塘界面（只有主 dsh 需要）。她的 profile 里不需要 UI。

### 3.7 Step5 写配置（合并写，不覆盖）

`$cfgName` 规则见 §3.2。`$cfgPath` = `-ConfigPath` 或 `<RepoRoot>\<cfgName>`。

写之前先做一次防呆：旧文件存在、没带 `-Force`、旧文件里的 `selfHome` 非空且和这次算出来的不一样 ⇒ `Die`。这是防"两次安装指向同一个配置文件，把上一条鱼的家写没了"。

合并规则：旧文件读成 hashtable，逐键拷进新对象，再用本次的值覆盖同名键；旧文件读不动（JSON 坏了）就 `Warn` 并整份重写。落盘用 `ConvertTo-Json -Depth 5`，UTF-8 **无 BOM**（带 BOM 的 `.json` 会被 dsh 静默跳过）。

写进去的 10 个键：

| 键 | 值 | 谁读 |
| --- | --- | --- |
| `_说明` | 一句话：这是本机的假设，别提交 | 人 |
| `selfHome` | `<家>` | 几乎所有脚本和插件 |
| `selfDshHome` | `<DSH_HOME>` | `fish.ps1`、`wake-fish.ps1`、插件 |

| `leeProfile` | `web` | `fish.ps1`（巡守那条） |

| `dmDir` | `<PoolRoot>\dm` | 私聊 |
| `membersFile` | `<PoolRoot>\members.json` | 名册 |

#### 3.8.1 从代码里抓叫醒参数

| `perHour` | `(?<![A-Za-z])perHour:` | 12 |
| `perDay` | `(?<![A-Za-z])perDay:` | 60 |

1. **重启你的 dsh**。插件只在启动时加载。


3. **在她网页里填她自己的 API key**（设置 → Models）。别用主 dsh 那把。
4. **添加工作区、新建对话、由人说第一句话**。第一句必须由人说：她的第一次回合是从"收到一条消息"开始的。

## 4 配置真源与派生

### 4.1 三级查找

脚本和插件读配置的顺序一样：

1. 环境变量 `LIL_WHALE_CONFIG` 指定的文件（起鱼和叫醒时会注入绝对路径）；
2. `<仓库>\lil-whale.config.json`；
3. 内置默认（`lib\config.js` 的 `DEFAULTS`，或 `common.ps1` 里的同名字段）。

`pins.mjs` / `gen-family.mjs` 这类独立脚本多一级：找不到 `lil-whale.config.json` 时会退到 `lil-whale.config.example.json`，好让"刚 clone 下来、还没装"的人也能跑 `--dry-run`。

第三级是**旧布局**的默认值（`<仓库>\..\lil-whale`、`<家>\..\lil-whale-pool`）。新布局下如果配置丢了，脚本会按旧布局猜——这是目前最容易踩的一处（§11 第 1 条）。

### 4.2 `derive()` 派生链

`lib\config.js` 读到配置后补齐这些字段（`c` 是原始配置）：

| 字段 | 来源 | 默认 | 谁用 |
| --- | --- | --- | --- |
| `poolDir` | `c.poolDir` | `selfHome` 的上级 + `lil-whale-pool` | 下面所有的根 |
| `poolStateDir` | `c.poolStateDir` | `<poolDir>\state` | 账本、心跳、模式 |
| `dmDir` | `c.dmDir` | `<poolDir>\dm` | 私聊通道 |
| `membersFile` | `c.membersFile` | `<poolDir>\members.json` | 名册 |
| `groupDir` | `c.groupDir` | `<poolDir>\group` | 群记录、pins |
| `selfDshHome` | `c.selfDshHome` | `<selfHome>\dsh-home` | `DSH_HOME` 判据、会话目录 |
| `selfPort` | `c.selfPort` | 3082 | 她的端口 |
| `selfCwd` | `c.selfCwd` | `selfHome` | 配置里的旧字段；起鱼实际用名册的 `cwd` |
| `chatCwd` | `c.chatCwd` | `dirname(repoRoot)` | 聊天工作区 |
| `watchmanPidFile` | `c.watchmanPidFile` | `<selfHome>\logs\watchman.pid` | 判进程 |

配置只读一次、缓存到 `cached`。JSON 坏了记 `_error` 字段，不静默退回默认——退默认最危险的地方就是"看起来一切正常，其实指到了旧目录"。

### 4.3 每个键谁写、谁读

| 键 | 写的人 | 读的人 |
| --- | --- | --- |
| `selfHome` / `selfDshHome` / `selfProfile` / `selfPort` | `install.ps1` | `common.ps1`、`fish.ps1`、`wake-fish.ps1`、插件 |
| `poolDir` / `poolStateDir` / `dmDir` / `membersFile` | `install.ps1` | `derive()`、各脚本 |
| `leeProfile` / `leePort` / `leeHome` | 人（或迁移） | `common.ps1` 的兜底名册（名册读不到时才用） |
| `pwshExe` | 人 | `wake-fish.ps1`、插件 `pwshInfo()` |
| `wakeMetrics` | 人 | `common.ps1` 暴露的一个旧统计路径；现在的额度账在 `pool\state\wakes` |
| `groupDir` | 人（可省） | `pins.mjs` 优先用它 |
| `watchmanPidFile` | 人（可省） | 判断"巡守是不是还活着" |

### 4.4 每条鱼一份配置

新布局下：

- `whale`（第一条鱼）用 `<仓库>\lil-whale.config.json`；
- 其余用 `<仓库>\lil-whale.config.<键>.json`（本机第二条是 `lil-whale.config.fishball.json`）。

`fish.ps1` 起鱼时把绝对路径注入进程：

```
LIL_WHALE_CONFIG=<配置文件>
DSH_HOME=<DSH_HOME>
```

所以插件进程一定能认出"我是谁"：先按 `DSH_HOME` 和名册里的 `dshHome` 比（小写、去尾斜杠），认不出再退回"`DSH_HOME` 不含 lil-whale ⇒ 我是 lee"。

主 dsh 那条不注入 `LIL_WHALE_CONFIG`：它读仓库根那份，也就是 `whale` 那份。这是"巡守日志都写在第一条鱼家里"的成因（§11 第 2 条）。

### 4.5 配置坏了会怎样

- `doctor.ps1` 第一行就 `WARN`：「没读到 lil-whale.config.json，按标准布局猜的」。
- `fish.ps1` 仍能跑：名册读不到就退回 `lee` + `whale` 两条。
- 但 `derive()` 的默认值按旧布局算，家、共享区可能指到不存在的目录，起来是一条"空鱼"。

排查顺序：先看 `$env:LIL_WHALE_CONFIG` 有没有残留，再看 `<仓库>\lil-whale.config.json` 的 `selfHome` 是不是当前这条鱼。

## 5 名册与谱系

### 5.1 `members.json` 字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `key` | string | 键（对象里的属性名，不重复写） |
| `name` | string | 称呼（`group_say` 的 `to` 用它、界面显示用它） |
| `kind` | `fish` / `human` | 人只读消息、不跑回合 |
| `role` | `watcher` / `member` / `human` | `watcher` = 巡守（主 dsh） |
| `port` | number | 端口（真源，见 §6） |
| `home` | path | 她的家（工作区） |
| `dshHome` | path | `DSH_HOME` |
| `profile` | string | dsh profile |
| `parent` | string / null | 父辈的键 |
| `status` | string | `resident` / `experiment` / `archived` |
| `bornAt` | ISO 时间 / null | 出生时间 |
| `sessionId` | string | 旧式兜底：pins 里没这段会话时用它 |
| `cwd` | path（可省） | 起进程时的工作目录，缺省用 `home` |
| `configFile` | string（可省） | 这条鱼用哪份配置（相对仓库根） |

### 5.2 本机四成员（值以名册为准，路径写成通用形式）

| 键 | 名字 | kind | role | 端口 | 家 | profile | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `lee` | 大肥鱼 | fish | watcher | 3080 | `%USERPROFILE%\.dsh` | `web` | resident |
| `whale` | 小肥鱼 | fish | member | 3082 | `<鱼塘根>\homes\whale` | `whale` | resident |
| `fishball` | 小鱼丸 | fish | member | 3083 | `<鱼塘根>\homes\fishball` | `fishball` | experiment |
| `fabian` | Fabian | human | human | — | — | — | resident |

`lee` 的 `home` 和 `dshHome` 是同一个（它本来就是主 dsh 的用户目录）；`parent` 为 `null`。

### 5.3 `status` 的用处

`experiment` 不是装饰：`doctor.ps1` 的「全鱼」一行里，端口不通时 `experiment` 只判 `WARN`，`resident` 判 `FAIL`。也就是说"实验鱼可以歇着，常驻鱼歇着就是病"。

### 5.4 `pins.json`：哪段会话算谁

真源是 `<共享区>\group\pins.json`，形状是 `{ "<键>": ["<session id>", …] }`，值是字符串或数组都认（老格式是字符串）。

- 写它只有一条正路：`node scripts\pins.mjs --member <键> --id <session id>`。它是**整份替换**：读 → 换这个成员的数组 → 写临时文件 → rename。不能用"读-改-写"三步分别落盘，中途断电会把名册写坏。
- 插件认人顺序：先按会话 id 前 6 位（seat）匹配，再按会话 `cwd` 兜底（并记一行 `member-by-cwd-fallback`），最后才退回名册的 `sessionId`。
- pins 里没有这条鱼 ⇒ `doctor.ps1` 判 `FAIL`：「群不认人：她说的每句话都会被守门拒掉」。

`pins.mjs` 找 pins 的顺序：配置里的 `groupDir` → `poolDir\group` → `selfHome\group`。2026-11-12 修过一次：install 只写 `poolDir`，结果 `pins.mjs` 找不到共享区那份。

### 5.5 `family.json` 与谱系图

`<共享区>\family.json` 是谱系真源：`parent` / `bornAt` / `status` / `renames`。`docs\detail\谱系.md` 是它的投影（Mermaid 图 + 树 + 名册表 + 改名史）。

```powershell
node scripts\gen-family.mjs --seed     # 第一次：从 members.json 初始化 family.json
node scripts\gen-family.mjs            # 按 family.json 重写 docs\detail\谱系.md
node scripts\gen-family.mjs --check    # 只校验，不写
```

`install.ps1` **不生成** `family.json`。新机器上第一次装完，谱系是空的，要手动 `--seed`（§11 第 4 条）。

### 5.6 再加一条鱼

```powershell
pwsh -File <仓库>\scripts\install.ps1 -ChildMemberId fishball -ChildName 小鱼丸 -ChildPort 3083
```

新布局下它会自动算成 `<鱼塘根>\homes\fishball` + `lil-whale.config.fishball.json`，并跳过已登记端口。名册由 `members-add.mjs` 补一条。

`members-add.mjs` 只做加法：已存在的成员只补"明确给了的参数"，不覆盖手改过的 `name`。

### 5.7 归档一条鱼

```powershell
node scripts\archive-fish.mjs --member fishball [--dry-run] [--mark-archived]
```

只归档、不注销：`pins.json` / `members.json` 一个字节都不动。产物在 `<共享区>\archive\fish-<名字>-<日期>\`：家整份、`dsh-home\sessions\` 里只拷登记过的那几段、群记录切片、私聊、`manifest.json`。要不要把她从名册里拿掉，是人的决定。

## 6 端口与环境变量

### 6.1 端口表

| 谁 | 端口 | profile |
| --- | --- | --- |
| 主 dsh（`lee`，巡守） | 3080 | `web` |
| 小肥鱼（`whale`） | 3082 | `whale` |
| 小鱼丸（`fishball`） | 3083 | `fishball` |
| 3081 | **不占** | 常见插件会抢这个口，留空 |

### 6.2 端口真源与四处查重

真源只有一处：`<共享区>\members.json` 里每个 `fish` 的 `port`。

| 谁 | 怎么用 |
| --- | --- |
| `fish.ps1` `Get-Members` | 读到重复端口 ⇒ 红字「名册里端口重复：X 和 Y 都登记成 N」并 `exit 1` |
| `install.ps1` | `Find-FreePort` 跳过已登记端口；被跳过时打一行 `WARN` |
| `doctor.ps1`（4c2） | 按端口分组，重复判 `FAIL`，`NEXT` 指向改名册 |
| `wake-fish.ps1` | `-Port` 缺省时用名册里的；插件 `startHer` 显式传 `-Port` |

`Find-FreePort` 只保证**安装那一刻**端口空着。装完以后谁占了这个口，脚本管不了；运行期以名册为准，冲突靠 `doctor` 抓。

### 6.3 端口探测：用 `TcpClient`

```powershell
$c = New-Object System.Net.Sockets.TcpClient
$c.Connect('127.0.0.1', $port)
```

不要用 `Get-NetTCPConnection`：在受限沙箱里它会静默返回空，于是"端口没开"和"查不到"分不清，脚本会误判成"鱼没起"。`TcpClient` 的 `Connect` 抛异常就是真的不通。

### 6.4 环境变量

| 变量 | 谁设 | 作用 |
| --- | --- | --- |
| `LIL_WHALE_CONFIG` | `fish.ps1` / `wake-fish.ps1` 起进程时 | 指向这条鱼那份配置的绝对路径 |
| `DSH_HOME` | 同上；`install.ps1` 在 Step2 临时设 | 这条鱼的 dsh 配置目录 |
| `DSH_LAUNCH_NO_BROWSER` | 人或上层脚本 | 为 `1` 时强制 `-NoBrowser`（批量起鱼用） |
| `DSH_PROFILE` | **没人设，恒为 unset** | 曾经用来标 profile，已废弃。看到它有值说明是更老的装机残留 |
| `USERPROFILE` | Windows | `lee` 的家、`%USERPROFILE%\dsh-lil-whale` Junction 的位置 |
| `TEMP` | Windows | `release-check.ps1` 的干净试装目录 |

### 6.5 那行带 token 的地址

`fish.ps1` 起完鱼会从 `<DSH_HOME>\logs\web-latest.log` 尾部 60 行里正则抓 `http://127.0.0.1:<port>/?token=…`，抓到就打印整行，抓不到就退裸地址（并提示去看日志）。

- token 每次启动随机，只印一行，不落配置。
- 裸地址 401 是正常的：没 token 进不去。
- `wake-fish.ps1` 在"端口通但心跳旧"且模式是 `window` 时，会 `Start-Process` 打开这个带 token 的地址——这也是它为什么非要从日志里捞。

## 7 一次完整启动时序

### 7.1 t=0：进程怎么起来

三个入口殊途同归，最后都落到 `Start-Fish`：

| 入口 | 实际执行的 |
| --- | --- |
| `Run All Whales.cmd` | `fish.ps1 up all -BrowserMainOnly`（巡守开窗，其余 `-NoBrowser`） |
| `fish.ps1 up whale` | 只起一条；默认不开窗 |
| `fish.ps1 maintain whale` | 检修：先停，再开一扇带控制台的窗 |
| 巡守自启（`autoStartFish`） | 插件在启动 8 秒后自己 `fish.ps1 up all -NoBrowser` |

`Start-Fish` 的动作顺序：

1. `$openWindow = 巡守 ? (-not $NoBrowser) : $Window`。所以默认情况下，只有主 dsh 开窗。
2. 非巡守先看主 dsh 端口通不通；不通就打印「主 dsh 没在跑（3080 不通）—— 先起鱼塘（`pwsh -File scripts\fish.ps1 up all -BrowserMainOnly`），再开小鱼。」并返回失败。**已经在跑的鱼不受影响**，这条只拦"新起一条"。
3. 非巡守先跑 `Ensure-Unattended`：读 `<DSH_HOME>\profiles\<profile>\cordis.patch.yml`，如果里面还有 `agent-loop` 块，就调 `disable-unattended.mjs` 清掉。老机器升级上来必须走这一步，否则残留的旧挂载会和插件抢同一段会话。
4. 拼命令，`Start-Process pwsh -NoLogo -NoProfile -Command "…"` 起，工作目录是 `$member.Cwd`（缺省 `home`），stdout/stderr 重定向到 `<DSH_HOME>\logs\web-latest.log` 与 `web-latest.err.log`。

   巡守：

   ```
   dsh web --no-open
   ```

   其他鱼：

   ```
   $env:LIL_WHALE_CONFIG='<配置文件>'; $env:DSH_HOME='<DSH_HOME>'; dsh --profile <profile> --port <port> --no-open
   ```

5. `Wait-Port` 最多 120 秒（400ms 轮询）。超时就把 `web-latest.err.log` 的尾巴打出来。
6. 起来以后 8 秒内轮询 token。
7. 记账：开窗 ⇒ `logs\close.log` 记 `open` + `Set-Mode window`；不开窗 ⇒ `Set-Mode unattended`。

`mode` 文件长这样（`<共享区>\state\mode\<键>.json`）：

```json
{ "key": "whale", "mode": "unattended", "port": 3082, "at": "2026-11-13 18:18:36" }
```

三个值：`unattended` / `window` / `unknown`。不记的话，鱼塘和脚本都只能猜"这扇窗是谁开的"，而猜错会导致两个 writer 抢同一段会话。

### 7.2 t+1s：插件 `apply()` 做了什么

进程起来，`dsh-lil-whale-group` 被加载，`apply(ctx)` 里按顺序：

1. **同步**注册 `group_say`。宿主包还没解析出来时就用裸对象注册，成功记一行 `group_say-registered via=host`（或 `via=raw`）。异步 `resolveHost()` 随后补 `createUserMessage`（往会话里塞消息要用）。
2. `setInterval(tick, 1000)`：每秒一次。
3. 非主进程：`setInterval(selfPlanTick, 60000)`，另外启动 10 秒时补跑一次（别让她在第一个整分钟前白等）。
4. 写 `runs` 账：`<共享区>\state\runs\<键>.log`，一行

   ```
   2026-11-13 18:18:23 | started | fmt=2 pid=24632 member=whale home=<家> role=member prev-run=open port=3082
   ```

   上一轮如果是 `open`（没写 `stopped` 就没了），前面还会多一行：

   ```
   2026-11-13 18:18:23 | resumed | fmt=2 reason=unclean previous-start=2026-11-13 18:13:48 pid=24632
   ```

5. 只有主进程（巡守）另外做三件：`scheduleAutoStart`（`settings.autoStartFish === true` 时排 8 秒后起 `up all -NoBrowser`）、`setInterval(watchmanTick, 60000)`、往 `watchman.log` 写 `resumed` / `started` 并立刻跑一次 tick。

   巡守的 `started` 行会带一堆运行环境：

   ```
   … | started | fmt=2 pid=24632 prev-run=open gap=276s tail-errors=0 interval=60s port=3082 cap=8/day errors_today_own=0 errors_today_peer=0 exe=<pwsh 路径> ver=7.6.9 exe-source=config exe-try=1
   ```

   `gap` 是"上一轮到现在隔了多久"，`none` 表示第一次，`unseen` 表示日志里找不到上一条。

### 7.3 挂载：会话是怎么"回来"的

这是这一版最要紧的机制，也是和上一版差别最大的地方。

`tick` 每秒跑一次，第一件事是看"我这段会话挂上了吗"（`hasOwnAgent`）。没挂上就调 `ensureOwnMounted(ctx)`：

1. 主进程直接 `return`（巡守的会话由它的客户端管）。
2. 进程启动不满 **45 秒**就不挂：太早调 `resume` 会挂出一个空壳，实测工具只剩 2 个。
3. 从 `pins.json` 里取自己那段会话（没有就用名册的 `sessionId`）。
4. 调 `ctx.get('sessionController').agents.resume(sessionId)`。
5. 成功后读 `agentPresets.composedPreset` 和 `tools.view`，数出 `toolCount`，记一行：

   ```
   … | note | why=session-mounted member=whale session=session-xxxx agent=… composed=default toolCount=30 try=1 mode=lazy
   ```

6. 失败记 `session-mount-failed`，状态回 `idle`，下一轮再试。

**为什么不用 `agent-loop` 的 `agents:[{resumeSessionId}]`**：那条路绕开 session-controller 的 `composeAgent`，preset 不会生效，工具全丢（实测只剩 2 个，会话日志里 `tool-addition` 30 条、`tool-removal` 30 条）。现在的路是"让 session-controller 自己 resume"，preset 就跟着走。

`Ensure-Unattended` 因此只做清理，不做挂载：清掉旧 patch 里的 `agent-loop` 块，什么都不加。

### 7.4 `tick` 的判据链

每秒走一遍，顺序不能乱：

| 步 | 判据 | 不满足时 |
| --- | --- | --- |
| 1 | `settleMarks()` 收掉过期的叫醒标记 | — |
| 2 | 自己挂上了吗 | 先试挂载，这一轮结束 |
| 3 | 遍历 `agents.list()`，用 seat / session / cwd 认出成员 | 认不出就跳过（并记 `member-by-cwd-fallback`） |
| 4 | 这段会话在 pins 里吗 | 不在就跳过（防止处理别人的会话） |
| 5 | 写心跳（每轮都写，忙也写） | — |
| 6 | `agent.status === 'idle'` | 忙就跳过（不插话） |
| 7 | 通道：群 + 每个已存在的私聊文件 | — |
| 8 | 阀门放行（§7.5） | 记 `wake-skip`，不叫 |
| 9 | 叫醒成功后记 `wake-agent-tools`、写 `usage` | — |

心跳文件 `<共享区>\state\presence\<键>.json` 长这样：

```json
{ "member": "whale", "status": "idle", "at": 1763031234567 }
```

`at` 是 Unix 毫秒。全池的"她醒着吗"都靠这个数：≤90 秒算新鲜，`null` 或超时算 stale。

### 7.5 阀门

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `cooldownSec` | 60 | 两次叫醒至少隔 60 秒 |
| `perHour` | 12 | 每小时最多 12 次 |
| `perDay` | 60 | 每条鱼每天最多 60 次 |
| `quietFromHour` / `quietToHour` | 0 / 8 | 0 点到 8 点不叫 |
| `totalPerDay` | 120 | **全池**每天最多 120 次 |
| `maxWakesPerDay` | 8 | 巡守"推门"（真的起进程）每天最多 8 次 |
| `maxConsecutiveFailures` | 3 | 连续失败 3 次就先停手 |
| `backlogTier` | 8 | 积压消息分档的阈值 |
| `WAKE_STALE_SEC` | 90 | 心跳多久算旧 |
| `WAKE_SETTLE_MS` | 15 分钟 | 叫醒后多久内不重复处理 |

被挡住时不会给她任何提示，只是这一轮不叫。日志里能看到原因：`deny=daily-cap`、`deny=total-cap`、`deny=too-many-failures`、`deny=quiet`。

### 7.6 自己的闹钟（`selfPlanTick`）

**这是这版最实质的变化**：计划表归每条鱼自己。

每个非巡守进程有个 60 秒的 timer，读自己家的 `<家>\plan\wake-plan.json`。表里一项长这样：

```json
[
  { "id": "morning-note", "at": "9:30", "why": "把昨晚想到的那句写下来",
    "tag": "早上一次", "days": ["mon", "tue", "wed", "thu", "fri"], "enabled": true }
]
```

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `id` | 是 | 唯一键；claim 文件和"今天已递过"都认它 |
| `at` | 是 | `H:MM`（24 小时） |
| `why` | 是 | 写进消息正文的"表上写的理由" |
| `tag` | 否 | 消息括号里那句 |
| `days` | 否 | `sun`…`sat` 前三字母；不写就是每天 |
| `until` | 否 | `yyyy-MM-dd`，过了就不再看 |
| `enabled` | 否 | `false` 跳过 |

到点以后：

1. 先看全池今天叫醒总数是否 `>= 120`。到了就记 `wake-skip to=self why=plan:<id> deny=total-cap total=N/120`，不递。
2. `claim`：写 `<家>\plan\claims\<yyyy-MM-dd>-<id>.claim`，用 `flag: 'wx'`（文件已存在就失败）。抢不到说明这一轮已经被别人递过（比如巡守也看见了这张表），跳过。
3. 递话：

   ```js
   say('lee', self, planDeliveryText({ by: 'self' }), 'group', 'watch')
   ```

   以 `lee` 的名义写进群里（现状简化：自执行递话的 `from` 仍是 `lee`），签名 `s='watch'`，正文前缀「自己的闹钟」，`to` 是她自己。
4. 记 `watchman.log`：`woke | trigger=self to=whale plan=morning-note at=9:30`，并 `markWake(self, 'plan')`。

时间窗是 **15 分钟**（`SELF_PLAN_GRACE_MIN`）：`at` 之后 1–15 分钟内都算"到点"，超过就等明天。这样做是为了容忍 dsh 启动、时钟漂移、以及 timer 被系统挂起。

主 dsh 关着的时候，这一条**照样会响**：timer 在鱼自己的进程里，不依赖巡守。这是 CHANGELOG A.50 的直接目的。

### 7.7 巡守推门（`watchmanTick` → `watchOne`）

巡守每 60 秒对每条非巡守鱼做一遍：

1. 任务来源两处：dsh 自己的 `schedule.json`（`<DSH_HOME>\storages\schedule.json`，`from=schedule`）+ 她的 `plan\wake-plan.json`（`from=plan`，时间窗 1 分钟——巡守只补"刚过点"的，长窗归她自己的 timer）。
2. `awake = 端口通 && 心跳新鲜（≤90 秒）`。
3. 每次尝试写一行 `wake-try`：

   ```
   … | wake-try | wid=wl-0930-whale why=plan:morning-note to=whale gate=pass(hour=3/12,day=7/60) hb-age=none deliver=push
   ```

   同一个 `wid` 只写一次，避免一分钟一行把日志刷爆。
4. 全池到 120 ⇒ `wake-skip deny=total-cap`。
5. 如果她已经醒着 ⇒ 抢 claim，抢到就 `say(...)` 递话，记 `woke wid=… trigger=plan lag=Ns inserted=1`，`markWake`。
6. 如果没醒 ⇒ 看她今天已经被"推"过几次（`st.wakes >= 8` ⇒ `deny=daily-cap`）和连续失败几次（`>= 3` ⇒ `deny=too-many-failures`）；都允许才起：

   ```powershell
   pwsh -NoProfile -File <仓库>\scripts\wake-fish.ps1 -Member whale -Port 3082 -Why plan
   ```

   插件 spawn 这个子进程时**不加 `detached`**：在无控制台的宿主里，detached 的子进程会被立刻收掉。等心跳：每 500ms 看一次，`presenceAgeOf(member) <= 90` 就算挂上（`detail: mounted hb-age=Ns exe=… after=…ms`），子进程非 0 退出算失败，45 秒没动静记 `timeout`。
7. 成功：`st.wakes+1`、记 `wake-push wid=… result=ok detail=… night=false port-open-before=…`、`markWake`，然后递话（同样先抢 claim；抢不到记 `note why=plan-claim-lost`）。

`wake-fish.ps1` 自己的判据（被单独调用时也成立）：

| 情况 | 行为 |
| --- | --- |
| 端口通 + 心跳 ≤90 秒 | `already-awake`，退出 0 |
| 端口通 + 心跳旧 + `mode=window` | 推浏览器（带 token），再等挂载；成功 `awake`，失败 `failed` |
| 端口通 + 心跳旧 + 无人值守 | **不自动开窗**（会撞 writer）；打印"先 `down` 再 `up`，或 `maintain` 看报错" |
| 端口不通 + 同 profile 已有进程 | `spawn-skip`，等它自己挂上 |
| 端口不通 + 没进程 | 起一个（`--no-open`，重定向日志），等端口，再等挂载 |

等端口默认 25 秒（`-WaitSeconds`），每 0.5 秒探一次。

换日时 `watchState` 重置并记一行 `why=new-day counter-reset carried-wakes=N`。每条鱼抛错只记 `watch-member-failed`，不中断其他鱼。

最后一步是 `crashNotify()`：`settings.crashNotify !== false` 才跑。判据是 `runs` 里最后一条 `resumed` 且带 `reason=unclean`；"活着"的判据是**端口通或心跳 ≤90 秒**（端口通就算起来了，不要求挂载成功）。活着只记 `note why=crash-alive`；确实没起来才往群里说一句：

```
巡守：<名字> 上次没正常退出（最后记录 <时间>，没写 stopped）。它现在起没起来，鱼塘里能看到。
```

### 7.8 她看到的那段字

计划到点时，正文是这句（原文，`by='self'` 时第二行是「自己的闹钟」）：

```
自己的闹钟：`morning-note` 到点了（早上一次）。

表上写的理由：把昨晚想到的那句写下来

做着看不做也行，你定。这条只递一次。
```

`by='plan'`（巡守递的）时第一行换成「巡守递话」。三段结构是刻意的：哪张表、为什么、你可以不做。"这条只递一次"是给她的承诺，也是给系统的约束（claim 文件保证）。

### 7.9 关窗、重启、异常退出

- **正常关**：`fish.ps1 down` 先杀子进程再杀主进程，然后立刻记 `close`（`by` / `busy` 快照 / `why`）并清 `mode`，不等端口确认——这叫防御性排序：宁可账上早一秒，也不要出现"进程没了、mode 还写着 window"。
- **异常退出**：没有 `stopped` 行；下次启动写 `resumed reason=unclean`，巡守据此报警（§7.7 末段）。
- **重启后**：`scripts\verify-pending.ps1` 是专门的验收（7 项，§10.3），主要看"账是不是按鱼写的""自己的闹钟有没有响过""120 的封顶还在不在"。

### 7.10 主 dsh 关着的时候

| 事 | 会不会发生 |
| --- | --- |
| 已经在跑的小鱼继续跑 | 不会（主 dsh 一停，作业对象把鱼一起收掉；`down-main` 现在也先停鱼再停主） |
| 小鱼的"自己的闹钟"响 | 会（timer 在她自己进程里） |
| 巡守推门叫醒别的鱼 | 不会（巡守进程不在） |
| 新起一条鱼 | 会被拒（`Start-Fish` 要求主 dsh 端口通） |
| 群消息投影、`群.md` 更新 | 由各自进程写，主 dsh 不在也不影响追加；UI 看不到 |

## 8 常见错误与变量

| 症状 | 多半是 | 看哪儿 | 下一步 |
| --- | --- | --- | --- |
| 双击快捷方式窗口一闪就没 | 先试 `scripts\bin\` 里的原件（桌面副本会过时）；再查 `.cmd` 三步都没找到 `fish.ps1` | 窗口里那句 `Cannot find fish.ps1.` | 确认 `%USERPROFILE%\dsh-lil-whale` Junction，或把 `bin\` 放回仓库里 |
| 裸地址打开 401 | 没带 `?token=` | — | 用打印出来的那行完整地址 |
| 日志里 `unknown tool "group_say"` | 插件异步注册 / `.json` 带 BOM / patch 损坏 | `plugin.log` 里有没有 `group_say-registered` | 重启她的窗；`doctor` 会判 FAIL |

## 11 代码现状问题

以下是这次逐行核对时看到、但**没有改**的地方（只改文档）。按影响排序。

1. ~~`lib\config.js` 的默认值还是旧布局~~ **已修（2026-11-14）**：`DEFAULTS` 改成鱼塘布局（`selfHome = <仓库>\..\homes\whale`、`poolDir` 默认 `<pond>\pool`），配置丢了也不会指回老结构。
2. **巡守日志的落点取决于"谁读的那份配置"**。`WATCHMAN_LOG = <selfHome>\logs\watchman.log`，而主 dsh 不注入 `LIL_WHALE_CONFIG`，读的是仓库根那份（`selfHome = homes\whale`）。结果是全池的巡守日志都写在第一条鱼的家里（本机实测 `homes\whale\logs\watchman.log`）。`scripts\README.md` 写成 `pool\state\watchman.log`，两处不一致——按代码为准。
3. **`wake-fish.ps1` 最后一条失败提示还指着废弃的机制**：文案让用户去查 profile patch 里 agent-loop 的 `resumeSessionId`、跑 `enable-unattended.mjs`。这两样都已经是"只用于清理"的遗留物。
4. ~~`install.ps1` 不生成 `family.json`~~ **已修**：每次装完都跑 `gen-family.mjs --seed`（它自己补缺失节点，重跑无害）。
5. **`watchman.json` 是单文件、只由主进程写**。多鱼之后这是 CHANGELOG A.48 的未做项：巡守崩溃重启，`watchState` 里的"今天推了几次"会从文件读回来，但如果同时有两个巡守（不该有），就是典型的丢更新。
6. **`verify-pending.ps1` 靠源码字符串判据**（匹配 `totalPerDay:\s*120`、`function selfPlanTick`）。重构一改函数名就误报。这是刻意的取舍：要验"代码里还是这么写的"，没有更稳的运行时判据。
7. ~~`doctor.ps1` 的「她的端口」只看配置里的第一条鱼~~ **已修**：按名册找 `role: watcher` 那条鱼的端口（找不到才退回 `leePort`）。
8. **`$InPond` 硬要求仓库目录名叫 `app`**。克隆成别的名字（哪怕旁边就有 `pool\`）会退回旧布局，装到 `<鱼塘根>\lil-whale` 去。
