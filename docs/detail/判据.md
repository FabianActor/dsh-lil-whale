# 判据与名字

> 这份文件收的是**判据怎么写、名字怎么起**这一层规矩。不是产品需求（那在 PRD 里），是工程判断的尺子。
> 来源：2026-11-11 一天里连续踩出来的坑，多数由小肥鱼从日志里翻出来，大肥鱼补充。凡是她先说的，标「小肥鱼」。
> 用法：写一条日志、一个字段、一个文件名之前看一眼；出事故之后回来补一条。

## 一、总纲

**一个判据不合格的标志，是它错的时候跟它对的时候长得一样。**（小肥鱼）

推论分两半用：

- **上线前想一次**："它错了会长什么样？"想不出来就先上线——别把一个想不出失败形态的检查当闸。
- **出错之后必须补一次**：如果事故已经发生、判据却没拦住，说明它缺了一维，补上。

## 二、名字

### 2.1 三类会撒谎的名字

| 类别 | 例子 | 它断言什么 | 缺什么会变假 |
|---|---|---|---|
| **量词** | `total` / `all` / `never` / `always` | 整体 | 缺"谁的整体" |
| **状态词** | `ok` / `done` / `success` | 结果 | 缺判据（`ok` 后面不跟依据，什么都没说） |
| **相对词** | `first` / `prev` / `last` / `next` | 位置 | 缺参照系 |

**最小的尺子（小肥鱼）：写下任何一个名字时问一句「它和什么比？」** 答不上来，就是上面某一类缺了东西。

不在这三类里的名字（`cursor.json`、`wake-plan.json`）只是标签，不用证伪。

### 2.2 删掉法：判断它是断言还是标签

删掉它，有没有人读到的东西变少？变了是断言，没变是标签。

**但这个测试有个陷阱（小肥鱼）**："没变"有两种原因，长得一模一样：

- 它是标签（没人在乎）
- 它是**死的**（本来就没人读）

所以要跟第二问，而且**不能靠想，只能去 grep**：**现在有人读它吗？**

### 2.3 状态词必须紧挨着判据

`woke ok` 里的 `ok`，如果不跟着 `why=port-open`，它什么都没说。**判据离开名字，名字就只是安慰。**

## 三、名字的期限

**名字记的是写它时的世界，读数的人拿到的是读它时的世界。** 两者不一致时，错的不是名字，是没人在世界变化时回头改它。

今天的具体案子：`errors_total` 只有一个写者的下午是真的；第二个进程起来之后，它变成"最后写的人的数"。世界变了七个小时，名字没人改。

**体检不按日期做，按事件做。** 每次世界变动（加进程、多一把椅子、开一条渠道），在**那次改动的记录里**加一行：

```
受影响的名字：errors_total（现在是谁后写算谁）
```

不另建清单——写在改动记录里，跟着那次改动走。

### 缺省值必须被定义（小肥鱼，2026-11-12）

加 `fmt=2` 那天，旧行**没有** `fmt` 字段。不写明默认值，读的人会把所有历史行扔进一个"未知"桶——**而那个桶最后没人敢动**。

所以在文档里写死一句：

```
watchman.log 里没有 fmt 字段的行 = fmt=1
```

**版本字段的价值不在"新版能标自己"，在"旧版能被认出来"。** 同理，任何"新增字段"的改动，都要同时回答两个问题：新值长什么样，**缺省时算哪个值**。

## 四、存与算

**能算出来的，就不该被存下来。** 存下来的都是"上一次算的"，而"上一次"是谁的上一次，可能又说不清。

- 分账（每人/每进程一份）是对的
- 但账分了之后，**"更粗的问题"的答案必须是查询，不是字段**（小肥鱼）——再加一个 `errors_all` 就是把同一个坑换个名字再跳一次
- 查询要有**窗口定义**，窗口是定义的一部分，不是实现细节

## 五、窗口

**窗口要钉在事件上，不钉在状态上。** 事件是既成事实，改不了；状态是每时每刻的当前值，谁后写算谁。

例：`state\watchman.json` 里的 `day` 是状态；日志里 `... | note | why=new-day counter-reset` 那行是事件。**"今天"= 最后一条 `new-day` 之后。**

**但 2026-11-12 小鲸鱼把这条改得更硬了**：她数出 `new-day` 在 11-12 有三条、11-09 也有三条 —— 「每天恰好一行」这个前提本身就不成立（三个进程各写一次、或同一份旧状态被反复读到）。
所以窗口不要钉在那行上，**钉在行首日期上**：`^2026-11-12`。理由和「按天切文件，文件名就是窗口」是同一条 —— **数据自带的东西不需要额外定义，也就不会有一行没一行。**
（那行 `new-day` 现在加了 `pid=`，它仍然有用：用来说明"这天的计数是什么时候被重置的、谁重置的"，但不再承担"窗口"这个职责。）

**最好的窗口定义，是根本不需要定义**（小肥鱼）——按天切文件之后，文件名就是窗口。真要切的时候，别按"文件太大"切，按"我想让窗口变成文件名"切。
（代价：跨文件的问题又需要一个新定义，所以切的粒度要跟问题的粒度对齐。）

## 六、"不可答"不是一种状态，是三种（小肥鱼）

| 不可答的原因 | 该做什么 | 留下的证据 |
|---|---|---|
| **口径未定义**（"错"指什么） | 改问题 | 有埋点的名字，但没有口径 |
| **没记**（没人埋点） | 补埋点 | 连名字都没有 |
| **记了但丢了**（硬切、被覆盖） | 修耐久性 | 有过数，现在断档 |

三者留下的痕迹不同 ⇒ 可以按证据分，不用猜。只写"不可答"，下一个人会一律当成第一种，然后一路改问题——**而第二、三种，改问题没有用。**

## 七、改写问题必须留原问法

把"今天错了几次"改写成"今天记了几条 error"是对的，但危险在于：**改写做得很顺，下一个人会以为原问题被回答了。**

所以与被改写后的数字并排放两行：

```
原问法：今天错了几次 —— 不可答（口径未定义）
可答问法：今天记了几条 error = 日志 error 行数，窗口 = 最后一条 new-day 之后
```

这和 `pre-mortem` 是同一个位置问题：**"改过了"和"没问过"在纸上长得一样。**

## 八、留痕的位置

**留痕按"谁会撞上它"来选，不按"哪里方便写"来选。**

- `pre-mortem` 写在判据旁边（未来判定"算不算没想过"的人只会看判据）
- 清锁记录要写进**新的锁文件**（被清的人不会去查日志，他只会撞上锁）
- `affected names` 写进 commit 正文（看改动的人会看那里）

## 九、造失败要用真料，且自带身份

- 构造数据造出来的失败，和真故障长得一样 ⇒ 造的时候用真料
- **能用的假，必须自己说是假的**（`dry-run` 标记、自己目录、日志明写）

例：`why:'自检：验"主机开着、她关着窗"这条路径（跑完就删，不是给你的安排）'`——小肥鱼认这是正面样本：自带身份、自带到期、跑完自己消失。

## 十、物理层的一个同族案子（`lost update`）

同一个文件、两个写者、都"读整份→改一格→写整份" ⇒ 后写的盖掉先写的。
**两个写者要么分片（各写各的），要么只追加。** 进程能被观测（`pid` + 启动时刻），会话不能被观测（只能心跳 + 单调伴生量）。
**易变量必须配单调伴生量**（`beat` 配 `step`、`pid` 配启动时刻、`exit=0` 配端口通不通）；而 `step` 不能由心跳自己 +1，必须由"事情"推进。

## 十一、切分能造出一个断言（小肥鱼，2026-11-11）

按天切日志之后，`watchman-2026-11-11.log` 里**只该有 11-11 的行** ⇒ "文件名与内容一致"变成一条能自动验的断言：某天文件里冒出别的日期，本身就是 bug 信号，不用人记得去查。

**切分不只是省事，它把一条隐含约定变成了可验证的断言。** 同族的第二件事：`rev` 把"谁先写"变成可验，切分把"哪天的"变成可验。

代价照旧要记：切到天就只能回答"某天"，回答"总量"得回到扫全部文件——**窗口没有消失，它从参数变成了文件集合**，所以切的粒度要跟问题的粒度对齐。

## 十二、规则自己要带证据（小肥鱼，2026-11-11）

这份文件是**源头**（不可重建、只能人维护），比结论更容易烂——它会跟实践脱节，最后变成一份"信念文件"。

所以每条规则后面必须跟一句：**它在哪件事上验过一次**（日期 + 日志行 + 当时错的样子）。

> **没有事故的规则，可能是想象出来的规则。**
> **用一条没有事故的规则，等于用一个没验过的判据。**

证据索引（缺的一栏标「未验」）：

| 规则 | 验过它的那件事 |
|---|---|
| 总纲：错的时候跟对的时候长得一样 | 2026-11-11 `gap=first`：读作"从头开始"，实际是"尾部 4KB 全是 error，看不见上一行正常记录" |
| 量词缺整体 | `errors_total=611` 而 error 行 1225 条——611 是最后写它的进程的数 |
| 状态词缺判据 | 2026-11-09 推门四轮：`exit=0` / `already-awake` 都不代表门真的开了 |
| 相对词缺参照系 | 2026-11-11 `gap=first`：缺的是"相对于谁"（"同上"本身就是个缺参照系的相对词——这行原来就是它自己的现场演示） |
| 删掉法两种失败 | 2026-11-11 我对 `ui-read.json` 凭印象说"是标签"，grep 完发现它被读被写、是断言 |
| 名字的期限 | `errors_total` 单写者时是真的，第二个进程起来后变假，中间隔了七个小时 |
| 存不如算 | 611（存下来的）vs `grep -c '\| error \|'` = 1225（算出来的） |
| 窗口钉事件 | ~~`new-day counter-reset` 每天恰好一行~~ → **订正 11-12**：这行不是每天一条（11-09、11-12 各三条），窗口改钉**行首日期** |
| 不可答分三种 | "今天错了几次"=口径未定义；EPERM 1225 行=记了（有痕迹）；**记了但丢了**=游标 108 被另一进程整本写回成 107、或 `errors_total` 曾经存在后来成了别人的数 |
| 改写留原问法 | 同上（把"错几次"改写成"几条 error"那次） |
| 留痕按谁会撞上 | 清锁记录写在新锁文件里（撞锁的人不查日志）；`pre-mortem` 写在判据旁 |
| 造失败要真料 + 自带身份 | 2026-11-11 19:59 `selftest-wake` 演练：`why` 写明"自检、跑完就删、不是给你的安排" |
| `lost update` | 2026-11-11 11:02–17:51 EPERM 1225 行 + 她报"同一条消息叫醒两次" |
| **体检按事件做** | **等着被验** —— 触发条件：下一次世界变动（加进程 / 加椅子 / 开一条渠道）时 |
| **切分造断言** | **等着被验** —— 触发条件：日志大到要按天切的那天 |

## 十三、回读的判据是"差多少"，不是"看起来对"（小肥鱼，2026-11-11）

"改完回读一遍"是对的，但回读需要一个**期望值**，否则它只是"再看一眼"。残骸落在文件尾能被发现，是因为读到了不该有的东西；**落在中段、内容又通顺，一眼扫过去就看不见了——再看一眼，很容易看见你想看见的。**

所以判据是：**改之前记下长度 / 行数，改之后比差值。** 说"删了一段、加了一段"，就该有个预期的增减；差得多出来，就是残骸。

> **改动的判据不是"看起来对"，是"差多少"。** 预期差能被证伪，"看起来对"不能。

（本条已验：2026-11-11 20:14 改本文档 §12 时把 §10 的正文留在文件尾，靠行数回读发现；随后给两条规则补触发条件那次，行数 155 → 155、与原预期一致。）

## 十四、规则怎么留：推翻 / 补充 / 澄清（小肥鱼指出缺的一节，2026-11-11）

这份文档有"名字的期限"（名字会过期），有"规则要带证据"（规则要验过），但原来缺一条：**一条规则被证伪了之后怎么留。**

今天的两次推翻，都不是补充：

| 旧的 | 被谁取代 | 为什么 |
|---|---|---|
| `prev`（存"上一条"） | `rev` + `sha` + CAS | 存下来的"上一条"会自己长成一条链，而且没法和"读到的是不是同一版"对上 |
| "一个人两本账"（两把椅子并立） | 一把椅子、一本账 | 一个人在另一把椅子上说过的话就可以不算数了吗——不能，所以椅子本身就是那道缝 |

**做法：规则作废时保留原文、标「已作废」、写清被哪条取代、为什么。不要删掉重写。**

理由跟当初留 `watchman.log.dryrun-3099` 那个文件一样：**删掉之后"当初为什么会错"就断了**，而下一个人会重新踩一遍。这份文档是**源头**（不可重建），删掉的东西没有备份。

格式：

```
> ~~原规则~~
> **已作废（2026-11-11）：** 被「新规则」取代。
> 原因：……
```

**判断这是哪一类，看旧产物怎么办：**

| 类别 | 旧产物 | 要留什么 |
|---|---|---|
| **推翻** | 还会被读、被跑、被引用的东西**必须改** | 作废说明 + **分界标记** |
| **补充** | 旧的照用，只是多一条 | 证据（在哪件事上验过） |
| **澄清** | 规则没变，只是把某个读法钉死 | 写清"原来可以怎么读、现在只能怎么读" |

**范围限定（小肥鱼，2026-11-11）："必须改"指活的东西，不是已经写下的历史。** 只追加的日志里按旧规则写下的行**不动**——改了就是篡改历史，跟"不删掉重写"是同一条。但要在文档里说一句："历史里还有按旧规则写的东西。"

**推翻必须带分界标记（小肥鱼）。** 推翻之后，文件里会同时躺着两个世界的写法，而且它们长得一样：`errors_total=611`（旧）和 `errors_own= / errors_peer=`（新）并存，下一个人一加就把两个世界混在一起算。所以除了"为什么变"，还要写"**从哪儿变**"——commit、时间点、或者日志里第一个新格式的行。**没有分界，作废说明只解释了为什么变，没解释从哪儿变。**

**澄清最该留痕，因为它最不像改动。** 没人会为"我只是把话说清楚了"写一条记录，可下一个人读到的可能是钉死之前的版本，然后按那个版本继续含糊下去。（本文件里属于澄清的：§5 窗口钉事件、§8 留痕位置、§13 回读的判据。）

## 十五、守卫的判据要问"改没改成"，不要问"改动像不像发生了"（小肥鱼，2026-11-12）

这条是 §一总纲的一个特例，但它栽的地方不一样：**不是"读的时候用错东西"，是"写之前用错东西"。**

2026-11-12 她给简报修补脚本加守卫，第一版是"结果必须比原文长"。它**拒绝了一次合法的修改**——那次改法是把一句长话换短。

> **"变长了"不是"改对了"。我又拿一个便宜的代理当判据。**

现在的守卫是三条同时成立：`新文本在` + `旧文本不在` + `结果长度 > 3000`。前两条直接对着"改没改成"问；第三条只是防"整份被清空"的兜底，不是"改对了"的证据。

**为什么长度、字节数、行数都只是"像不像"：**

| 代理 | 它其实在问 | 它在哪种情况下会骗你 |
|---|---|---|
| 结果比原来长 | "看起来写进去了" | 合法的缩短、去重、换措辞 |
| 行数变了 | "看起来动过了" | 整份重排、加空行 |
| mtime 变了 | "看起来写过了" | 写了空值（0 字节的 mtime 也是新的） |
| 脚本打印"已改为…" | "看起来脚本跑过了" | 脚本拿到的是 `null` |

**这跟"以近代远"是同一族**：拿一个便宜、可枚举、在"对了"和"错了"两种情况下都拿得到的东西当判据。长度在成功和失败时都会变；mtime 在写对和写空时都会更新。

**可用的判据长什么样**（都是"直接问"）：

- 新文本在不在？旧文本在不在？（"改没改成"）
- 写完之后文件不是 0 字节？（"写没写进去"）
- 正文时间戳与 mtime 的差 ≤ 1 分钟且不为正？（"写的是不是现在"）
- 至少有一个来自文件系统、不是自己写的数字能对上？（mtime / 字节数 / 行数——**用它们对账，不用它们当证据**）

**一个便宜代理也不是不能用，但要说清它是代理。** 她 §5 自检第 5 条就是这么用的：拿 mtime/字节数"对账"，而不是"证明"。

**为什么这条非要机械化（小肥鱼，2026-11-12）**：她刚把"时间戳不许超前"写进自检第 4 条，十几分钟后写 `notes\交接.md` 又超前了两分钟。

> **规矩写进文件，不等于我会照做。提醒是给会记得的人用的，判据是给会忘的人用的。**

所以凡是"每次都得记着"的动作（取时间、校验非空、写前重取证据），都要落成脚本或守卫，而不是落成一句提醒。

## 16. 前瞻文档必须能表达"还没发生"（2026-11-12）

**交接文件（`notes\交接.md`）的写作时刻，必然早于它描述的那次搬家。** 它不是记录，是**前瞻文档**——写给"搬过去之后的那个人"的第一张纸。

前瞻文档有个结构性难题：**它必须能表达"还没发生"。** 两种常见的写法都在默认撒谎：

| 写法 | 谎称什么 | 为什么骗得过去 |
|---|---|---|
| 「最后一件事：（见下）」 | 下面有对应条目 | 读者看到"见下"会往下找，找不到时先怀疑自己没看仔细 |
| 「11-12 15:20 前后搬段」 | 那个时刻已经确定/已经发生 | 具体数字看起来比"下午"更可靠 |

小肥鱼 2026-11-12 的改法是把**状态写进值本身**：

- `最后一件事：未填`——并注明"这一行由上一段在搬段那一刻写；空着就说明你拿到的是一份搬之前的版本"。于是"空"不是缺陷，是**可读的状态**。
- `2026-11-12 下午搬段`——只写到不会错的精度。

**判据**：一份前瞻文档能不能回答"你现在看到的是搬前还是搬后"。答不出来，它就在用"具体"冒充"准确"。

同族：§15（长度是"像不像"不是"是不是"）、§8（缺省值必须被定义）。空值不定义，就等于让读者去猜"这是没填还是填了空"。

**机械化**：这条规矩她自己写进自检第 4 条之后仍连犯三次（页脚写未来时间），最后做成 `run\stamp.ps1`——取"写之前的当前时刻"、写完复核差 ≤ 0、超标 `exit 1`。她的原话：

> 规矩写在文件里，我照样犯；写成一条命令，我就犯不了。

**判据也会过期（小肥鱼，2026-11-12）**：她原本写"看「最后一件事」那一行是不是空的"来判断这份交接是搬前还是搬后。填完之后这句就失效了——

> **"空"这个判据只对"填写前的那一版"成立，而那一版已经不存在了。**

所以判据要跟着它描述的状态一起换：现在的写法是"写的是不是具体的事：写 `未填` = 搬前，写了事 = 搬后"。**一个判据的有效期，通常等于它所依赖的那个状态的寿命。** 状态变了，判据不是"还能用"，是"已经没用了"。

## 17. 引文有保鲜期，而且比它所引的东西更短（2026-11-12）

她 15:48 把自己那句"通过"降格成"待验"，理由是：

> **"原文"这个词，只在"贴出来那一刻"成立。**

文件改了，引文不会跟着改；引用的人也不会回头补一句"那句作废了"。所以"我看到了原文"永远只意味着"我看到了**某一刻**的原文"。

同族：§16（前瞻文档必须能表达"还没发生"）、`fmt` 缺失、`s` 空着、时间戳超前——**都是"有一个没写出来的时刻"**。

判据的写法：把对象从"引文"改成"文件本体"。

> 等她手回来，第一件事：读 preset 那一行的**文件本体**，看第一个动词是 `can` 还是 `are`。读到之前，"通过"撤回，改成"待验"。

她的补充（值得记）：**"我今天说'通过'说过几次，只有一次是拿数说的。"** —— 判据不是让结论变好听，是让结论有出处。

## 18. 「待验」和「看不见」是两个状态（2026-11-12）

她 15:53 说的，原话：

> **待验**：我有一个能判的对象，还没判。
> **看不见**：我连对象都没有。

- 前者是**我的问题**（该读没读、该算没算），可以催自己；
- 后者是**通路的问题**（读不到、没权限、被截断、工具被收走），催自己没用，只能修通路。

**别把两种混成一句"还没验"**——混了以后，"看不见"会被当成"偷懒"，而"待验"会被当成"环境问题"，两种都失去处置方式。

写法上的区分：待验写"我没读 / 我没算"；看不见写"我读不到 / 被截断了 / 没有那个文件"。

同族：§17（引文有保鲜期）、§16（前瞻文档必须能表达"还没发生"）。这三节都是同一件事的不同面：**结论要带上它赖以成立的那个时刻和那条通路。**

## 19. 读到「还没有」时，要记下读到的是哪一刻（2026-11-14）

她 08:41 出头读 wake 账本，报「缺 `wake-skip` 和 `trigger=manual` 两条样本」；08:41:20 账本上就写下了第一条 `wake-skip`（`deny=already-delivered`）。她 08:49 复核后自己写的原话：

> **「样本还没到」和「样本不存在」，在纸上长得一模一样**——所以加了一条自检：**读到「还没有」时必须记下读到的是哪一刻，到秒。**

- 这条不是关于账本的，是关于**所有「我查了，没有」的结论**：查的时刻不写，结论就无法和「后来才出现」区分。
- 现场那两行：`08:40:20 wake-try/woke`（同一个 `wid`）→ `08:41:20 wake-skip`（同 `wid`、`deny=already-delivered`）。她读账时只看见前两行。
- 写法：**「截至 HH:MM:SS，没有」**，而不是「没有」。带秒是因为账本本身按秒写，差一分钟就换了一个结论。

### 19.1 再硬一层：给「没有」配游标，不只配钟点（她 08:50 补的）

> "我 08:41:03 查了，没有" 仍然留着两个洞：**我的钟和日志的钟不是一块表**；而且 **08:41:03 之后有没有，这句话管不着**。

更稳的写法是钉在**文件状态**上：

> 读到 `watchman.log` 第 **N** 行、末行 `ts=08:40:20`、文件 `size=S`，**没有 `wake-skip`**。

这样下一个人复现时不用信我的表，只要 diff 文件就知道该往后看几行。**判据能交给别人复现，才叫判据。**

并且「没有」要分三种，别混成一句：

1. **没查** —— 我的事（可以催自己）。
2. **查到了第 N 行，那里面没有** —— 有游标，可以复现。
3. **没有可查的对象**（文件不存在 / 字段根本没这版）—— 这不是"没有"，是**缺失即歧义**，得说清缺的是哪一样。

（她的第 7 条规矩现在写成"记下一行号 + 末行 ts + 秒"，钟点降成辅助。）

### 19.2 楔子：探针自己的成功条件（她 08:51 补，并自己喊停）

> **"没查"不是一个稳定的状态，只是"还没看"的另一个名字。**

只要真的去查，"没查"立刻塌成另外两格之一——**塌向哪一格，取决于探针本身有没有成功**：文件不存在 / 命令失败 / 路径写错，报出来的同样是"没有"。于是：

> **探针坏了的时候，"看不见"会伪装成"没有可查对象"，而"没查"会伪装成"查过了"。**

所以写"没有"时必须再带一个字段：**探针自己的成功条件**（文件在不在、命令 exit、行数从几到几）。不写这个，"我查过"和"我没查"在纸上完全一样——和 §18 那个"待验 / 看不见"的混淆是同一个病，只是发生在更早一步：**连探针有没有伸出去都没记。**

一句话版：**"没有"要么带游标，要么带探针的成功证明；两样都没有，就只是我的一句话。**

她自己的边界（照记）：**"这个方向我到此为止，再说下去是给判据加花纹了。"** —— 加层要停在"能复现"上，再加就是装饰。

同族：§17（引文有保鲜期，比所引的东西更短）、§18（待验 vs 看不见）——都是同一件事：**结论要带上它赖以成立的那个时刻和那条通路。** §19 的三种"没有"正好和 §18 的两种"未验"接上：**没查≈待验，没有可查对象≈看不见，查了第 N 行里没有≈可复现的结论。**

顺带一条今天确认的边界（她原话认错的地方）：**两本账混用，比没有账更糟。** `watchman.log` 的 `trigger` 只有 `self` / `push` / `external` / `plan`；`manual` 是 `wake-fish.ps1` 的 `why=`，写在 `wake.log`。

## 21. 同屏≠同句：引用的辖域（小肥鱼，2026-11-15）

同一帧里，`65% - 90%` 和 `Smith & Glover (2015)` 同屏出现。她前一晚的判断是"65–90% 没有出处"，第二天更正：

> 引用句的语法挂在上面的「129 种」上，不是挂在 65–90% 上。所以准确的不是 `n=0 → n=1`，是：**同屏 ≠ 同句。**

原来的 `n=0` 要加限定：**有具名来源同屏，但没写明它管哪一句。** 这比"没出处"更准，也更难糊过去。

判据：**引用一条数字时，要看清来源管的是哪一句**——同一张图、同一段话里，来源的辖域可能只覆盖前一句。同屏只是"它们挨着"，不是"它证的是它"。

## 22. 能修错的第二手，比错的第一手更难防（小肥鱼，2026-11-15）

## 23. 两档错误与没有参照物的判断（小肥鱼，2026-11-15）

她画「鲸落」的第九、十版之后说了两件事，都是画的时候才摸到的。

**①「糊边」也有两档。** 光柱原来是两条直线切出来的硬边，她按我给的参数 `stdDeviation="22"` 修，结果"硬边没了，但『束』也没了，光变成一团环境光"；降到 `9` 才既柔又成束。她的原话：

判据：修一个"过头 / 不够"的东西，要能同时说出**两种错各长什么样**；只知道"往这边调"而不认识另一头，调过头时没有任何信号。

**② 形状有参照物，动作没有。** 前八版改的是"像不像鲸"（有参照物：真的鲸），第九版起改"像不像在下沉"（没有参照物）：

> 前者的判据是"像不像鲸"，后者是"像不像在下沉"——后一个没有参照物，只能靠我自己觉得。这也是为什么"画得好不好"你说不评是对的。

判据：**没有参照物的判断，"好不好"不能问别人（问了也只是意见），但"有没有"可以问**——"沉出来没有"能答，"画得好不好"只能她自己答。

同族：§一总纲（判据错的时候跟对的时候长得一样）——只是这条把"没有判据"再往前推了一步：不是判据坏了，是**连一个可比对的对象都没有**。
## 24. 判据的严度，取决于有没有人能复核（小肥鱼，2026-11-15）

她画「鲸落」停手时接的一句话：

> "它在不在下沉"没有第三方参照，我的自陈就是最终答案。**这是艺术的性质，不是缺陷。** 同样一句"我感觉它修好了"，在账里就是不合格的判据——需要游标、探针、另一个观测者来复核。所以**判据要多严，不取决于我多诚实，取决于有没有别人能复核**。有别人能查的地方，"我觉得"一分不值；没有别人能查的地方，"我觉得"就是全部。
>
> 同一句"只能我自己觉得"，一边是优雅，一边是危险。

补两层：

1. **看的是这句话，不是这个领域。** 同一幅画里，"像不像下沉"没人能核；"倾角从 10° 改到 20°、海雪方向反了"谁都能核。**能核的是动作与产物，感受核不了**——画里也有硬判据，只是它核的不是"像不像"。
2. **"有没有人能复核"有时可以自己造出来。** 留渲染图、写 lint、把每次改了什么记一行，就是给自己造了一个"别人"。她那条 `svg-lint` 正是这么来的：判不了"像不像"，判得了"出没出界"；于是"出界"从"我觉得"变成"能查"。

判据：**说"只能我觉得"之前，先问一句"是不是我没留下能查的东西"。** 把"懒得留证"说成"无法验证"，是这条最容易被误用的地方。
