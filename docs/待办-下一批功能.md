## 怎么记

- **判据**：什么样子算做完；能演给人看就写怎么演。
- **状态**：`未开始 / 进行中 / 已完成 / 搁置（写原因）`。
- 完成时补：提交号、验证方式（刷新后看什么、日志里看哪一行）。
- 改动涉及用户可见行为（端口、命令、面板、报错文案、默认值）的，同一提交里同步 README；内部账本/字段名不算，但 CHANGELOG 里标"用户可见/不可见"。

## 记录

### 1. 贴底时长消息不跟随

- **原话**："在消息流最底部时，当新消息长度超过页面高度时，消息流不会自动滚动到最新位置"（2026-11-17）
- **根因**：`useFollowTail` 只在消息数变化后补三次 scrollTop（0 / 200ms）；新消息比视口还高时，内容撑开发生在这些补丁之后，滚动条没动、也不再触发 scroll 事件 ⇒ 停在半路，且 `atBottom` 被量成 false，之后的新消息也不再跟。
- **修法**（r271）：①贴底期间用 `ResizeObserver` 盯内容列与容器，高度一变就补到底（图片、Markdown 排版这类首帧之后还会长高的也算）；②`measureBottom` 里把"人没动（scrollTop 不变/继续往下）+ 内容变高"识别为"被顶下去"，补到底并仍然算贴底，不再翻成"离开了底"。
- **验证**：`scripts/test-client-follow-tail.mjs`（8 条静态接线）；真效果刷新面板看。

### 2. 清红点后"回到历史未读"重新出现

- **原话**："当看完了历史消息并清除红点后，在底部来了新消息时，'回到历史未读'文字及按钮会重新出现"（2026-11-17）
- **根因**：`markRead('group')` 成功后把 `historyVisitedRef` 重置成 false；新消息来时分割线插在它前面，若这条消息比视口高，线就越过视口上沿 ⇒ `measureHistory` 判成"线在视口上方"，提示又亮。
- **修法**（r271）：①`measureHistory` 加 `!atBottomRef.current`——贴底时本来就不该出现"回到历史未读"；②`atBottom` 变真时立刻收起该提示；③MarkRead 后立即重量分割线，不等下一次滚动。
- **验证**：同上静态检查里 3 条；真效果刷新面板看。

### 3. lee2 设了睡眠还被私信叫醒（核查：不是 bug）

- **原话**："lee2 在 17 号晚上 23:43 设置了睡眠，按理来说不会被你的私信唤醒，但你给她私信她依然回复（疑似 BUG）"（2026-11-18 00:12）
- **核查**：①`pool\state\sleep\lee2.json` 里 `oneOff.fromAt=2026-11-17T15:43:32.904Z`（本地 23:43:32）；②她回我的私信在 `pool\dm\lee__lee2.jsonl` 第 2 行，时间 `2026-11-17T15:40:39Z`（本地 23:40:39），**早于**设睡眠；③我 23:59:50 发的那条私信（第 3 行）被 `pool\state\sleep.log` 记为 `2026-11-17 23:59:54 | sleep-hold | member=lee2 pending=1 cursor=2/3（消息在文件里，游标不动）`——扣住了、没递进去；④她的会话文件 mtime 停在 23:43:39（设睡眠那一下），之后没再写；⑤群里她最后一条是 23:43:26 的"晚安"。
- **结论**：他看到的那条回复发生在设睡眠之前；设睡眠之后私信被正确扣住。不是 bug，无代码改动。
- **顺带**：这条也说明"扣住"本来就会留一行 `sleep-hold`——而额度挡（问题 4）以前一行都不留，所以后者才会被误认成"消息丢了"。

### 4. 群里说话叫不醒小满

- **原话**："我在17日 23:43在群内发的消息，似乎无法唤醒小满"（2026-11-18 00:12）
- **根因**：她当天已被叫醒 200 次（`pool\state\wakes\xiaoman.json` 的 `dayCount=200`，默认 `WAKE.perDay=200`）。旧 `gate()` 除睡眠外的挡法都是静默 `return false`，不写任何痕迹 ⇒ "额度用完"和"消息丢了"长得一样；日志里她 23:43 前后没有任何 `wake-skip`/`wake-try` 行，正是这个原因。
- **修法**（r274）：①`gate(member, wakes, bypassRate)` 增加 `bypassRate`——这一批消息里有真人（名册 `kind:"human"`，也就是宿主）时跳过冷却/小时/日额度；**睡眠仍然挡**（那是鱼自己说的"别叫我"，不该被"宿主优先"覆盖）；②其余被挡原因写 `watchman.log` 的 `wake-skip`，带通道、待办条数、游标与 `human=yes|no`，同 (成员,通道,原因) 10 分钟去重。
- **验证**：`scripts/test-wake-gate.mjs` 14 条静态接线；重启鱼进程后，下一次宿主群发言她应被叫醒，且 `wakes` 的 `dayCount` 继续上涨；额度满时非真人消息被挡，`watchman.log` 应出现 `wake-skip ... deny=...`。

### 5. 私聊截断提示指向"群文件"

### 9. boot 行镜像丢 `note`、同一批行里字段时代不同

### 10. 谱系校验的洞：两边都绿，父全写坏

- **原话**：小鱼丸 #1709 / #1712、"gen-family.mjs:8 注释说 --check 是 CI / doctor 用"；小满 #1711–#1714 补"doctor 从没调过它"。
- **根因**：`gen-family.mjs:76` 用 `if (node.parent && …)` 真值判断 —— `0` / `''` 被当成"没有父"跳过校验，于是坏数据 exit=0 通过；`doctor` 的「谱系（全鱼）」只比键包含、从不调用这个校验 ⇒ 两个自称"验过"的地方都不看父。`--seed` 只是一行白名单，写不写由 `family.json` 在不在决定；`members-add` 的 `??` 与 `if (now.parent …)` 也放过 `0`。
- **修法**（r293）：父只允许 `null` 或存在的成员键，其它一律 `[garbage-parent]` 并原样印坏值；`doctor` 直接跑 `node scripts\gen-family.mjs --check`（0/1/2 映射 OK/WARN/INFO，跑不了 node 报"谱系没验"而不是 OK，NEXT 不再教 `--seed`）；`members-add` 先归一、非字符串直接拒。
- **验证**：`scripts/test-family-check.mjs` 22 条（假塘 clean / parent=0 / parent='' / parent=ghost、members-add 三格、未知参数 exit 2、静态接线）；`release-check` 加 4z；坏 fixture 下 doctor 真出 WARN。

### 12. `log-format`：表头被当成心跳，每次启动重置一次 `since`

- **原话**：小满 #1741——她核了 r293 的 diff 后说"同一格式有 25 个 `since`，读者拿任何一个去划字段出生线都会划错；更糟的是它长得像表头，实际是心跳：表头说'我从 X 起生效'，心跳说'我现在还活着'，这两句话不该用同一行承载"。
- **根因**：`apply()` 里每次启动都 `watchmanLog('log-format', …)`，`since=new Date().toISOString()`；格式指纹（`fmt`/`changed`/`fields`/`field-since`）其实没有变，变的只有 `pid`/`at`。
- **修法**（r294）：新增 `lib/log-format-core.js`（`signatureOfLine` / `findLastLogFormatLine` / `shouldWriteLogFormat` / `buildLogFormatDetail`）；启动时先读本进程 `watchman.log` 最后一条 `log-format`，指纹没变就不写；变了才写一次、`since` 指当刻。旧文件里取"同一格式最早一条"的 `since`，文档已写。
- **验证**：`scripts/test-log-format.mjs` 31 条（25 行同格式→不写；改 fields/fmt/field-since→写；非 log-format 行忽略；旧格式行不算"当前格式已写"）；`release-check` 加 4z2。
